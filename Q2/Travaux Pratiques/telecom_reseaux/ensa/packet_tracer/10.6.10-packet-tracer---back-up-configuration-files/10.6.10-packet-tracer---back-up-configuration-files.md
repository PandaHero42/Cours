# Packet Tracer – Back Up Configuration Files

## Topologie

| Device      | Interface | Adresse IP  | Rôle |
|-------------|-----------|-------------|------|
| RTA         | G0/0      | (même sous-réseau que TFTP Server) | Routeur à restaurer |
| TFTP Server | NIC       | 172.16.1.2  | Serveur de sauvegarde |
| PCA         | NIC       | —           | PC de gestion (console) |

---

## Objectifs

- **Partie 1 :** Configurer la connectivité initiale vers le serveur TFTP
- **Partie 2 :** Restaurer la configuration depuis le serveur TFTP
- **Partie 3 :** Sauvegarder la configuration et l'IOS vers le serveur TFTP

---

## Contexte

**Scénario :** Un routeur a été remplacé suite à une panne matérielle. Sa configuration est sauvegardée sur un serveur TFTP. La procédure consiste à restaurer la configuration sur le nouveau routeur, puis à effectuer une nouvelle sauvegarde.

**TFTP (Trivial File Transfer Protocol)** : protocole de transfert de fichiers simplifié, opérant sur **UDP port 69**. Utilisé en environnement réseau pour les sauvegardes et restaurations de configurations et d'images IOS. Pas d'authentification, pas de chiffrement — à utiliser uniquement sur des réseaux de gestion sécurisés.

---

## Partie 1 : Établir la connectivité vers le serveur TFTP

### Configuration initiale via console

Accès console sur RTA via PCA : Desktop → Terminal.

Configurer G0/0 avec une IP dans le même réseau que le TFTP Server (`172.16.1.x`) :

```
Router(config)# interface GigabitEthernet0/0
Router(config-if)# ip address 172.16.1.1 255.255.255.0
Router(config-if)# no shutdown
```

> L'adresse IP de G0/0 doit être dans le **même sous-réseau** que le TFTP Server (`172.16.1.2`) pour que la communication soit directe, sans routage intermédiaire.

### Tester la connectivité

```
Router# ping 172.16.1.2
```

Le ping doit réussir avant de tenter tout transfert TFTP.

## Partie 2 : Restaurer la configuration depuis le serveur TFTP

### Copier la configuration TFTP → running-config

```
Router# copy tftp running-config
Address or name of remote host []? 172.16.1.2
Source filename []? RTA-confg
Destination filename [running-config]? <cr>
```

Résultat :
```
Accessing tftp://172.16.1.2/RTA-confg...
Loading RTA-confg from 172.16.1.2: !
[OK - 785 bytes]
785 bytes copied in 0.001 secs
RTA#
%SYS-5-CONFIG_I: Configured from console by console
```

> **`copy tftp running-config`** fusionne le fichier TFTP avec la running-config existante — il ne remplace pas, il **ajoute/écrase**. Le message `%SYS-5-CONFIG_I: Configured from console by console` est normal après chaque modification de configuration.
>
> **Changement de prompt** : le nom d'hôte passe de `Router` à `RTA` — preuve que le hostname contenu dans le fichier de configuration a été appliqué.

**Réponse — Quels changements ont été effectués ?**
→ Le fichier de configuration a appliqué : le **hostname** (`RTA`), les **adresses IP** des interfaces, les mots de passe, les routes, et toutes les autres commandes présentes dans le backup. La running-config du nouveau routeur reflète maintenant la configuration sauvegardée de l'ancien.

### Vérifier les interfaces

```
RTA# show ip interface brief
```

**Réponse — Toutes les interfaces sont-elles actives ?**
→ Pas nécessairement. Les interfaces configurées dans le fichier de backup peuvent être en état **administratively down** si elles n'ont pas de `no shutdown` dans le backup, ou si des interfaces configurées ne sont pas physiquement connectées. Corriger avec `no shutdown` sur les interfaces concernées.

### Corriger et tester

```
RTA(config)# interface <interface>
RTA(config-if)# no shutdown
```

```
PCA> ping 172.16.1.2
```

## Partie 3 : Sauvegarder la configuration et l'IOS vers le serveur TFTP

### a. Changer le hostname

```
RTA(config)# hostname RTA-1
```

### b. Sauvegarder en NVRAM

```
RTA-1# copy running-config startup-config
```

> **Étape obligatoire avant le backup TFTP** : la commande `copy running-config tftp:` envoie la **running-config** (en RAM). Si on veut sauvegarder la configuration persistante, il faut d'abord la sauvegarder en NVRAM, puis copier.

### c. Copier la configuration vers le serveur TFTP

```
RTA-1# copy running-config tftp:
Address or name of remote host []? 172.16.1.2
Destination filename [RTA-1-confg]? <cr>
```

> Le nom de fichier suggéré (`RTA-1-confg`) est automatiquement basé sur le hostname du routeur + `-confg`. On peut l'accepter avec `<cr>` ou spécifier un nom personnalisé.

### d. Afficher les fichiers en flash

```
RTA-1# show flash
```

Liste le contenu de la mémoire flash — en particulier le fichier IOS (ex. `c1900-universalk9-mz.SPA.151-4.M4.bin`).

### e. Sauvegarder l'IOS vers le serveur TFTP

```
RTA-1# copy flash tftp:
Source filename []? c1900-universalk9-mz.SPA.151-4.M4.bin
Address or name of remote host []? 172.16.1.2
Destination filename [c1900-universalk9-mz.SPA.151-4.M4.bin]? <cr>
```

**Réponse — Quel caractère indique le succès de la copie ?**
→ Le caractère `!` (point d'exclamation) s'affiche de façon répétée pendant le transfert. Chaque `!` représente un bloc de données transféré avec succès. Les points `.` indiquent des timeouts ou délais. Une longue série de `!!!!!!...` confirme un transfert en cours et réussi.

### f. Vérifier sur le serveur TFTP

TFTP Server → onglet Services → TFTP → scroll dans la liste des fichiers.

**Réponse :** Le fichier `c1900-universalk9-mz.SPA.151-4.M4.bin` est présent dans la liste — sauvegarde IOS réussie.

## Tableau récapitulatif des commandes clés

| Commande | Contexte | Description |
|----------|----------|-------------|
| `copy tftp running-config` | Privileged EXEC | Restaure une config depuis TFTP vers la running-config |
| `copy tftp startup-config` | Privileged EXEC | Restaure une config depuis TFTP vers la NVRAM |
| `copy running-config tftp:` | Privileged EXEC | Sauvegarde la running-config vers un serveur TFTP |
| `copy startup-config tftp:` | Privileged EXEC | Sauvegarde la startup-config vers un serveur TFTP |
| `copy flash tftp:` | Privileged EXEC | Sauvegarde l'image IOS depuis flash vers TFTP |
| `copy tftp flash:` | Privileged EXEC | Restaure une image IOS depuis TFTP vers flash |
| `show flash` | Privileged EXEC | Liste les fichiers en mémoire flash (images IOS) |
| `show ip interface brief` | Privileged EXEC | Vérifie l'état des interfaces après restauration |

## Mémo — Gestion des fichiers de configuration IOS

```
Emplacements de stockage :
  RAM           → running-config (volatile — perdue au reboot)
  NVRAM         → startup-config (persistante — chargée au boot)
  Flash         → image IOS + fichiers additionnels
  TFTP Server   → sauvegardes externes

Commandes copy essentielles :
  copy run start           ← sauvegarder en NVRAM (= wr)
  copy run tftp:           ← backup config vers serveur externe
  copy tftp run            ← restaurer config depuis TFTP (merge)
  copy tftp flash:         ← upgrade/restaurer IOS
  copy flash tftp:         ← sauvegarder IOS vers TFTP

Particularité de "copy tftp running-config" :
  → MERGE (fusion) avec la running-config existante
  → Pas de remplacement complet
  → Pour un remplacement complet : erase startup-config + reload
    puis charger la config depuis TFTP

Indicateurs de transfert :
  ! = bloc transféré avec succès
  . = timeout/délai
  E = erreur

TFTP vs SCP vs FTP :
  TFTP   : UDP 69, simple, pas d'auth, réseau géré local
  SCP    : SSH-based, chiffré, authentifié (préférable en production)
  FTP    : TCP 21, auth par login, non chiffré
```

## Script complet

```
! ============================================================
! PARTIE 1 - Connectivité initiale (console sur RTA)
! ============================================================

      interface GigabitEthernet0/0
        ip address 172.16.1.1 255.255.255.0
        no shutdown

  ping 172.16.1.2

! ============================================================
! PARTIE 2 - Restauration depuis TFTP
! ============================================================

  copy tftp running-config
! → host: 172.16.1.2
! → source: RTA-confg
! → destination: <cr>

  show running-config
  show ip interface brief

! Corriger les interfaces si nécessaire :
      interface <if>
        no shutdown

! ============================================================
! PARTIE 3 - Sauvegarde vers TFTP
! ============================================================

      hostname RTA-1

  copy running-config startup-config

  copy running-config tftp:
! → host: 172.16.1.2
! → destination: <cr> (RTA-1-confg)

  show flash

  copy flash tftp:
! → source: c1900-universalk9-mz.SPA.151-4.M4.bin
! → host: 172.16.1.2
! → destination: <cr>
```
