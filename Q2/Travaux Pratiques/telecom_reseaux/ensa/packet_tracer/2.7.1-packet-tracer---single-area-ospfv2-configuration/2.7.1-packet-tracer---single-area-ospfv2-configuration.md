## Objectifs

Configurer OSPFv2 single-area sur un réseau mixte combinant des liens **point-à-point** (réseau HQ : P2P-1/2/3) et un réseau **broadcast multi-accès** (réseau Data Service : BC-1/2/3), en appliquant un ensemble complet d'exigences de configuration.

---

## Contexte et analyse de la topologie

Le réseau est divisé en deux zones logiques, toutes deux dans l'**area 0** :

**Réseau HQ (Headquarters) — P2P-1, P2P-2, P2P-3**
- Liens série point-à-point entre routeurs → pas d'élection DR/BDR
- OSPF activé via **network statements** + masques inverses

**Réseau Data Service — BC-1, BC-2, BC-3**
- Segment Ethernet partagé (`10.0.1.0/29`) → réseau multi-accès broadcast → élection DR/BDR
- OSPF activé via **ip ospf area** directement sur les interfaces

**BC-1** est à la frontière des deux zones et joue le rôle d'**ASBR** (connexion ISP via S0/1/1).

---

## Analyse des exigences avant configuration

| Exigence | Détail technique |
|----------|-----------------|
| Process ID 10 sur tous les routeurs | `router ospf 10` |
| HQ → network statements | Wildcard masks sur P2P-1/2/3 |
| Data Service → activation par interface | `ip ospf 10 area 0` sur BC-1/2/3 |
| Router IDs BC | BC-1=6.6.6.6, BC-2=5.5.5.5, BC-3=4.4.4.4 |
| Pas de mises à jour vers les LANs | `passive-interface` sur les interfaces LAN |
| BC-1 toujours DR | `ip ospf priority 255` sur G0/0/0 de BC-1 |
| Route par défaut vers ISP | `ip route 0.0.0.0 0.0.0.0 S0/1/1` + `default-information originate` |
| Coût GE=10, FE=100 | `auto-cost reference-bandwidth 10000` (sur tous les routeurs) |
| Coût P2P-1 S0/1/1 = 50 | `ip ospf cost 50` sur cette interface |
| Timers P2P-1 ↔ BC-1 = 2× défaut | Hello=20s, Dead=80s sur S0/2/0 (P2P-1) et S0/1/0 (BC-1) |

## Calcul de la référence de bande passante

Par défaut, la référence OSPF est **100 Mbps** :
- GigabitEthernet (1000 Mbps) : coût = 100/1000 = **0.1 → arrondi à 1** (trop bas)
- FastEthernet (100 Mbps) : coût = 100/100 = **1** (identique à GE, non différencié)

Pour obtenir GE=10 et FE=100 :
```
Référence = coût souhaité × vitesse interface
GE : 10 × 1000 Mbps = 10 000 Mbps
FE : 100 × 100 Mbps = 10 000 Mbps  ✓ (cohérent)
```

→ `auto-cost reference-bandwidth 10000` sur **tous** les routeurs.

> ⚠️ Cette commande doit être appliquée de façon **identique sur tous les routeurs OSPF** du domaine, sinon les calculs de coût seront incohérents et les meilleurs chemins mal déterminés.

## Configuration complète par routeur

### P2P-1

```
P2P-1(config)# router ospf 10
P2P-1(config-router)# auto-cost reference-bandwidth 10000
P2P-1(config-router)# network 10.0.0.0 0.0.0.3 area 0
P2P-1(config-router)# network 10.0.0.8 0.0.0.3 area 0
P2P-1(config-router)# network 10.0.0.12 0.0.0.3 area 0

! Coût spécifique sur S0/1/1
P2P-1(config)# interface s0/1/1
P2P-1(config-if)# ip ospf cost 50

! Timers 2× défaut sur le lien vers BC-1 (S0/2/0 ↔ BC-1 S0/1/0)
! Défaut série : Hello=10s, Dead=40s → 2× : Hello=20s, Dead=80s
P2P-1(config)# interface s0/2/0
P2P-1(config-if)# ip ospf hello-interval 20
P2P-1(config-if)# ip ospf dead-interval 80
```

> **Pourquoi `network 10.0.0.0 0.0.0.3` ?** Le masque inverse `/30` est `0.0.0.3`. Cette instruction inclut toute interface dont l'adresse tombe dans `10.0.0.0–10.0.0.3`, c'est-à-dire uniquement S0/1/0 (`10.0.0.1`).

### P2P-2

```
P2P-2(config)# router ospf 10
P2P-2(config-router)# auto-cost reference-bandwidth 10000
P2P-2(config-router)# network 10.0.0.0 0.0.0.3 area 0
P2P-2(config-router)# network 10.0.0.4 0.0.0.3 area 0
P2P-2(config-router)# network 192.168.1.0 0.0.0.255 area 0
P2P-2(config-router)# network 192.168.2.0 0.0.0.255 area 0
P2P-2(config-router)# passive-interface g0/0/0
P2P-2(config-router)# passive-interface g0/0/1
```

> **Passive-interface sur G0/0/0 et G0/0/1** : ces interfaces LAN n'ont aucun routeur OSPF voisin. Envoyer des Hellos vers les PCs est inutile et révèle des informations sur la topologie OSPF. `passive-interface` annonce quand même le réseau dans les LSA mais supprime l'envoi de Hellos.

### P2P-3

```
P2P-3(config)# router ospf 10
P2P-3(config-router)# auto-cost reference-bandwidth 10000
P2P-3(config-router)# network 10.0.0.4 0.0.0.3 area 0
P2P-3(config-router)# network 10.0.0.8 0.0.0.3 area 0
P2P-3(config-router)# network 192.168.3.0 0.0.0.15 area 0
P2P-3(config-router)# passive-interface g0/0/0
```

> **Masque inverse `/28` :** `255.255.255.240` → inverse = `0.0.0.15`. P2P-3 G0/0/0 est en `192.168.3.1/28` donc le réseau est `192.168.3.0` avec wildcard `0.0.0.15`.

### BC-1 (ASBR + DR du segment multi-accès)

```
BC-1(config)# router ospf 10
BC-1(config-router)# router-id 6.6.6.6
BC-1(config-router)# auto-cost reference-bandwidth 10000
BC-1(config-router)# default-information originate

! Activation OSPF par interface (méthode Data Service)
BC-1(config)# interface s0/1/0
BC-1(config-if)# ip ospf 10 area 0
! Timers 2× défaut sur le lien vers P2P-1
BC-1(config-if)# ip ospf hello-interval 20
BC-1(config-if)# ip ospf dead-interval 80

BC-1(config)# interface g0/0/0
BC-1(config-if)# ip ospf 10 area 0
! BC-1 doit toujours être DR → priorité maximale
BC-1(config-if)# ip ospf priority 255

! S0/1/1 = lien ISP → PAS dans OSPF, sert uniquement à la route par défaut
! Route par défaut statique vers ISP via interface de sortie
BC-1(config)# ip route 0.0.0.0 0.0.0.0 s0/1/1
```

> **Pourquoi S0/1/1 n'est pas inclus dans OSPF ?** C'est le lien vers l'ISP — un réseau externe au domaine OSPF. L'inclure dans OSPF redistribuerait des informations de topologie interne vers l'ISP. On utilise à la place une route statique par défaut que `default-information originate` propage aux autres routeurs.

> **Priorité 255 sur G0/0/0 :** La valeur maximale garantit que BC-1 sera toujours élu DR sur le segment multi-accès `10.0.1.0/29`, peu importe les Router IDs des autres. BC-2 et BC-3 garderont leur priorité par défaut (1) et seront DROTHERs ou BDR.

### BC-2

```
BC-2(config)# router ospf 10
BC-2(config-router)# router-id 5.5.5.5
BC-2(config-router)# auto-cost reference-bandwidth 10000

BC-2(config)# interface g0/0/1
BC-2(config-if)# ip ospf 10 area 0

BC-2(config)# interface g0/0/0
BC-2(config-if)# ip ospf 10 area 0
BC-2(config-if)# ip ospf passive
```

> **`ip ospf passive` sur interface :** méthode alternative à `passive-interface` dans le processus OSPF — applicable uniquement quand OSPF est activé par interface (`ip ospf area`). Même effet : annonce le réseau mais supprime les Hellos.

### BC-3

```
BC-3(config)# router ospf 10
BC-3(config-router)# router-id 4.4.4.4
BC-3(config-router)# auto-cost reference-bandwidth 10000

BC-3(config)# interface g0/0/1
BC-3(config-if)# ip ospf 10 area 0

BC-3(config)# interface g0/0/0
BC-3(config-if)# ip ospf 10 area 0
BC-3(config-if)# ip ospf passive
```

## Tableau récapitulatif des commandes clés

| Commande | Contexte | Description |
|----------|----------|-------------|
| `router ospf <id>` | Global config | Active le processus OSPF avec l'ID spécifié |
| `router-id <a.b.c.d>` | Router OSPF | Fixe manuellement le Router ID |
| `network <ip> <wildcard> area <n>` | Router OSPF | Inclut les interfaces correspondantes dans OSPF |
| `ip ospf <id> area <n>` | Interface config | Active OSPF directement sur l'interface |
| `ip ospf passive` | Interface config | Supprime les Hellos sur l'interface (méthode interface) |
| `passive-interface <if>` | Router OSPF | Supprime les Hellos sur l'interface (méthode processus) |
| `auto-cost reference-bandwidth <Mbps>` | Router OSPF | Ajuste la référence de calcul du coût OSPF |
| `ip ospf cost <valeur>` | Interface config | Fixe manuellement le coût OSPF de l'interface |
| `ip ospf priority <0-255>` | Interface config | Définit la priorité pour l'élection DR/BDR |
| `ip ospf hello-interval <s>` | Interface config | Intervalle Hello OSPF |
| `ip ospf dead-interval <s>` | Interface config | Dead timer OSPF |
| `default-information originate` | Router OSPF | Propage la route par défaut dans OSPF |
| `ip route 0.0.0.0 0.0.0.0 <if/next-hop>` | Global config | Route statique par défaut |

## Mémo — Deux méthodes d'activation OSPF

```
Méthode 1 : network statements (réseau HQ)
  router ospf 10
    network <réseau> <wildcard> area 0
  └─ Active OSPF sur toutes les interfaces dont l'IP matche
  └─ Passive-interface configurée dans le processus OSPF

Méthode 2 : activation par interface (réseau Data Service)
  interface <if>
    ip ospf 10 area 0
  └─ Active OSPF uniquement sur cette interface
  └─ Passive configurable avec "ip ospf passive" sur l'interface

Les deux méthodes sont équivalentes — peuvent coexister dans un même réseau.
```
