## Objectifs

- **Partie 1 :** Explorer les réseaux (Data Center, ISP, Coffee Shop, Home)
- **Partie 2 :** Implémenter des mesures de sécurité (IoT, VPN, WLANs sécurisés)

> ℹ️ Ce lab n'est **pas noté**. Les configurations se font principalement via des interfaces graphiques (GUI) dans Packet Tracer Physical Mode.

---

## Contexte

Ce lab illustre plusieurs approches de sécurité réseau dans des environnements réels distincts :

| Environnement | Menace | Solution appliquée |
|---------------|--------|--------------------|
| Data Center | Accès physique non autorisé, trafic non filtré | ACL sur routeur edge, IoT (porte+sirène+thermostat), détecteur de fumée |
| Coffee Shop | Wi-Fi ouvert → trafic interceptable | VPN IPsec chiffrant le tunnel vers le Data Center |
| Home | Accès WLAN non contrôlé | WPA2-AES, SSID caché, réseau guest séparé, filtrage MAC |

### Étape 3 : Data Center POP

**Réponses :**
- **Câble DC_Edge-Rtr1 → ISP :** Câble fibre optique (Serial/WAN).
- **Équipement faisant la NAT :** **DC_Edge-Rtr1** — il traduit les adresses privées du Data Center en adresses publiques pour communiquer avec l'ISP.

#### ACL sur DC_Edge-Rtr1

```
DC_Edge-Rtr1# show access-list
```

L'ACL autorise uniquement : **HTTP (80), HTTPS (443), IPsec (500/4500), FTP (21)**. Tout autre trafic est bloqué implicitement (deny any).

**Réponse — interface et direction :** L'ACL est appliquée sur l'interface **WAN (côté ISP)** en direction **inbound** — elle filtre le trafic entrant depuis Internet vers le Data Center.

> **Pourquoi inbound sur l'interface WAN ?** Bloquer le trafic indésirable dès son arrivée, avant qu'il ne traverse le routeur et atteigne le réseau interne — c'est la pratique standard pour les ACLs de sécurité périmétrique.

### Étape 4 : IoT Server — accès via Web Browser

Sur **DC_Laptop** → Desktop → Web Browser → `172.31.0.2` (admin / ciscorocks).

**Réponses :**

- **Niveau d'humidité actuel :** Visible dans l'interface IoT — valeur affichée par le capteur (typiquement ~30-60%).

### Étape 5 : Porte et sirène (démonstration IoT)

Séquence d'observation :
1. Door fermée → indicateur **rouge** (= porte fermée, pas d'alarme)
2. Déverrouiller via l'IoT Server → ALT+clic sur la porte → porte ouvre
3. Sirène → indicateur **vert** (= sirène active)
4. Refermer la porte → sirène s'arrête
5. Verrouiller via l'IoT Server → la porte ne peut plus être ouverte

> **Principe IoT de sécurité :** Le serveur IoT centralise le contrôle des capteurs/actionneurs. Un événement physique (ouverture de porte) déclenche automatiquement une action (sirène) — sans intervention humaine. C'est un exemple basique d'automatisation de sécurité physique.

### Étape 2 : Configurer un VPN au Coffee Shop

#### Contexte — pourquoi le VPN ?

Un Wi-Fi public ouvert n'offre **aucun chiffrement** entre le client et l'AP. N'importe qui sur le même réseau peut capturer le trafic avec Wireshark. Le VPN crée un **tunnel chiffré (IPsec)** entre le laptop et le Data Center, rendant le trafic illisible même s'il est intercepté.

#### a–c. Vérification de connectivité initiale

Sur **VPN Laptop** → Desktop → Command Prompt :

```
ipconfig
```

**Réponse — IP du VPN Laptop :** Adresse DHCP du réseau Coffee Shop (ex. `192.168.x.x`).

```
ping 10.0.0.2
```

Ping vers le serveur VPN (DC_Edge-Rtr1) — doit réussir avant de configurer le VPN.

#### d–e. Configuration du client VPN

Desktop → **VPN** :

| Paramètre | Valeur |
|-----------|--------|
| Group Name | `REMOTE` |
| Group Key | `CISCO` |
| Host IP (Server IP) | `10.0.0.2` |
| Username | `VPN` |
| Password | `ciscorocks` |

Cliquer **Connect** → message "VPN is connected" → OK.

**Réponse — Client IP :** Une adresse du pool VPN est assignée au laptop (ex. `172.31.x.x` — adresse interne Data Center). Le laptop est maintenant virtuellement **à l'intérieur** du réseau Data Center.

#### f–g. Vérification côté Data Center (DC_Edge-Rtr1)

```
DC_Edge-Rtr1# show crypto isakmp sa
```

**Réponses :**
- **Statut :** `QM_IDLE` — la SA (Security Association) IPsec est établie et active (Fase 1 ISAKMP complète).
- **IP destination :** L'adresse publique du VPN Laptop (IP Coffee Shop côté WAN) — c'est l'autre extrémité du tunnel IPsec.

#### h–m. Test FTP via VPN

```
ftp 172.19.0.3
```
```
Username: remote
Password: ciscorocks
```
```
ftp> dir
ftp> get <filename>
ftp> quit
```

Ouvrir **Text Editor** → File → Open → fichier téléchargé.

**Réponse — premier mot du fichier :** Visible dans le fichier (ex. "Congratulations" ou similaire).

#### n. Test depuis l'autre laptop (sans VPN)

```
ping 172.19.0.3
```

**Réponse — succès ?** **Non.** L'autre laptop n'a pas de VPN actif. L'ACL sur DC_Edge-Rtr1 bloque tout trafic non-autorisé depuis Internet. Seul le tunnel IPsec du VPN Laptop lui permet d'accéder aux ressources internes (`172.19.x.x`) du Data Center.

#### o. Exemples de services VPN réels

NordVPN, ExpressVPN, ProtonVPN (3 exemples parmi les plus répandus pour laptops, tablettes et smartphones).

### Étape 3 : Configurer les WLANs sécurisés à la maison

#### d. Configuration réseau du Home Router (GUI)

Home → **Home Router** → onglet **GUI** :

| Paramètre | Valeur |
|-----------|--------|
| IP Address | `192.168.0.254` |
| Subnet Mask | `255.255.255.0` |
| DHCP | Activé |
| Start IP Address | `192.168.0.10` |
| Maximum Users | `25` |
| Static DNS 1 | `10.2.0.125` |

→ **Save Settings**

#### f–g. WLAN principal (HomeNet)

Wireless → **Basic Wireless Settings** :

| Paramètre | Valeur |
|-----------|--------|
| SSID (2.4G + 5G) | `HomeNet` |
| SSID Broadcast | **Désactivé** (caché) |

→ **Save Settings**

> **Pourquoi cacher le SSID ?** Un SSID non-diffusé n'apparaît pas dans les scans Wi-Fi des appareils environnants. Ce n'est pas une sécurité absolue (un attaquant peut quand même le détecter avec des outils passifs) mais ça réduit la visibilité du réseau pour les utilisateurs non-initiés.

#### h–i. Sécurité WPA2 (HomeNet)

Wireless → **Wireless Security** (pour les 3 WLANs) :

| Paramètre | Valeur |
|-----------|--------|
| Security Mode | `WPA2 Personal` |
| Encryption | `AES` |
| Passphrase | `ciscorocks` |

→ **Save Settings**

> **WPA2-AES** est le standard actuel pour la sécurité Wi-Fi domestique. AES (Advanced Encryption Standard) est un chiffrement symétrique robuste. WPA2 remplace le WEP (facilement crackable) et le WPA (TKIP — vulnérabilités connues).

#### j–k. Réseau invité (GuestNet)

Wireless → **Guest Network** (pour les 3 WLANs) :

| Paramètre | Valeur |
|-----------|--------|
| Enable Guest Profile | ✓ |
| SSID | `GuestNet` |
| Enable Broadcast SSID | ✓ (visible — les invités doivent pouvoir le trouver) |
| Security Mode | `WPA2 Personal` |
| Encryption | `AES` |
| Passphrase | `guestpass` |

→ **Save Settings**

> **Séparation guest/home :** Le réseau guest est isolé du réseau principal — les invités accèdent à Internet mais ne peuvent pas communiquer avec les équipements du réseau familial (PCs, imprimantes, NAS). C'est une pratique de sécurité essentielle.

#### l–m. Filtrage MAC (HomeNet)

Wireless → **Wireless MAC Filter** :

- Activer le filtrage → mode **Permit** (liste blanche)
- Ajouter l'adresse MAC du Office Laptop : `00:01:42:2B:9E:9D`
- Répéter pour les 3 ports (2.4G, 5G(1), 5G(2)) via le menu déroulant

→ **Save Settings**

> **Filtrage MAC :** Seuls les appareils dont l'adresse MAC est dans la liste peuvent se connecter au HomeNet. Le Guest Laptop n'est **pas** dans cette liste → il ne peut accéder qu'au GuestNet.

#### n–o. Connexion Office Laptop au HomeNet

Config → Wireless0 → SSID : `HomeNet`, Auth : WPA2-PSK, passphrase : `ciscorocks`.

Desktop → Web Browser → `www.ptsecurity.com` → doit s'afficher.

#### p. Connexion Guest Laptop au GuestNet

Config → Wireless0 → SSID : `GuestNet`, Auth : WPA2-PSK, passphrase : `guestpass`.

**Réponse — Le laptop a-t-il reçu une IP DHCP ?** **Non** initialement — le Guest Network est activé mais le DHCP pour le réseau guest n'a peut-être pas été correctement activé.

#### q. Correction

Retourner dans le Home Router GUI → Guest Network → vérifier que **DHCP est activé pour le réseau guest** → Save Settings. Revenir sur le Guest Laptop et basculer DHCP/Static pour forcer un renouvellement.

#### s–t. Tests de connectivité Guest Laptop

```
ping 10.2.0.125
```
**Réussi** — accès Internet (DNS ISP) fonctionnel depuis le réseau guest.

```
ping 192.168.0.x  (autres appareils Home)
```
**Réponse — ces pings réussissent-ils ?** **Non.** Le réseau guest est **isolé** du réseau principal — c'est le comportement attendu et souhaité. Les invités ne doivent pas pouvoir accéder aux équipements privés du foyer.

## Synthèse — Approches de sécurité utilisées

**Réponse à la question de réflexion :**

| Approche | Où | Détail |
|----------|----|--------|
| ACL périmétrique | Data Center Edge | Filtre le trafic entrant — autorise uniquement HTTP/HTTPS/IPsec/FTP |
| Sécurité physique IoT | Data Center | Porte verrouillée + sirène + thermostat + détecteur de fumée connectés au IoT Server |
| VPN IPsec | Coffee Shop | Tunnel chiffré laptop → Data Center sur Wi-Fi public ouvert |
| WPA2-AES | Home (HomeNet + GuestNet) | Chiffrement fort des communications Wi-Fi |
| SSID caché | Home (HomeNet) | Réseau familial non visible dans les scans Wi-Fi |
| Réseau guest isolé | Home (GuestNet) | Séparation invités / réseau familial |
| Filtrage MAC | Home (HomeNet) | Liste blanche — seuls les appareils autorisés peuvent se connecter |
| Authentification IoT Server | Data Center | Accès à l'interface de gestion IoT par username/password |

**Suggestions supplémentaires pour un environnement réel :**
- Désactiver le management à distance du routeur home
- Mettre à jour le firmware de tous les équipements
- Utiliser des mots de passe forts et uniques (pas `ciscorocks` en prod)
- Activer IDS/IPS sur le routeur Data Center
- Chiffrer les disques des serveurs
- Authentification 802.1X (RADIUS) plutôt que PSK pour les environnements d'entreprise
- Segmentation VLAN dans le Data Center
