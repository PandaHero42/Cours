## Objectifs

- **Partie 1 :** Vérifier la connectivité locale et tester l'impact de l'ACL

---

## Contexte

Ce lab est un **lab d'observation** : une ACL est déjà configurée sur R1. L'objectif est de comprendre comment une ACL standard bloque du trafic, comment l'identifier avec les commandes `show`, et comment la supprimer proprement (deux étapes : retrait de l'interface, puis suppression de l'ACL elle-même).

---

## Rappel — Fonctionnement des ACLs standard IPv4

Une ACL standard filtre le trafic **uniquement sur l'adresse IP source**. Elle est constituée d'une liste ordonnée d'ACEs (Access Control Entries) évaluées séquentiellement :

```
Paquet reçu → ACE 1 → match ? → action (permit/deny)
              ↓ non
              ACE 2 → match ? → action
              ↓ non
              ...
              deny any implicite (toujours présent en fin de liste)
```

> ⚠️ **Deny implicite :** Toute ACL se termine par un `deny any` implicite invisible. Si aucune ACE ne matche le paquet, il est **droppé** silencieusement.

**Règle de placement :** Une ACL standard doit être placée **le plus proche possible de la destination** (car elle ne peut filtrer que sur la source — la placer trop tôt bloquerait aussi le trafic légitime vers d'autres destinations).

## Partie 1 : Vérifier la connectivité locale et tester l'ACL

### Étape 1 : Pings sur le réseau local

```
PC1> ping 192.168.10.11   (PC2 — même réseau /24)
PC1> ping 192.168.11.10   (PC3 — réseau G0/1 de R1)
```

**Réponse — pourquoi les pings réussissent-ils ?**

PC1 → PC2 : même réseau (`192.168.10.0/24`), trafic local, **ne traverse pas R1** → l'ACL sur S0/0/0 n'est jamais atteinte.

PC1 → PC3 : le paquet sort par G0/0 de R1 et arrive sur G0/1. L'ACL est appliquée sur **S0/0/0 outbound** — ce trafic ne passe pas par S0/0/0 → l'ACL n'est pas évaluée → ping réussi.

### Étape 2 : Pings vers les réseaux distants (derrière R2/R3)

```
PC1> ping 192.168.30.12   (PC4)
PC1> ping 192.168.31.12   (DNS Server)
```

**Réponse — pourquoi les pings échouent-ils ?**

Les paquets de PC1 (`192.168.10.x`) traversent R1 **via S0/0/0 en direction de R2/R3**. L'ACL 11 est appliquée sur **S0/0/0 outbound** : elle bloque tout paquet dont l'adresse source appartient à `192.168.10.0/24`. Les pings de PC1 vers PC4 et le DNS Server sont donc **droppés par R1 à la sortie de S0/0/0**.

## Partie 2 : Supprimer l'ACL et retester

### Étape 1 : Investiguer l'ACL avec les commandes show

#### Voir le contenu de l'ACL

```
R1# show access-lists
```
```
Standard IP access list 11
    10 deny   192.168.10.0 0.0.0.255
    20 permit any
```

**Lecture de l'ACL 11 :**

| Séquence | Action | Source | Effet |
|----------|--------|--------|-------|
| 10 | `deny` | `192.168.10.0/24` | Bloque tout paquet provenant du réseau de PC1/PC2 |
| 20 | `permit any` | Toutes sources | Autorise tout le reste |

> **Pourquoi le `permit any` en ligne 20 ?** Sans lui, le `deny any` implicite final bloquerait **tout** le trafic (y compris PC3 vers les réseaux distants). La ligne 20 préserve la connectivité pour les autres sources.

#### Trouver l'interface d'application — commande filtrée

```
R1# show run | include interface|access
```
```
interface GigabitEthernet0/0
interface GigabitEthernet0/1
interface Serial0/0/0
 ip access-group 11 out
interface Serial0/0/1
interface Vlan1
access-list 11 deny 192.168.10.0 0.0.0.255
access-list 11 permit any
```

> **`| include interface|access`** : le pipe `|` filtre la sortie de `show run`. Le symbole `|` dans la chaîne de recherche crée une condition **OR** : affiche les lignes contenant "interface" OU "access". Pas d'espaces dans la condition — cela permet de voir rapidement sur quelle interface chaque ACL est appliquée sans lire toute la configuration.

**Réponse — interface et direction :** ACL 11 appliquée sur **Serial0/0/0**, direction **outbound** (`out`). Tout paquet quittant R1 via S0/0/0 est évalué contre cette ACL.

### Étape 2 : Supprimer l'ACL

La suppression d'une ACL se fait en **deux étapes obligatoires** :

#### 1. Retirer l'ACL de l'interface

```
R1(config)# interface s0/0/0
R1(config-if)# no ip access-group 11 out
```

> Si on oublie cette étape et qu'on supprime directement l'ACL, IOS peut laisser une référence orpheline sur l'interface (comportement variable selon les versions).

#### 2. Supprimer l'ACL de la configuration globale

```
R1(config)# no access-list 11
```

> `no access-list 11` supprime **uniquement** l'ACL numéro 11. `no access-list` sans argument supprimerait **toutes** les ACLs du routeur — à utiliser avec précaution.

#### 3. Vérifier

```
R1# show access-lists
```
Aucune sortie → ACL supprimée.

```
PC1> ping 192.168.30.12
PC1> ping 192.168.31.12
```
Les deux pings **réussissent** maintenant.

## Tableau récapitulatif des commandes clés

| Commande | Contexte | Description |
|----------|----------|-------------|
| `show access-lists` | Privileged EXEC | Affiche toutes les ACLs et leurs compteurs de hits |
| `show access-lists <num>` | Privileged EXEC | Affiche une ACL spécifique |
| `show run \| include interface\|access` | Privileged EXEC | Filtre la running-config pour voir ACLs + interfaces d'un coup |
| `show ip interface <if>` | Privileged EXEC | Affiche quelle ACL est appliquée sur une interface (in/out) |
| `ip access-group <num> <in\|out>` | Interface config | Applique une ACL sur une interface |
| `no ip access-group <num> <in\|out>` | Interface config | Retire l'ACL d'une interface |
| `no access-list <num>` | Global config | Supprime l'ACL de la configuration |

---

## Mémo — ACLs standard IPv4

```
ACL standard :
  └─ Filtre sur adresse IP SOURCE uniquement
  └─ Numéros : 1–99 et 1300–1999
  └─ Placement recommandé : le plus proche de la DESTINATION

Syntaxe :
  access-list <num> {deny|permit} <source> <wildcard>
  access-list <num> {deny|permit} any            ← any = 0.0.0.0 255.255.255.255
  access-list <num> {deny|permit} host <ip>      ← host = wildcard 0.0.0.0

Application sur interface :
  ip access-group <num> {in|out}

  in  → filtre les paquets ENTRANT dans l'interface (depuis le réseau vers le routeur)
  out → filtre les paquets SORTANT de l'interface (depuis le routeur vers le réseau)

Suppression (ordre obligatoire) :
  1. no ip access-group <num> {in|out}   ← retirer de l'interface
  2. no access-list <num>                ← supprimer l'ACL

Implicite en fin d'ACL :
  deny any  → tout paquet non matché est bloqué silencieusement
```
