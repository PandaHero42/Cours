## Objectifs

Configurer 4 ACLs de types différents sur HQ et Branch pour répondre à des exigences de sécurité précises.

**Contraintes imposées :**
- Pas de `deny any` explicite en fin d'ACL
- Utiliser `host` et `any` dès que possible
- Respecter l'ordre des ACEs tel que spécifié
- Placer les ACLs à l'endroit le plus efficace

## Configuration des 4 ACLs

### ACL 101 — Filtrage trafic Internet entrant (HQ S0/1/0 in)

**Exigences :**
1. Bloquer FTP depuis Internet vers Enterprise Web Server (`192.168.1.70`)
2. Bloquer tout ICMP depuis Internet vers HQ LAN 1 (`192.168.1.0/26`)
3. Autoriser tout le reste

**Placement :** HQ S0/1/0 inbound — tout trafic venant d'Internet entre par cette interface.

```
HQ(config)# access-list 101 deny tcp any host 192.168.1.70 eq 21
HQ(config)# access-list 101 deny icmp any 192.168.1.0 0.0.0.63
HQ(config)# access-list 101 permit ip any any
```

```
HQ(config)# interface s0/1/0
HQ(config-if)# ip access-group 101 in
```

> **ACE 1** : `any` = toute source Internet, `host 192.168.1.70` = Enterprise Web Server uniquement, `eq 21` = FTP.
>
> **ACE 2** : Bloque les pings entrants vers HQ LAN 1 — protection contre le scanning réseau depuis Internet. L'Enterprise Web Server (`192.168.1.64/29`) n'est **pas** dans HQ LAN 1 (`192.168.1.0/26`) → son ICMP n'est pas bloqué par cette ACE.

---

### ACL 111 — Bloquer HQ LAN 1 → Branch Server (HQ G0/0/0 in)

**Exigences :**
1. Bloquer tout trafic de HQ LAN 1 (`192.168.1.0/26`) vers Branch Server (`192.168.2.45`)
2. Autoriser tout le reste

**Placement :** HQ G0/0/0 inbound — trafic de HQ LAN 1 entre dans HQ par cette interface. Placement proche de la source (ACL étendue).

```
HQ(config)# access-list 111 deny ip 192.168.1.0 0.0.0.63 host 192.168.2.45
HQ(config)# access-list 111 permit ip any any
```

```
HQ(config)# interface g0/0/0
HQ(config-if)# ip access-group 111 in
```

> **`deny ip`** au lieu de `deny tcp` ou `deny icmp` — `ip` bloque **tous** les protocoles (TCP, UDP, ICMP, etc.) entre ces deux endpoints. Plus efficace qu'une liste de deny par protocole.

---

### ACL vty_block — Sécuriser les lignes VTY de HQ (standard nommée)

**Exigences :**
- Seule la plage d'adresses HQ LAN 2 (`192.168.1.64/29`) peut accéder aux VTY du routeur HQ

**Placement :** Sur les lignes VTY de HQ avec `access-class` (pas sur une interface — spécifique aux VTY).

```
HQ(config)# ip access-list standard vty_block
HQ(config-std-nacl)# permit 192.168.1.64 0.0.0.7
```

```
HQ(config)# line vty 0 4
HQ(config-line)# access-class vty_block in
```

> **`access-class` vs `ip access-group` :** `ip access-group` s'applique sur une interface réseau. `access-class` s'applique sur les **lignes VTY** (sessions Telnet/SSH). La direction `in` signifie que l'ACL filtre les tentatives de connexion entrantes vers les VTY.
>
> **ACL standard suffisante ici** : on filtre uniquement sur l'adresse source (qui essaie de se connecter en VTY). L'ACL standard est donc appropriée — pas besoin d'une ACL étendue.
>
> Le `deny any` implicite bloque toute autre source automatiquement — seul Admin (`192.168.1.67`) et Enterprise Web Server (`192.168.1.70`) peuvent donc accéder aux VTY de HQ.

---

### ACL branch_to_hq — Bloquer Branch LANs → HQ LAN 1 (Branch S0/1/1 out)

**Exigences :**
1. Bloquer Branch LAN 1 (`192.168.2.0/27`) → HQ LAN 1 (`192.168.1.0/26`)
2. Bloquer Branch LAN 2 (`192.168.2.32/28`) → HQ LAN 1 (`192.168.1.0/26`)
3. Autoriser tout le reste

**Placement :** Branch S0/1/1 outbound — tout trafic des deux Branch LANs vers HQ passe par cette interface. Une seule ACL couvre les deux LANs sources. Outbound car on filtre à la sortie vers HQ.

```
Branch(config)# ip access-list extended branch_to_hq
Branch(config-ext-nacl)# deny ip 192.168.2.0 0.0.0.31 192.168.1.0 0.0.0.63
Branch(config-ext-nacl)# deny ip 192.168.2.32 0.0.0.15 192.168.1.0 0.0.0.63
Branch(config-ext-nacl)# permit ip any any
```

```
Branch(config)# interface s0/1/1
Branch(config-if)# ip access-group branch_to_hq out
```

> **Pourquoi outbound sur S0/1/1 de Branch plutôt qu'inbound sur G0/0/0 et G0/0/1 ?** En outbound sur S0/1/1, une seule application d'ACL suffit pour couvrir les deux LANs sources → plus efficace. En inbound sur les deux interfaces LAN, il faudrait deux applications distinctes de l'ACL.

## Vérification — Tests de connectivité

### a. Tests entre équipements internes

**Branch PC → Enterprise Web Server**

**Réponse :** ✅ **Succès.** Branch PC est dans Branch LAN 1 (`192.168.2.0/27`). `branch_to_hq` bloque l'accès vers HQ LAN 1 (`192.168.1.0/26`). L'Enterprise Web Server est dans **HQ LAN 2** (`192.168.1.64/29`) — pas dans HQ LAN 1. Le trafic matche la ligne `permit ip any any` de `branch_to_hq`.

**ACE matchée :** `branch_to_hq` sur Branch S0/1/1 out — ligne `permit ip any any`.

---

**PC-1 → Branch Server**

**Réponse :** ❌ **Échec.** PC-1 (`192.168.1.10`) est dans HQ LAN 1. Branch Server est `192.168.2.45`. ACL 111 bloque tout trafic de `192.168.1.0/26` vers `host 192.168.2.45`.

**ACE matchée :** ACL 111 sur HQ G0/0/0 in — `deny ip 192.168.1.0 0.0.0.63 host 192.168.2.45`.

---

**External Web Server → Enterprise Web Server (HTTP)**

**Réponse :** ✅ **Succès.** Le trafic HTTP (port 80) entrant depuis Internet via HQ S0/1/0 est évalué par ACL 101. ACL 101 bloque uniquement FTP (port 21) vers l'Enterprise Web Server et ICMP vers HQ LAN 1. HTTP (port 80) n'est pas bloqué → `permit ip any any`.

**ACE matchée :** ACL 101 sur HQ S0/1/0 in — `permit ip any any`.

---

### b. Tests depuis Internet

**Internet User → Branch Server (FTP)**

**Réponse :** ✅ **Succès (indésirable).** ACL 101 bloque FTP uniquement vers `host 192.168.1.70` (Enterprise Web Server). La Branch Server (`192.168.2.45`) n'est pas couverte par cette règle → FTP depuis Internet vers Branch Server n'est pas bloqué.

**Quelle ACL modifier ?** → **ACL 101** (l'ACL sur l'interface Internet-facing de HQ, S0/1/0).

**ACE à ajouter :**
```
HQ(config)# access-list 101 deny tcp any host 192.168.2.45 eq 21
```
À insérer **avant** le `permit ip any any`. En pratique, avec une ACL numérotée, il faudrait la réécrire dans l'ordre :

```
no access-list 101
access-list 101 deny tcp any host 192.168.1.70 eq 21
access-list 101 deny tcp any host 192.168.2.45 eq 21
access-list 101 deny icmp any 192.168.1.0 0.0.0.63
access-list 101 permit ip any any
```

> Avec une ACL **nommée**, on pourrait simplement insérer la nouvelle ACE avec un numéro de séquence entre `deny ftp → Enterprise Web Server` (seq 10) et `deny icmp` (seq 20).

## Tableau récapitulatif des commandes clés

| Commande | Contexte | Description |
|----------|----------|-------------|
| `access-list <100-199> deny/permit <proto> <src> <wc> <dst> <wc> [eq <port>]` | Global config | ACL étendue numérotée |
| `ip access-list standard <nom>` | Global config | ACL standard nommée |
| `ip access-list extended <nom>` | Global config | ACL étendue nommée |
| `ip access-group <acl> {in\|out}` | Interface config | Applique une ACL sur une interface |
| `access-class <acl> in` | Line VTY config | Applique une ACL sur les lignes VTY |
| `deny ip <src> <wc> <dst> <wc>` | ACL config | Bloque tous les protocoles IP entre src et dst |
| `show ip access-lists` | Privileged EXEC | Affiche les ACLs avec compteurs |
| `clear access-list counters` | Privileged EXEC | Remet les compteurs à zéro |

## Mémo — Points clés du lab

```
access-group vs access-class :
  ip access-group → sur interfaces réseau (filtre les paquets IP)
  access-class    → sur lignes VTY (filtre les sessions Telnet/SSH)

ACL étendue sur VTY : non recommandé → utiliser standard (filtre source suffit)

deny ip any any vs deny tcp/udp/icmp :
  deny ip → bloque TOUS les protocoles en un seul ACE (plus efficace)

Placement recap :
  Standard  → proche de la DESTINATION
  Étendue   → proche de la SOURCE
  Exception : si une interface unique couvre plusieurs sources
              (ex: S0/1/1 out sur Branch) → outbound peut être plus efficace

Modifier ACL numérotée :
  → Impossible d'insérer une ACE → supprimer et réécrire
  → Préférer les ACLs NOMMÉES pour les ACLs susceptibles d'être modifiées
```

## Script complet

```
! ============================================================
! ACL 101 — Filtrage Internet entrant (HQ)
! ============================================================
      access-list 101 deny tcp any host 192.168.1.70 eq 21
      access-list 101 deny icmp any 192.168.1.0 0.0.0.63
      access-list 101 permit ip any any

      interface s0/1/0
        ip access-group 101 in

! ============================================================
! ACL 111 — Bloquer HQ LAN 1 → Branch Server (HQ)
! ============================================================
      access-list 111 deny ip 192.168.1.0 0.0.0.63 host 192.168.2.45
      access-list 111 permit ip any any

      interface g0/0/0
        ip access-group 111 in

! ============================================================
! ACL vty_block — Restreindre accès VTY (HQ)
! ============================================================
      ip access-list standard vty_block
        permit 192.168.1.64 0.0.0.7

      line vty 0 4
        access-class vty_block in

! ============================================================
! ACL branch_to_hq — Bloquer Branch LANs → HQ LAN 1 (Branch)
! ============================================================
      ip access-list extended branch_to_hq
        deny ip 192.168.2.0 0.0.0.31 192.168.1.0 0.0.0.63
        deny ip 192.168.2.32 0.0.0.15 192.168.1.0 0.0.0.63
        permit ip any any

      interface s0/1/1
        ip access-group branch_to_hq out

! ============================================================
! Vérification
! ============================================================
  show ip access-lists
  clear access-list counters
```
