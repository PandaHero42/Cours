# Packet Tracer – Configure Static NAT

## Topologie (déduite de l'énoncé)

| Device  | Interface | Adresse IP      | Zone NAT |
|---------|-----------|-----------------|----------|
| R1      | G0/0      | —               | **Inside** (LAN interne) |
| R1      | S0/0/0    | 209.165.201.2   | **Outside** (Internet) |
| Server1 | NIC       | 172.16.16.1     | Inside Local |
| Server1 | (publique)| 64.100.50.1     | Inside Global (adresse NAT statique) |
| PC1     | NIC       | (réseau externe)| Outside |
| L1      | NIC       | (réseau externe)| Outside |

---

## Objectifs

- **Partie 1 :** Tester l'accès sans NAT → confirmer l'échec
- **Partie 2 :** Configurer le NAT statique sur R1
- **Partie 3 :** Vérifier l'accès avec NAT

---

## Contexte

**Problème :** Server1 est dans un réseau privé (`172.16.16.0/24`). PC1 et L1 sont des hôtes sur Internet qui veulent accéder au serveur web de Server1. Les adresses privées ne sont pas routables sur Internet → les paquets vers `172.16.16.1` sont détruits dans le cloud Internet.

**Solution :** NAT statique — associer définitivement l'adresse privée de Server1 (`172.16.16.1`) à une adresse publique fixe (`64.100.50.1`). Les hôtes Internet accèdent au serveur via `64.100.50.1` et R1 traduit automatiquement vers `172.16.16.1`.

**Cas d'usage typique du NAT statique :** Serveurs web, FTP, DNS, mail — tout service hébergé en interne mais accessible depuis Internet. La traduction est permanente et bidirectionnelle (inside → outside ET outside → inside).

---

## Partie 1 : Tester l'accès sans NAT

### Étape 1 : Tentative de connexion en mode Simulation

Mode **Simulation** → depuis PC1 ou L1 → Web Browser → `172.16.16.1`.

Les paquets **ne quittent pas** le cloud Internet — ils sont détruits car `172.16.16.1` est une adresse privée non routable sur Internet. Aucun routeur Internet ne possède de route vers ce réseau.

```
PC1> ping 172.16.16.1
```
→ **Échec** (Destination host unreachable ou Request timed out)

```
PC1> ping 209.165.201.2
```
→ **Succès** — l'interface S0/0/0 de R1 a une adresse publique, elle est joignable depuis Internet.

### Étape 2 : Vérifier que NAT n'est pas configuré

```
R1# show run | include nat
```
→ Aucune sortie — pas de configuration NAT sur R1.

```
R1# show ip nat translations
```
→ Table vide — aucune traduction active.

---

## Partie 2 : Configurer le NAT statique

### Étape 1 : Créer la traduction statique

```
R1(config)# ip nat inside source static 172.16.16.1 64.100.50.1
```

**Décomposition de la commande :**

| Mot-clé | Signification |
|---------|---------------|
| `ip nat inside source` | Traduit l'adresse source des paquets venant de l'intérieur |
| `static` | Traduction permanente (pas de pool, pas de timeout) |
| `172.16.16.1` | Adresse Inside Local (adresse privée réelle de Server1) |
| `64.100.50.1` | Adresse Inside Global (adresse publique visible depuis Internet) |

> **NAT statique = bidirectionnel :** Cette commande crée automatiquement une entrée dans la table NAT pour les deux sens :
> - Trafic **sortant** : `172.16.16.1` → `64.100.50.1` (Server1 initie une connexion vers Internet)
> - Trafic **entrant** : `64.100.50.1` → `172.16.16.1` (Internet accède au Server1 via son IP publique)

### Étape 2 : Configurer les interfaces inside/outside

```
R1(config)# interface g0/0
R1(config-if)# ip nat inside
```

```
R1(config)# interface s0/0/0
R1(config-if)# ip nat outside
```

> **`ip nat inside` et `ip nat outside` sont obligatoires** — sans eux, NAT ne fonctionne pas même si la règle de traduction est configurée. IOS a besoin de savoir **depuis quelle direction** le trafic arrive pour appliquer la traduction :
> - `ip nat inside` : trafic entrant sur cette interface = vient du réseau privé
> - `ip nat outside` : trafic entrant sur cette interface = vient d'Internet

## Partie 3 : Tester l'accès avec NAT

### Étape 1 : Vérifier la connectivité

```
PC1> ping 64.100.50.1
```
→ **Succès** — R1 traduit `64.100.50.1` → `172.16.16.1` et achemine vers Server1.

Depuis PC1 et L1 → Web Browser → `64.100.50.1` → la page web de Server1 s'affiche.

### Étape 2 : Vérifier la configuration NAT

```
R1# show run | include nat
```
```
ip nat inside source static 172.16.16.1 64.100.50.1
...
ip nat inside    (sur G0/0)
ip nat outside   (sur S0/0/0)
```

```
R1# show ip nat translations
```
```
Pro  Inside global    Inside local     Outside local    Outside global
---  64.100.50.1      172.16.16.1      ---              ---
tcp  64.100.50.1:80   172.16.16.1:80   <PC1_IP>:xxxx    <PC1_IP>:xxxx
```

> L'entrée statique (sans protocole ni port) est **toujours présente** dans la table — c'est la caractéristique du NAT statique. Les entrées avec port apparaissent pour chaque session active.

```
R1# show ip nat statistics
```
```
Total active translations: 1 (1 static, 0 dynamic; 0 extended)
Outside interfaces: Serial0/0/0
Inside interfaces: GigabitEthernet0/0
Hits: x  Misses: y
```

## Tableau récapitulatif des commandes clés

| Commande | Contexte | Description |
|----------|----------|-------------|
| `ip nat inside source static <inside_local> <inside_global>` | Global config | Crée une traduction NAT statique permanente |
| `ip nat inside` | Interface config | Marque l'interface comme côté privé (inside) |
| `ip nat outside` | Interface config | Marque l'interface comme côté public (outside) |
| `show ip nat translations` | Privileged EXEC | Affiche la table NAT active |
| `show ip nat statistics` | Privileged EXEC | Compteurs NAT (hits, misses, interfaces) |
| `show run \| include nat` | Privileged EXEC | Filtre la config pour afficher uniquement les lignes NAT |
| `clear ip nat translation *` | Privileged EXEC | Supprime les entrées dynamiques (les statiques restent) |

## Mémo — NAT statique

```
Cas d'usage : serveur interne accessible depuis Internet (web, FTP, mail, VPN...)

Configuration minimale (3 étapes) :
  1. Règle de traduction :
     ip nat inside source static <IP_privée> <IP_publique>

  2. Interfaces :
     interface <LAN>
       ip nat inside
     interface <WAN>
       ip nat outside

  3. Vérification :
     show ip nat translations   → entrée statique toujours présente
     show ip nat statistics     → compteurs de hits

Différences NAT statique vs dynamique vs PAT :
  Statique   → 1 privée ↔ 1 publique, permanent, bidirectionnel
  Dynamique  → pool de publiques, temporaire, initié depuis l'inside
  PAT        → N privées ↔ 1 publique (+ ports), initié depuis l'inside

Fonctionnement bidirectionnel du NAT statique :
  Paquet sortant (inside→outside) : src 172.16.16.1 → traduit en 64.100.50.1
  Paquet entrant (outside→inside) : dst 64.100.50.1 → traduit en 172.16.16.1
```
