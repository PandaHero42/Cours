# Packet Tracer – Configure Dynamic NAT

## Topologie (déduite de l'énoncé)

| Device  | Zone NAT | Réseau |
|---------|----------|--------|
| R2      | Routeur NAT | Interface(s) inside → `172.16.0.0/16` ; Interface outside → Internet |
| L1, PC1, PC2 | Inside (clients) | `172.16.0.0/16` (3 hôtes possibles) |
| Server1 | Outside | Internet |
| Pool NAT | Inside Global | `209.165.200.228/30` → 2 adresses utilisables |

**Analyse du pool `209.165.200.228/30` :**
```
Réseau  : 209.165.200.228
Hôtes   : 209.165.200.229 et 209.165.200.230
Broadcast: 209.165.200.231
→ 2 adresses publiques disponibles dans le pool
```

---

## Objectifs

- **Partie 1 :** Configurer le NAT dynamique sur R2
- **Partie 2 :** Vérifier les traductions NAT

---

## Contexte

**NAT dynamique** : les hôtes internes (`172.16.0.0/16`) se voient assigner une adresse publique depuis un pool **à la demande** lorsqu'ils initient une connexion vers Internet. La traduction est temporaire — elle expire après un timeout d'inactivité.

**Différence clé avec NAT statique et PAT :**

| Type | Adresses publiques | Nb hôtes simultanés | Direction |
|------|--------------------|---------------------|-----------|
| Statique | 1 fixe par hôte | Illimité (1 règle = 1 hôte) | Bidirectionnel |
| **Dynamique** | **Pool limité** | **= taille du pool** | Inside → Outside uniquement |
| PAT | 1 seule | Théoriquement illimité (ports) | Inside → Outside uniquement |

## Partie 1 : Configurer le NAT dynamique

### Étape 1 : Configurer l'ACL — définir le trafic à traduire

```
R2(config)# access-list 1 permit 172.16.0.0 0.0.255.255
```

> **Rôle de l'ACL dans le NAT dynamique :** L'ACL ne filtre pas ici pour bloquer du trafic — elle définit **quelles adresses source sont éligibles à la traduction NAT**. Tout paquet dont la source matche `172.16.0.0/16` sera traduit. Les autres ne le seront pas.
>
> **Wildcard `/16` :** `255.255.0.0` → inverse = `0.0.255.255`

### Étape 2 : Créer le pool d'adresses publiques

```
R2(config)# ip nat pool NAT-POOL 209.165.200.229 209.165.200.230 netmask 255.255.255.252
```

**Décomposition :**

| Paramètre | Valeur | Signification |
|-----------|--------|---------------|
| `NAT-POOL` | Nom du pool | Identifiant arbitraire (sensible à la casse) |
| `209.165.200.229` | Première adresse | Début de la plage publique |
| `209.165.200.230` | Dernière adresse | Fin de la plage publique |
| `netmask 255.255.255.252` | Masque du pool | Correspondant au `/30` |

> `.228` est l'adresse réseau et `.231` le broadcast → seules `.229` et `.230` sont utilisables comme Inside Global.

**Réponse à la question — Que se passe-t-il si plus de 2 appareils tentent d'accéder à Internet ?**

→ Le pool est **épuisé** après 2 sessions simultanées. Le 3ème hôte (`L1`, `PC1` ou `PC2`) ne peut pas obtenir d'adresse publique et sa connexion Internet **échoue**. R2 log une erreur "NAT: pool NAT-POOL exhausted". La session sera possible uniquement quand l'une des deux entrées dynamiques expire (timeout TCP = ~86400 s par défaut, mais les entrées inactives expirent en 300 s).

> C'est **la limitation principale du NAT dynamique** par rapport au PAT — le nombre de sessions simultanées est limité par la taille du pool. Pour 3 hôtes avec seulement 2 adresses publiques, PAT serait plus adapté.

### Étape 3 : Associer l'ACL au pool NAT

```
R2(config)# ip nat inside source list 1 pool NAT-POOL
```

> Cette commande lie les deux éléments : "traduire les paquets dont la source matche ACL 1 en utilisant les adresses du pool NAT-POOL". Sans cette association, ni l'ACL ni le pool n'ont d'effet NAT.

### Étape 4 : Configurer les interfaces inside/outside

```
R2(config)# interface <interface_LAN>
R2(config-if)# ip nat inside

R2(config)# interface <interface_WAN>
R2(config-if)# ip nat outside
```

> Les interfaces `inside` pointent vers le réseau `172.16.0.0/16` (L1, PC1, PC2). L'interface `outside` pointe vers Internet (là où le pool public est routable).

## Partie 2 : Vérifier l'implémentation NAT

### Étape 1 : Générer du trafic

Depuis le navigateur de L1, PC1 ou PC2 → accéder à la page web de Server1.

### Étape 2 : Observer la table NAT

```
R2# show ip nat translations
```

Exemple de sortie après connexion de PC1 :

```
Pro  Inside global       Inside local        Outside local       Outside global
tcp  209.165.200.229:xxxx  172.16.x.x:yyyy    <Server1_IP>:80     <Server1_IP>:80
```

- **Inside local** (`172.16.x.x`) : adresse privée réelle du PC
- **Inside global** (`209.165.200.229`) : adresse du pool assignée dynamiquement à ce PC
- Si une deuxième session s'ouvre depuis un autre PC → `.230` est assignée
- Si une 3ème session tente de s'ouvrir → **refusée** (pool épuisé)

```
R2# show ip nat statistics
```
```
Total active translations: x (0 static, x dynamic; x extended)
Peak translations: x
Outside interfaces: <WAN>
Inside interfaces: <LAN>
Hits: x  Misses: x
Expired translations: x
Dynamic mappings:
-- Inside Source
access-list 1 pool NAT-POOL refcount x
 pool NAT-POOL: netmask 255.255.255.252
        start 209.165.200.229 end 209.165.200.230
        type generic, total addresses 2, allocated x (x%), misses x
```

> **`allocated x (x%)`** et **`misses x`** dans `show ip nat statistics` permettent de détecter l'épuisement du pool : si `misses` augmente alors qu'il y a du trafic, le pool est saturé.

## Tableau récapitulatif des commandes clés

| Commande | Contexte | Description |
|----------|----------|-------------|
| `access-list 1 permit <réseau> <wildcard>` | Global config | Définit les hôtes internes éligibles à la traduction |
| `ip nat pool <nom> <ip_début> <ip_fin> netmask <masque>` | Global config | Crée le pool d'adresses publiques |
| `ip nat inside source list <acl> pool <nom>` | Global config | Associe l'ACL au pool — active le NAT dynamique |
| `ip nat inside` | Interface config | Marque l'interface comme côté privé |
| `ip nat outside` | Interface config | Marque l'interface comme côté public |
| `show ip nat translations` | Privileged EXEC | Table NAT active (inside local ↔ inside global) |
| `show ip nat statistics` | Privileged EXEC | Compteurs, taux d'utilisation du pool, misses |
| `clear ip nat translation *` | Privileged EXEC | Vide les entrées dynamiques (libère le pool) |

## Mémo — NAT dynamique vs PAT

```
NAT Dynamique (ce lab) :
  ip nat pool <nom> <début> <fin> netmask <masque>
  ip nat inside source list <acl> pool <nom>
  → Pool d'adresses publiques, 1 IP/session
  → Limite stricte : nb de sessions = taille du pool
  → Entrées expirent après timeout d'inactivité

PAT / NAT Overload (variante courante) :
  ip nat inside source list <acl> pool <nom> overload
  → Ou : ip nat inside source list <acl> interface <WAN> overload
  → Même IP publique pour toutes les sessions, distinguées par port
  → Pas de limite pratique de sessions simultanées
  → Solution pour ce lab si >2 hôtes → remplacer "pool NAT-POOL" par "pool NAT-POOL overload"

Épuisement du pool :
  → Symptôme : misses++ dans show ip nat statistics
  → Solution : agrandir le pool OU passer en PAT
  → Libération manuelle : clear ip nat translation *
```
