## Objectifs

- **Partie 1 :** Configurer et appliquer une ACL standard nommée
- **Partie 2 :** Vérifier l'implémentation

---

## Contexte

**Politique à implémenter :** Seuls **PC1** (`192.168.20.4`) et le **Web Server** (`192.168.100.100`) sont autorisés à accéder au **File Server** (`192.168.200.100`). Tout autre hôte est bloqué.

Ce lab introduit les **ACLs nommées** — alternative aux ACLs numérotées avec plusieurs avantages pratiques.

---

## ACL nommée vs ACL numérotée

| Caractéristique | ACL numérotée | ACL nommée |
|-----------------|---------------|------------|
| Identification | Numéro (1–99 standard) | Nom alphanumérique |
| Lisibilité | Faible (`access-list 1`) | Élevée (`File_Server_Restrictions`) |
| Modification d'une ACE | Impossible — il faut tout supprimer et réécrire | Possible : supprimer/ajouter une ACE individuelle par numéro de séquence |
| Syntaxe de création | `access-list <num> ...` | `ip access-list standard <nom>` puis ACEs dans le sous-mode |
| Application sur interface | `ip access-group <num>` | `ip access-group <nom>` |

> **Avantage clé des ACLs nommées :** On peut modifier une ACE individuelle sans recréer toute l'ACL. En numérotée, toute modification nécessite de supprimer l'ACL entière (`no access-list <num>`) et de la réécrire.

## Partie 1 : Configurer et appliquer l'ACL nommée

### Étape 1 : Vérifier la connectivité initiale

Depuis PC0, PC1 et PC2 :

```
ping 192.168.100.100   (Web Server)
ping 192.168.200.100   (File Server)
```

Tous les pings doivent réussir — baseline confirmée avant application de l'ACL.

### Étape 2 : Planifier le placement

| Élément | Décision |
|---------|----------|
| Sources autorisées | PC1 (`192.168.20.4`), Web Server (`192.168.100.100`) |
| Sources bloquées | Tout le reste (PC0, PC2, etc.) |
| Destination protégée | File Server sur `192.168.200.0/24` |
| Routeur | R1 (seul routeur, gateway de tout le monde) |
| Interface | **F0/1** (lien vers le File Server, `192.168.200.x`) |
| Direction | **outbound** — trafic sortant vers le File Server |

> **Logique de l'ACL :** En listant les deux sources autorisées en `permit host`, puis `deny any`, on crée une **liste blanche** : uniquement les hôtes explicitement autorisés peuvent atteindre le File Server.

### Étape 3 : Créer l'ACL nommée

```
R1(config)# ip access-list standard File_Server_Restrictions
R1(config-std-nacl)# permit host 192.168.20.4
R1(config-std-nacl)# permit host 192.168.100.100
R1(config-std-nacl)# deny any
```

> **`ip access-list standard <nom>`** ouvre le sous-mode de configuration de l'ACL (`config-std-nacl`). Les ACEs sont saisies directement sans répéter `access-list <num>` à chaque ligne.

> **`permit host 192.168.20.4`** est l'équivalent de `permit 192.168.20.4 0.0.0.0` — le mot-clé `host` remplace le wildcard `0.0.0.0` pour désigner une adresse IP unique.

> **`deny any`** ici est explicite (visible dans `show access-lists`), contrairement au deny implicite invisible en fin d'ACL. Le rendre explicite est une bonne pratique pour la lisibilité et pour voir les compteurs de hits sur cette ligne.

> ⚠️ **Le nom est sensible à la casse** : `File_Server_Restrictions` ≠ `file_server_restrictions`.

#### Vérifier avant d'appliquer

```
R1# show access-lists
```
```
Standard IP access list File_Server_Restrictions
    10 permit host 192.168.20.4
    20 permit host 192.168.100.100
    30 deny any
```

### Étape 4 : Appliquer l'ACL sur F0/1

```
R1(config)# interface FastEthernet0/1
R1(config-if)# ip access-group File_Server_Restrictions out
```

Sauvegarder :

```
R1# copy running-config startup-config
```

## Tableau récapitulatif des commandes clés

| Commande | Contexte | Description |
|----------|----------|-------------|
| `ip access-list standard <nom>` | Global config | Crée/entre dans une ACL standard nommée |
| `permit host <ip>` | ACL config (std-nacl) | Autorise une adresse IP unique |
| `deny any` | ACL config (std-nacl) | Bloque tout le reste (deny explicite) |
| `ip access-group <nom> {in\|out}` | Interface config | Applique l'ACL nommée sur l'interface |
| `show access-lists` | Privileged EXEC | Affiche ACLs et compteurs de hits |
| `show ip interface <if>` | Privileged EXEC | Confirme quelle ACL est appliquée |

## Mémo — ACL nommée standard

```
Syntaxe de création :
  ip access-list standard <NOM>        ← entre dans le sous-mode
    permit host <ip>                   ← autorise une IP unique
    permit <réseau> <wildcard>         ← autorise un réseau
    deny any                           ← bloque tout le reste (explicite)

Mot-clé "host" :
  permit host 192.168.20.4  =  permit 192.168.20.4 0.0.0.0

Avantage des nommées vs numérotées :
  → Modification d'une ACE individuelle possible :
    ip access-list standard <NOM>
      no 10                            ← supprime l'ACE de séquence 10
      10 permit host <nouvelle_ip>     ← recrée l'ACE à la même séquence

Logique liste blanche vs liste noire :
  Liste blanche (permit + deny any)  → tout est bloqué sauf les exceptions listées
  Liste noire  (deny + permit any)   → tout est autorisé sauf les exceptions listées
```

## Script complet

```
! ============================================================
! PARTIE 1 - Configuration et application de l'ACL nommée
! ============================================================

! --- Vérification initiale (depuis PC0, PC1, PC2) ---
ping 192.168.100.100
ping 192.168.200.100

! --- Sur R1 : création de l'ACL nommée ---
      ip access-list standard File_Server_Restrictions
        permit host 192.168.20.4
        permit host 192.168.100.100
        deny any

! --- Vérification avant application ---
  show access-lists

! --- Application sur l'interface vers le File Server ---
      interface FastEthernet0/1
        ip access-group File_Server_Restrictions out

! --- Sauvegarde ---
  copy running-config startup-config

! ============================================================
! PARTIE 2 - Vérification
! ============================================================

  show ip interface fastethernet 0/1
  show access-lists

! Tests :
! PC1       → File Server : succès
! Web Server → File Server : succès
! PC0       → File Server : ÉCHEC
! PC2       → File Server : ÉCHEC
```
