## Objectifs

- **Partie 1 :** Modifier les paramètres OSPF par défaut (timers, bande passante)
- **Partie 2 :** Vérifier la connectivité complète

---

## Contexte

OSPF est déjà configuré et tous les équipements ont une connectivité complète au départ. Ce lab porte sur deux paramètres OSPF modifiables en cours de fonctionnement :

1. **Les timers Hello/Dead** — contrôlent la détection de panne de voisinage
2. **La bande passante d'interface** — influence le calcul du coût OSPF et donc le choix du meilleur chemin

> ⚠️ Ces deux paramètres sont **critiques** : une mauvaise configuration des timers rompt les adjacences, et une bande passante incorrecte peut forcer OSPF à choisir un chemin sous-optimal.

## Partie 1 : Modifier les paramètres OSPF par défaut

### Étape 1 : Tester la connectivité initiale

Depuis chaque PC, on pinge le Web Server (`64.100.1.2`) et les autres PCs pour confirmer que tout fonctionne avant modification.

```
ping 64.100.1.2
ping 172.16.1.2
ping 172.16.2.2
ping 192.168.1.2
```

### Étape 2 : Ajuster les timers Hello et Dead entre R1 et R2

#### Rappel — Hello et Dead timers

OSPF utilise deux timers pour maintenir les adjacences entre voisins :

| Timer | Rôle | Valeur par défaut |
|-------|------|-------------------|
| **Hello interval** | Fréquence d'envoi des paquets Hello (preuve de vie) | 10 s (liens point-à-point / broadcast) |
| **Dead interval** | Délai après lequel un voisin est déclaré mort si aucun Hello n'est reçu | 40 s (= 4 × Hello) |

> **Règle absolue :** les deux extrémités d'un lien OSPF **doivent avoir des timers identiques**. Si les valeurs diffèrent, les routeurs ne forment pas (ou perdent) leur adjacence.

#### a. Configuration sur R1 (interface S0/0/0 — lien vers R2)

```
R1(config)# interface s0/0/0
R1(config-if)# ip ospf hello-interval 15
R1(config-if)# ip ospf dead-interval 60
```

> On passe le Hello à 15 s et le Dead à 60 s (= 4 × 15). Dès l'application sur R1 uniquement, R2 continue d'envoyer des Hellos toutes les 10 s mais attend 40 s max. R1, lui, n'envoie plus ses Hellos au bon rythme → R2 déclare R1 mort après 40 s.

#### b. Perte d'adjacence observée

Après quelques secondes, la console de R1 affiche :

```
%OSPF-5-ADJCHG: Process 1, Nbr 209.165.200.225 on Serial0/0/0 from FULL to DOWN,
Neighbor Down: Dead timer expired
```

L'adjacence tombe car les timers sont désormais asymétriques. Il faut **appliquer les mêmes valeurs sur R2**.

#### c. Configuration sur R2 (interface S0/0/0 — lien vers R1)

```
R2(config)# interface s0/0/0
R2(config-if)# ip ospf hello-interval 15
R2(config-if)# ip ospf dead-interval 60
```

Une fois les timers alignés des deux côtés, l'adjacence se rétablit automatiquement :

```
%OSPF-5-ADJCHG: Process 1, Nbr 192.168.10.5 on Serial0/0/0 from LOADING to FULL,
Loading Done
```

> `LOADING to FULL` : le routeur vient de terminer l'échange de sa base LSDB et la relation de voisinage est pleinement établie.

### Étape 3 : Ajuster la bande passante sur R1

#### a. Traceroute initial (avant modification)

Depuis PC1, on trace le chemin vers le Web Server :

```
tracert 64.100.1.2
```

Résultat :
```
1   172.16.1.1       (R1 - G0/0)
2   172.16.3.2       (R2 - S0/0/0)
3   209.165.200.226  (passerelle Internet)
4   64.100.1.2       (Web Server)
```

Le trafic passe **directement R1 → R2** via le lien série S0/0/0. OSPF a calculé que ce chemin a un coût inférieur au chemin R1 → R3 → R2.

#### Rappel — Calcul du coût OSPF

Le coût OSPF d'une interface est calculé ainsi :

```
Coût = Référence de bande passante / Bande passante de l'interface
     = 100 000 000 bps (100 Mbps par défaut) / Bande passante configurée
```

| Interface | Bande passante par défaut | Coût calculé |
|-----------|--------------------------|--------------|
| FastEthernet | 100 Mbps | 1 |
| Serial (T1) | 1,544 Mbps | ~64 |
| Serial (64 Kbps) | 64 Kbps | 1562 |

> **Important :** la commande `bandwidth` ne modifie **pas** la vitesse réelle du port. Elle modifie uniquement la valeur utilisée par les protocoles de routage (OSPF, EIGRP) pour leurs calculs de métrique.

#### b. Modification de la bande passante sur R1 S0/0/0

```
R1(config)# interface s0/0/0
R1(config-if)# bandwidth 64
```

On annonce à OSPF que ce lien ne vaut que 64 Kbps → son coût explose à `100 000 / 64 ≈ 1562`. Le chemin R1 → R2 direct devient beaucoup plus coûteux que R1 → R3 → R2.

#### c. Traceroute après modification

```
tracert 64.100.1.2
```

Résultat :
```
1   172.16.1.1       (R1 - G0/0)
2   192.168.10.6     (R3 - S0/0/0)
3   172.16.3.2       (R2 - S0/0/0)
4   209.165.200.226  (passerelle Internet)
5   64.100.1.2       (Web Server)
```

Le trafic passe désormais par **R1 → R3 → R2**, confirmant qu'OSPF a recalculé ses routes et préfère maintenant ce chemin (coût total inférieur malgré un saut supplémentaire).

## Tableau récapitulatif des commandes clés

| Commande | Contexte | Description |
|----------|----------|-------------|
| `ip ospf hello-interval <secondes>` | Interface config | Définit l'intervalle d'envoi des paquets Hello OSPF |
| `ip ospf dead-interval <secondes>` | Interface config | Définit le délai avant de déclarer un voisin mort |
| `bandwidth <kbps>` | Interface config | Définit la bande passante logique (métrique OSPF uniquement) |
| `show ip ospf neighbor` | Privileged EXEC | Vérifie l'état des adjacences OSPF |
| `show ip ospf interface <interface>` | Privileged EXEC | Affiche les timers et le coût OSPF d'une interface |
| `tracert <ip>` / `traceroute <ip>` | PC / Privileged EXEC | Trace le chemin utilisé vers une destination |

## Mémo — Points clés du lab

```
Timers Hello/Dead :
  └─ Doivent être identiques des deux côtés du lien
  └─ Asymétrie → perte d'adjacence (Dead timer expired)
  └─ Défaut : Hello = 10 s, Dead = 40 s (liens broadcast/point-à-point)
  └─ Commandes : ip ospf hello-interval / ip ospf dead-interval

Coût OSPF :
  └─ Coût = Référence BW (100 Mbps) / BW interface
  └─ Plus le coût est bas, plus le chemin est préféré
  └─ bandwidth <kbps> → modifie la métrique OSPF, PAS la vitesse physique
  └─ Augmenter le coût d'un lien → OSPF le contourne
```

## Script complet

```
! ============================================================
! PARTIE 1 - Modification des timers Hello/Dead
! ============================================================

! --- Sur R1 : ajustement des timers sur le lien vers R2 ---
      interface s0/0/0
        ip ospf hello-interval 15
        ip ospf dead-interval 60

! L'adjacence avec R2 tombe → appliquer les mêmes timers sur R2

! --- Sur R2 : ajustement des timers sur le lien vers R1 ---
      interface s0/0/0
        ip ospf hello-interval 15
        ip ospf dead-interval 60

! L'adjacence se rétablit automatiquement (FULL)

! ============================================================
! Modification de la bande passante (métrique OSPF)
! ============================================================

! --- Sur R1 : réduction BW logique du lien S0/0/0 vers R2 ---
      interface s0/0/0
        bandwidth 64

! OSPF recalcule : coût S0/0/0 = 100000/64 ≈ 1562
! → le chemin R1→R3→R2 devient préféré

! ============================================================
! PARTIE 2 - Vérification de la connectivité
! ============================================================

! --- Depuis PC1 (ligne de commande) ---
ping 64.100.1.2
ping 172.16.2.2
ping 192.168.1.2
tracert 64.100.1.2

! --- Vérification OSPF sur les routeurs ---
  show ip ospf neighbor
  show ip ospf interface s0/0/0
```
