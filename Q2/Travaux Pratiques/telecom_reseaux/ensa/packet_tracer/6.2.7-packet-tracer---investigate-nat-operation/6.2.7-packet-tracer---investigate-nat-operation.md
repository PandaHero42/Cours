## Contexte

Ce lab est un **lab d'observation** en mode Simulation : aucune configuration à réaliser. L'objectif est de comprendre comment les adresses IP sont modifiées lors du passage d'un paquet à travers des équipements configurés avec NAT, en suivant un paquet étape par étape dans la topologie.

**Rappel des concepts NAT :**

| Terme | Définition |
|-------|-----------|
| **Inside Local** | Adresse privée de l'hôte source (vue depuis l'intérieur) |
| **Inside Global** | Adresse publique assignée à l'hôte source après traduction NAT (vue depuis l'extérieur) |
| **Outside Local** | Adresse de la destination vue depuis l'intérieur du réseau |
| **Outside Global** | Adresse réelle de la destination sur Internet |

```
Réseau interne          |   NAT   |   Réseau externe
PC (Inside Local)  →→→  |  R2/WRS |  →→→  Serveur (Outside Global)
192.168.x.x             |         |         64.x.x.x
         ↕ traduit en              
     Inside Global
       64.100.x.x
```

## Partie 1 : NAT sur l'intranet (Central → Branch Server)

### Étape 1 : Attendre la convergence

Cliquer **Fast Forward Time** jusqu'à ce que tous les liens soient verts et que les protocoles de routage aient convergé.

### Étape 2 : Générer une requête HTTP

Mode **Simulation** → filtrer uniquement les paquets HTTP.

Depuis un PC du domaine **Central** → Web Browser → `http://branchserver.pka` → Go.

### Observation du paquet au fil du réseau

#### PDU sur D1 ou D2 (switches Central)

**Adresses IP du paquet :**
- **Source :** Adresse privée du PC Central (ex. `10.10.10.x`)
- **Destination :** Adresse résolue de `branchserver.pka` (adresse du Branch Server, ex. `172.16.0.x`)

**Réponse :** Ces adresses appartiennent au **PC source** (réseau Central) et au **Branch Server** (réseau Branch). À ce stade, le paquet n'a pas encore traversé de NAT.

#### PDU sur R2 (sortie vers le WAN)

**Adresses IP dans le paquet sortant :**
- **Source :** Une adresse du pool NAT de R2 (`64.100.100.3` – `64.100.100.31`) → **Inside Global**
- **Destination :** Adresse publique du Branch Server (ou de R4 côté WAN)

**Réponse :** L'adresse source appartient maintenant au **pool NAT R2Pool** — R2 a traduit l'adresse privée du PC en une adresse publique routable sur Internet.

Vérification sur R2 :
```
R2# show run | include pool
ip nat pool R2Pool 64.100.100.3 64.100.100.31 netmask 255.255.255.224
ip nat inside source list 1 pool R2Pool
```

#### PDU sur R4 (sortie vers le réseau Branch)

**Adresses IP dans le paquet sortant :**
- **Source :** Adresse Inside Global de R2 (`64.100.100.x`)
- **Destination :** Adresse privée du Branch Server (`172.16.0.x`) après dé-NAT par R4

**Réponse :** R4 effectue une traduction inverse : il reçoit le paquet avec destination publique et le redirige vers l'adresse privée du Branch Server sur son réseau interne.

#### PDU sur Branch Server (ports TCP)

**Ports TCP dans le segment :**
- **Port source :** Port éphémère du PC (ex. `1025`, `49152`, etc.)
- **Port destination :** `80` (HTTP)

Ces ports sont conservés dans la table NAT pour permettre la démultiplexion des sessions (PAT — Port Address Translation).

### Table NAT — `show ip nat translations`

```
R2# show ip nat translations
```
```
Pro  Inside global       Inside local        Outside local       Outside global
tcp  64.100.100.3:xxxx   10.10.10.x:yyyy     172.16.0.x:80       172.16.0.x:80
```

```
R4# show ip nat translations
```

**Réponses aux questions :**

- **Ce que les Inside Local ont en commun :** Toutes les adresses Inside Local sont des **adresses privées** (RFC 1918 : `10.x.x.x`, `172.16.x.x`, `192.168.x.x`) — non routables sur Internet.
- **Des adresses privées ont-elles traversé l'intranet ?** → **Non.** R2 traduit les adresses privées en adresses publiques avant de les envoyer sur le lien WAN. Aucune adresse privée ne circule entre R2 et R4.

## Partie 2 : NAT sur Internet (Home Office → Central Server)

### Étape 1 : Requête HTTP depuis le Home Office

Depuis un PC du domaine **Home Office** → Web Browser → `http://centralserver.pka` → Go.

### Observation sur WRS (routeur sans fil / passerelle Home Office)

**Adresses inbound (côté LAN) :**
- **Source :** Adresse privée du PC Home Office (`192.168.0.x`) — Inside Local
- **Destination :** Adresse du Central Server

**Adresses outbound (côté Internet) :**
- **Source :** Adresse publique de WRS (`64.104.223.2`) — Inside Global (PAT : une seule IP publique pour tout le réseau Home)
- **Destination :** Adresse publique du Central Server

**Réponse :** WRS fait du **PAT (Port Address Translation)** — aussi appelé NAT Overload. Tous les hôtes du réseau Home partagent une seule adresse publique (`64.104.223.2`), différenciés par leurs ports TCP.

### Observation sur R2

**Adresses dans le paquet entrant depuis Internet :**
- **Source :** `64.104.223.2` (adresse publique de WRS)
- **Destination :** Adresse publique du Central Server traduite par R2

R2 maintient sa propre table NAT pour le trafic entrant :
```
R2# show ip nat translations
```

**Réponse — Les pages web se sont-elles affichées ?** → **Oui.** La double NAT (WRS + R2) est transparente pour les applications — HTTP fonctionne correctement car les tables NAT des deux routeurs maintiennent les associations d'adresses et de ports.

## Partie 3 : Investigations complémentaires

**Les tables NAT grandissent-elles au fil du temps ?**
→ **Oui.** Chaque nouvelle session TCP (HTTP, HTTPS) crée une nouvelle entrée dans la table NAT. Les entrées expirent après un timeout d'inactivité (300 s pour TCP par défaut). Les tables peuvent donc croître avec le nombre de sessions actives simultanées.

**WRS dispose-t-il d'un pool d'adresses NAT ?**
→ **Non.** WRS utilise du **PAT (NAT Overload)** : une seule adresse publique (`64.104.223.2`) est partagée par tous les hôtes du réseau Home, distingués uniquement par leurs numéros de port. Pas besoin d'un pool.

**Est-ce ainsi que les ordinateurs de la classe se connectent à Internet ?**
→ **Oui.** Dans la plupart des réseaux domestiques et d'entreprise, le routeur (box internet, firewall) effectue du PAT — une seule IP publique, des milliers de sessions possibles simultanément grâce aux ports.

**Pourquoi NAT utilise-t-il 4 colonnes (adresses + ports) ?**
→ Pour permettre la **démultiplexion des sessions** :
- Les colonnes Inside/Outside + Local/Global permettent de tracer la correspondance exacte entre l'adresse privée d'un hôte interne et son adresse publique côté externe.
- Les **ports** permettent de distinguer plusieurs sessions simultanées du **même hôte** (ou de plusieurs hôtes partageant une IP publique via PAT) vers le même serveur.

```
Inside Local        Inside Global       Outside Local       Outside Global
PC_A:1025           64.100.x.x:1025     Serveur:80          Serveur:80
PC_B:1026           64.100.x.x:1026     Serveur:80          Serveur:80
→ Même IP publique, ports différents → PAT démultiplexe les sessions
```

**Où se trouvent les réseaux Inside Global et Inside Local ?**
→ Les réseaux **Inside Local** sont les réseaux **privés internes** (derrière le NAT) : `10.x.x.x`, `172.16.x.x`, `192.168.x.x`.
Les adresses **Inside Global** sont les adresses **publiques** attribuées par le FAI, présentes côté WAN du routeur NAT.

**Sur quels équipements NAT fonctionne-t-il ? Point commun ?**
→ NAT fonctionne sur **R2**, **R4** et **WRS**. Point commun : ce sont des **routeurs** positionnés **à la frontière** entre un réseau privé (inside) et un réseau public ou d'opérateur (outside). Ils sont les points de sortie uniques de chaque domaine.

## Tableau récapitulatif des commandes clés

| Commande | Contexte | Description |
|----------|----------|-------------|
| `show ip nat translations` | Privileged EXEC | Affiche la table NAT active (inside local/global, outside local/global, ports) |

## Mémo — Types de NAT

```
NAT Statique :
  → 1 adresse privée ↔ 1 adresse publique (fixe)
  → Utilisé pour les serveurs accessibles depuis Internet

NAT Dynamique (pool) :
  → Pool d'adresses publiques partagées par les hôtes internes
  → Limité : si le pool est épuisé, nouvelles connexions refusées

PAT (Port Address Translation) / NAT Overload :
  → 1 seule adresse publique pour tous les hôtes internes
  → Sessions distinguées par les numéros de port TCP/UDP
  → Utilisé dans ~100% des réseaux domestiques et PME
  → Commande IOS : ip nat inside source list <acl> interface <if> overload

Table NAT (show ip nat translations) :
  Inside Local  = adresse privée réelle de l'hôte
  Inside Global = adresse publique vue depuis l'extérieur
  Outside Local = adresse de la destination vue depuis l'intérieur
  Outside Global = adresse réelle de la destination
```
