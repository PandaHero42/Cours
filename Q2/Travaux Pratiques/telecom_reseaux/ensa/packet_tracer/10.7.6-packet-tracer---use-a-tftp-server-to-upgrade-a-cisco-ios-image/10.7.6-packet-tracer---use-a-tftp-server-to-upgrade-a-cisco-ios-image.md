# Packet Tracer – Use a TFTP Server to Upgrade a Cisco IOS Image

## Topologie

| Device      | Interface | Adresse IP    | Masque        | Default Gateway |
|-------------|-----------|---------------|---------------|-----------------|
| R1          | G0/0/0    | 192.168.2.1   | 255.255.255.0 | N/A             |
| R2          | G0/0      | 192.168.2.2   | 255.255.255.0 | N/A             |
| S1          | VLAN 1    | 192.168.2.3   | 255.255.255.0 | 192.168.2.1     |
| TFTP Server | NIC       | 192.168.2.254 | 255.255.255.0 | 192.168.2.1     |

---

## Objectifs

- **Partie 1 :** Mettre à jour l'image IOS sur R2 (routeur) et S1 (switch)
- **Partie 2 :** Sauvegarder l'image IOS de R1 vers le serveur TFTP

---

## Contexte

La gestion des images IOS via TFTP couvre deux cas d'usage :

| Cas | Direction | Commande |
|-----|-----------|---------|
| **Mise à jour / restauration** | TFTP → Flash | `copy tftp: flash:` |
| **Sauvegarde** | Flash → TFTP | `copy flash: tftp:` |

**Nommage des images IOS :** Le nom d'un fichier IOS contient des informations sur la plateforme et la version. Ex. `c1900-universalk9-mz.SPA.155-3.M4a.bin` :

```
c1900           → Plateforme (Cisco 1900)
universalk9     → Feature set (Universal avec chiffrement K9)
mz              → Stockage en mémoire compressé (m=RAM, z=zip)
SPA             → Signature numérique (Digitally Signed)
155-3.M4a       → Version IOS (15.5(3)M4a)
.bin            → Fichier binaire
```

## Partie 1 : Mettre à jour l'image IOS

### Étape 1 : Mise à jour IOS sur R2 (routeur 1941)

#### a–b. Vérifier les images disponibles sur le serveur TFTP

TFTP Server → onglet Services → TFTP → liste des fichiers.

**Réponse — Images compatibles avec un routeur 1941 :**
→ Les fichiers dont le nom commence par `c1900-` (la famille 1900 inclut les 1941). En l'occurrence : `c1900-universalk9-mz.SPA.155-3.M4a.bin`.

#### c. Vérifier la flash de R2

```
R2# show flash:
```

**À relever :** taille totale de la flash, espace disponible, et image IOS actuellement présente. Vérifier que l'espace libre est suffisant pour accueillir la nouvelle image **en plus** de l'ancienne (les deux coexistent pendant le processus).

#### d. Copier la nouvelle image depuis TFTP vers flash

```
R2# copy tftp: flash:
Address or name of remote host []? 192.168.2.254
Source filename []? c1900-universalk9-mz.SPA.155-3.M4a.bin
Destination filename [c1900-universalk9-mz.SPA.155-3.M4a.bin]? <cr>
```

```
Loading c1900-universalk9-mz.SPA.155-3.M4a.bin from 192.168.2.254:
!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!
[OK - 33591768 bytes]
33591768 bytes copied in 4.099 secs (860453 bytes/sec)
```

> Les `!` répétés indiquent le transfert en cours (chaque `!` = bloc transféré avec succès). L'image est copiée **en plus** de l'ancienne — les deux coexistent en flash jusqu'au redémarrage.

#### e. Vérifier le nombre d'images en flash

```
R2# show flash:
```

**Réponse :** **2 images IOS** sont maintenant présentes en flash — l'ancienne et la nouvelle `15.5`. Le routeur utilisera toujours l'ancienne jusqu'au prochain redémarrage, à moins qu'on spécifie la nouvelle avec `boot system`.

#### f. Désigner l'image à charger au prochain boot

```
R2(config)# boot system flash c1900-universalk9-mz.SPA.155-3.M4a.bin
```

> **`boot system flash <nom>`** définit explicitement quelle image IOS sera chargée au prochain `reload`. Sans cette commande, IOS charge la **première image** trouvée en flash (ordre alphabétique ou selon la configuration). Après upgrade, il est impératif de le spécifier pour charger la nouvelle version.

#### g. Sauvegarder et recharger

```
R2# copy running-config startup-config
R2# reload
```

> **Sauvegarder avant de reloader est obligatoire** : la commande `boot system` est dans la running-config — sans `copy run start`, elle disparaîtra au reboot et le routeur chargera peut-être l'ancienne image.

#### h. Vérifier après redémarrage

```
R2# show version
```

```
Cisco IOS Software, C1900 Software (C1900-UNIVERSALK9-M), Version 15.5(3)M4a
...
System image file is "flash0:c1900-universalk9-mz.SPA.155-3.M4a.bin"
```

La ligne `System image file` confirme quelle image IOS est actuellement chargée en mémoire.

### Étape 2 : Mise à jour IOS sur S1 (switch 2960)

```
S1# copy tftp: flash:
```

→ Entrer l'IP du TFTP Server (`192.168.2.254`) et le nom de fichier `c2960-lanbasek9-mz.150-2.SE4.bin`.

```
S1(config)# boot system flash c2960-lanbasek9-mz.150-2.SE4.bin
```

```
S1# copy running-config startup-config
S1# reload
```

Après redémarrage :
```
S1# show version
```

Vérifier que la nouvelle image est chargée.

## Partie 2 : Sauvegarder l'image IOS de R1 vers TFTP

### a. Identifier l'image IOS de R1

```
R1# show flash:
```

**Image présente :** `isr4300-universalk9.03.16.05.S.155-3.S5-ext.SPA.bin` (routeur ISR 4300 series).

### b. Copier l'image flash → TFTP

```
R1# copy flash: tftp:
Source filename []? isr4300-universalk9.03.16.05.S.155-3.S5-ext.SPA.bin
Address or name of remote host []? 192.168.2.254
Destination filename [isr4300-universalk9.03.16.05.S.155-3.S5-ext.SPA.bin]? <cr>
```

```
[OK - 486899872 bytes]
486899872 bytes copied in 18.815 secs (83367 bytes/sec)
```

> L'image ISR4300 (~487 MB) est **bien plus volumineuse** que l'image 1900 (~34 MB) — le transfert prend donc bien plus longtemps. C'est normal : les images IOS des routeurs haut de gamme sont plus riches en fonctionnalités.

### c. Vérifier sur le serveur TFTP

TFTP Server → Services → TFTP → l'image `isr4300-universalk9.03.16.05.S.155-3.S5-ext.SPA.bin` doit apparaître dans la liste.

> **Note PT :** Si le fichier n'apparaît pas immédiatement, désactiver et réactiver le service TFTP sur le serveur pour forcer le rafraîchissement de la liste.

## Tableau récapitulatif des commandes clés

| Commande | Contexte | Description |
|----------|----------|-------------|
| `show flash:` | Privileged EXEC | Liste les fichiers en flash (images IOS + espace disponible) |
| `copy tftp: flash:` | Privileged EXEC | Télécharge une image IOS depuis TFTP vers flash |
| `copy flash: tftp:` | Privileged EXEC | Sauvegarde une image IOS depuis flash vers TFTP |
| `boot system flash <image>` | Global config | Désigne l'image à charger au prochain reload |
| `show version` | Privileged EXEC | Affiche la version IOS active et le fichier image chargé |
| `reload` | Privileged EXEC | Redémarre le routeur/switch |

---

## Mémo — Procédure complète d'upgrade IOS

```
1. Vérifier l'espace flash disponible :
   show flash:
   → S'assurer que l'espace libre ≥ taille de la nouvelle image

2. Télécharger la nouvelle image :
   copy tftp: flash:
   → host: <IP_TFTP>
   → source filename: <nom_image_nouvelle>
   → destination: <cr> (même nom)

3. Vérifier la présence des deux images :
   show flash:
   → Ancienne + nouvelle image doivent coexister

4. Désigner la nouvelle image au boot :
   boot system flash <nom_image_nouvelle>

5. Sauvegarder la configuration (OBLIGATOIRE) :
   copy running-config startup-config

6. Redémarrer :
   reload

7. Vérifier après reboot :
   show version
   → "System image file is" → doit pointer vers la nouvelle image

8. (Optionnel) Supprimer l'ancienne image si espace limité :
   delete flash:<ancienne_image>

Nommage image IOS :
  c1900-universalk9-mz.SPA.155-3.M4a.bin
  │     │           ││ │   └─ Version (15.5(3)M4a)
  │     │           ││ └─── Signed (SPA = digitally signed)
  │     │           │└───── Compressé (z = zipped)
  │     │           └────── Stocké en RAM (m = memory)
  │     └────────────────── Feature set (universalk9 = tous + chiffrement)
  └──────────────────────── Plateforme (c1900 = Cisco 1900 series)
```

## Script complet

```
! ============================================================
! PARTIE 1 - Mise à jour IOS (R2 et S1)
! ============================================================

! --- Sur R2 ---
  show flash:

  copy tftp: flash:
! → host: 192.168.2.254
! → source: c1900-universalk9-mz.SPA.155-3.M4a.bin
! → destination: <cr>

  show flash:

      boot system flash c1900-universalk9-mz.SPA.155-3.M4a.bin

  copy running-config startup-config
  reload

! Après reboot :
  show version

! --- Sur S1 (même procédure) ---
  copy tftp: flash:
! → source: c2960-lanbasek9-mz.150-2.SE4.bin

      boot system flash c2960-lanbasek9-mz.150-2.SE4.bin

  copy running-config startup-config
  reload
  show version

! ============================================================
! PARTIE 2 - Sauvegarde IOS R1 → TFTP
! ============================================================

! --- Sur R1 ---
  show flash:

  copy flash: tftp:
! → source: isr4300-universalk9.03.16.05.S.155-3.S5-ext.SPA.bin
! → host: 192.168.2.254
! → destination: <cr>
```
