## Méthodologie de dépannage — Approche top-down avec ICMP

```
Étape 1 : Test global (ping tous les hôtes ↔ tous + Internet)
           → Identifier quels hôtes/réseaux sont défaillants

Étape 2 : Localiser la frontière de la panne (divide & conquer)
           → ping gateway local : réussi = problème au-delà du LAN local
           → ping gateway local : échoue = problème sur le LAN ou la gateway

Étape 3 : Traceroute depuis le PC en échec
           → Identifier le dernier saut répondant = frontière de la panne

Étape 4 : Accès aux équipements défaillants
           → Telnet → show ip interface brief, show run, show ip route

Étape 5 : Corriger, sauvegarder, retester
```

## Partie 2 : Accéder aux équipements réseau

### Utiliser traceroute pour localiser la panne

```
PC1> tracert <destination_IP>
```

Le dernier routeur qui répond = le dernier point fonctionnel. Le problème se situe **après** ce point.

### Accès Telnet depuis le PC défaillant

```
PC> telnet <IP_gateway>
Password: cisco
Router> enable
Password: class
Router#
```

### Commandes de diagnostic sur chaque équipement

```
show ip interface brief    → Interfaces up/down, IP configurées
show interfaces            → État détaillé, erreurs, duplex/speed
show ip route              → Table de routage, routes manquantes
show run                   → Configuration complète
show ip nat translations   → NAT actif (si applicable)
show ip nat statistics     → Interfaces inside/outside NAT
show cdp neighbors         → Voisins connectés
```

## Partie 3 : Corriger les problèmes

### Checklist des problèmes courants à vérifier

#### Adressage

```
! IP incorrecte sur une interface :
Router(config)# interface <if>
Router(config-if)# ip address <IP_correcte> <masque>

! Masque incorrect sur un PC :
→ GUI PC → Desktop → IP Configuration → corriger manuellement

! Default gateway incorrecte sur un PC :
→ Corriger via GUI ou ipconfig
```

#### Interface non activée

```
! Interface en shutdown :
Router(config)# interface <if>
Router(config-if)# no shutdown
```

#### Routage

```
! Route statique manquante :
Router(config)# ip route <réseau> <masque> <next-hop>

! OSPF : réseau non annoncé :
Router(config)# router ospf 1
Router(config-router)# network <réseau> <wildcard> area 0

! OSPF : route par défaut non propagée :
Router(config)# router ospf 1
Router(config-router)# default-information originate

! Protocole de routage arrêté :
→ show run | section router → vérifier la config
```

#### NAT

```
! Interface non marquée inside :
Router(config)# interface <if_interne>
Router(config-if)# ip nat inside

! Interface non marquée outside :
Router(config)# interface <if_WAN>
Router(config-if)# ip nat outside

! ACL NAT incorrecte :
→ show run | include nat → vérifier ACL et pool
```

## Partie 4 : Documenter les problèmes et corrections

Tableau à compléter lors de l'exécution du lab (les bugs réels dépendent du fichier PT) :

| Device | Problème identifié | Action corrective |
|--------|-------------------|-------------------|
| (ex. R2) | Interface G0/1 en `shutdown` | `no shutdown` sur G0/1 |
| (ex. R1) | Route par défaut manquante | `ip route 0.0.0.0 0.0.0.0 <next-hop>` |
| (ex. R2) | Interface S0/0/0 sans `ip nat inside` | `ip nat inside` sur S0/0/0 |
| (ex. PC3) | IP incorrecte (mauvais sous-réseau) | Corriger IP dans GUI PC |
| (ex. Router) | Réseau non annoncé en OSPF | `network <réseau> <wc> area 0` |

## Mémo — Approche structurée de dépannage réseau

```
1. TESTER d'abord (avant de toucher quoi que ce soit)
   → Identifier précisément quels flux échouent

2. LOCALISER avec traceroute
   → Trouver la frontière entre fonctionnel et défaillant

3. ACCÉDER à l'équipement suspect
   → Telnet/SSH → show ip int brief, show run, show ip route

4. COMPARER avec la documentation
   → Écart entre config attendue et config réelle = le bug

5. CORRIGER et SAUVEGARDER
   → Toujours copy run start après correction

6. VÉRIFIER immédiatement
   → Retester le flux qui échouait

7. DOCUMENTER le bug et la correction
   → Tableau Device / Problème / Action
```
