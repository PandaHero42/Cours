## Contexte — PAT (Port Address Translation)

PAT = NAT Overload. Plusieurs hôtes internes partagent une ou plusieurs adresses publiques, différenciés par leurs **numéros de port TCP/UDP**.

**Deux variantes de PAT dans ce lab :**

| Variante | Syntaxe | Usage typique |
|----------|---------|---------------|
| **Pool + overload** (R1) | `ip nat inside source list <acl> pool <nom> overload` | Plusieurs IPs publiques disponibles, utilisées séquentiellement avec ports |
| **Interface + overload** (R2) | `ip nat inside source list <acl> interface <WAN> overload` | Une seule IP publique (celle de l'interface WAN) — cas le plus courant (box internet) |

> **`overload`** est le mot-clé qui active PAT. Sans `overload`, c'est du NAT dynamique classique (1 IP publique par hôte). Avec `overload`, une même IP publique peut servir des milliers de sessions simultanées grâce aux ports.

## Partie 1 : PAT avec pool (R1)

### Étape 1 : ACL — définir les hôtes à traduire

```
R1(config)# access-list 1 permit 172.16.0.0 0.0.255.255
```

### Étape 2 : Créer le pool

```
R1(config)# ip nat pool ANY_POOL_NAME 209.165.200.233 209.165.200.234 netmask 255.255.255.252
```

> Le nom du pool (`ANY_POOL_NAME`) est arbitraire — l'énoncé laisse le choix. Il doit juste être cohérent entre la commande `pool` et la commande d'association.

### Étape 3 : Associer ACL + pool + activer PAT

```
R1(config)# ip nat inside source list 1 pool ANY_POOL_NAME overload
```

> **Différence avec le lab NAT dynamique :** La seule différence est le mot `overload` à la fin. Ce simple mot-clé transforme le comportement :
> - **Sans `overload`** : 1 IP du pool par hôte, 2 hôtes max simultanés (taille du pool)
> - **Avec `overload`** : toutes les sessions utilisent `.233` (puis `.234` quand les ports de `.233` sont épuisés), hôtes illimités en pratique

### Étape 4 : Configurer les interfaces

```
R1(config)# interface s0/1/0
R1(config-if)# ip nat outside

R1(config)# interface g0/0/0
R1(config-if)# ip nat inside

R1(config)# interface g0/0/1
R1(config-if)# ip nat inside
```

> R1 a **deux interfaces inside** (G0/0/0 et G0/0/1) — deux LANs distincts dont les hôtes bénéficient du PAT. Les deux interfaces `ip nat inside` alimentent la même règle NAT.

## Partie 2 : Vérifier PAT avec pool (R1)

### Étape 1 : Test — 4 hôtes simultanés

Depuis PC1, L1, PC2, L2 → Web Browser → `Server1`.

**Réponse — Toutes les connexions ont-elles réussi ?** → **Oui.** Avec PAT, les 4 hôtes peuvent accéder simultanément à Internet en partageant les 2 adresses publiques du pool. Chaque session est distinguée par son port TCP source.

### Étape 2 : Table NAT

```
R1# show ip nat translations
```

```
Pro  Inside global           Inside local          Outside local    Outside global
tcp  209.165.200.233:1024    172.16.0.10:1045      <S1>:80          <S1>:80
tcp  209.165.200.233:1025    172.16.0.11:1046      <S1>:80          <S1>:80
tcp  209.165.200.233:1026    172.16.1.10:1047      <S1>:80          <S1>:80
tcp  209.165.200.233:1027    172.16.1.11:1048      <S1>:80          <S1>:80
```

**Observation clé :** Les 4 sessions utilisent toutes la même IP publique (`209.165.200.233`) — seuls les **ports** diffèrent. PAT continuera d'utiliser `.233` jusqu'à épuisement des ports (théorique max ≈ 65 536 ports par IP), puis passera à `.234`.

> **Limite théorique vs pratique :** Le champ port TCP/UDP est sur 16 bits → max 65 535 sessions par IP publique. En pratique, la mémoire du routeur s'épuise bien avant cette limite.

## Partie 3 : PAT via interface (R2)

### Étape 1 : ACL

```
R2(config)# access-list 2 permit 172.17.0.0 0.0.255.255
```

### Étape 2 : PAT via interface — pas de pool

```
R2(config)# ip nat inside source list 2 interface s0/1/1 overload
```

> **Syntaxe `interface <WAN>` :** R2 utilise directement l'IP de son interface WAN (`s0/1/1`) comme adresse Inside Global — pas besoin de définir un pool séparé. L'IP publique est celle de l'interface, obtenue dynamiquement via DHCP chez un FAI ou configurée statiquement. C'est la méthode la plus courante dans les box Internet domestiques et les petits routeurs d'entreprise.

### Étape 3 : Interfaces NAT de R2

```
R2(config)# interface <LAN_interfaces>
R2(config-if)# ip nat inside

R2(config)# interface s0/1/1
R2(config-if)# ip nat outside
```

## Partie 4 : Vérifier et comparer R1 vs R2

### Étape 1 : Test — 4 hôtes simultanés sur R2

Depuis PC3, L3, PC4, L4 → Web Browser → `Server1`.

**Réponse — Toutes les connexions ont-elles réussi ?** → **Oui.** Même résultat que R1 — PAT via interface gère tout autant de sessions simultanées.

### Étape 3 : Comparer `show ip nat statistics` sur R1 et R2

```
R1# show ip nat statistics
```
```

-- Inside Source
access-list 1 pool ANY_POOL_NAME refcount x
 pool ANY_POOL_NAME: netmask 255.255.255.252
        start 209.165.200.233 end 209.165.200.234
        type generic, total addresses 2, allocated x (x%), misses x
```

```
R2# show ip nat statistics
```
```
Dynamic mappings:
-- Inside Source
access-list 2 interface Serial0/1/1 refcount x
```

**Réponse — Pourquoi R2 ne liste aucun "dynamic mapping" de pool ?**

→ R2 utilise **PAT via interface** (`interface s0/1/1`), pas un pool. Il n'y a pas de pool à afficher — l'adresse publique est directement celle de l'interface WAN. La section `Dynamic mappings` de R2 référence donc une **interface** et non un pool avec plage d'adresses.

## Tableau récapitulatif des commandes clés

| Commande | Contexte | Description |
|----------|----------|-------------|
| `ip nat inside source list <acl> pool <nom> overload` | Global config | PAT avec pool d'adresses partagées |
| `ip nat inside source list <acl> interface <WAN> overload` | Global config | PAT via interface WAN (IP unique de l'interface) |
| `ip nat inside` | Interface config | Marque l'interface comme inside |
| `ip nat outside` | Interface config | Marque l'interface comme outside |
| `show ip nat translations` | Privileged EXEC | Table NAT — observer le partage de l'IP publique avec ports différents |
| `show ip nat statistics` | Privileged EXEC | Compteurs + type de mapping (pool vs interface) |

## Mémo — Les 3 types NAT en résumé

```
1. NAT Statique :
   ip nat inside source static <local> <global>
   → 1 IP privée ↔ 1 IP publique, permanent, bidirectionnel
   → Cas : serveur interne accessible depuis Internet

2. NAT Dynamique :
   ip nat pool <nom> <début> <fin> netmask <masque>
   ip nat inside source list <acl> pool <nom>
   → N IP privées → pool d'IP publiques, 1 IP/session, temporaire
   → Limite : nb sessions = taille du pool

3. PAT / NAT Overload :
   a) Avec pool :
      ip nat inside source list <acl> pool <nom> overload
      → Pool d'IP publiques partagées avec ports (rare)

   b) Via interface (le plus courant) :
      ip nat inside source list <acl> interface <WAN> overload
      → Une seule IP publique (celle du WAN), ports différencient les sessions
      → Cas typique : box internet, routeur SOHO, Cisco C1111...

Démultiplexion PAT :
  [IP_publique : port_source] → [IP_privée : port_interne]
  Même IP publique, ports différents = sessions différentes
  Capacité théorique : ~65 000 sessions par IP publique
```

## Script complet

```
! ============================================================
! PARTIE 1 - PAT avec pool (R1)
! ============================================================

! --- Sur R1 ---
      access-list 1 permit 172.16.0.0 0.0.255.255

      ip nat pool ANY_POOL_NAME 209.165.200.233 209.165.200.234 netmask 255.255.255.252

      ip nat inside source list 1 pool ANY_POOL_NAME overload

      interface s0/1/0
        ip nat outside

      interface g0/0/0
        ip nat inside

      interface g0/0/1
        ip nat inside

  show ip nat translations

      access-list 2 permit 172.17.0.0 0.0.255.255

        ip nat inside

  show ip nat translations
```
