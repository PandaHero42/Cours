## Objectifs

- **Partie 1 :** ACL étendue numérotée (ACL 100) — PC1 : FTP + ICMP vers le Server
- **Partie 2 :** ACL étendue nommée (HTTP_ONLY) — PC2 : HTTP + ICMP vers le Server

## Contexte et politique de sécurité

| Hôte | Accès autorisé vers le Server | Accès refusé |
|------|-------------------------------|--------------|
| PC1 (`172.22.34.66`) | FTP (port 21) + ICMP (ping) | Tout le reste, dont HTTP et ping vers PC2 |
| PC2 (`172.22.34.98`) | HTTP (port 80) + ICMP (ping) | Tout le reste, dont FTP et ping vers PC1 |
| PC1 ↔ PC2 | — | Ping mutuel bloqué |

---

## Rappel — ACL étendue vs ACL standard

| Critère | Standard | Étendue |
|---------|----------|---------|
| Filtre sur | Source IP uniquement | Source IP + Destination IP + Protocole + Port |
| Numéros | 1–99, 1300–1999 | 100–199, 2000–2699 |
| Placement recommandé | Proche de la destination | **Proche de la source** (filtre précis → moins d'impact sur le reste) |
| Syntaxe | `access-list <num> permit/deny <src> <wc>` | `access-list <num> permit/deny <proto> <src> <wc> <dst> <wc> [eq <port>]` |

> **Placement proche de la source :** Une ACL étendue peut filtrer précisément (protocole + destination) donc on peut la placer près de la source sans bloquer du trafic légitime vers d'autres destinations. Cela évite que le trafic parcoure inutilement tout le réseau avant d'être bloqué.

## Calcul des wildcards

**Méthode 1 — Inverse bit à bit :**
```
/27 → 255.255.255.224 → 11111111.11111111.11111111.11100000
                    inverse → 00000000.00000000.00000000.00011111 = 0.0.0.31
```

**Méthode 2 — Soustraction (plus rapide) :**
```
255.255.255.255
- 255.255.255.240  (masque /28)
= 0.0.0.15
```

## Partie 1 : ACL étendue numérotée — ACL 100 (PC1 LAN)

### Étape 1 : Créer l'ACL 100

#### Exploration de la syntaxe (aide contextuelle `?`)

```
R1(config)# access-list ?
  <1-99>    IP standard access list
  <100-199> IP extended access list

R1(config)# access-list 100 permit ?
  icmp  Internet Control Message Protocol
  ip    Any Internet Protocol
  tcp   Transmission Control Protocol
  udp   User Datagram Protocol
  ...
```

> FTP n'apparaît pas dans la liste des protocoles car c'est un **protocole applicatif** — au niveau transport, FTP utilise **TCP**. On sélectionne donc `tcp` puis on précise le port `eq ftp` (= port 21).

#### Commandes

```
R1(config)# access-list 100 permit tcp 172.22.34.64 0.0.0.31 host 172.22.34.62 eq ftp
R1(config)# access-list 100 permit icmp 172.22.34.64 0.0.0.31 host 172.22.34.62
```

**Décomposition de la première ACE :**

| Champ | Valeur | Signification |
|-------|--------|---------------|
| `100` | Numéro ACL | ACL étendue |
| `permit` | Action | Autorise |
| `tcp` | Protocole | Transport TCP |
| `172.22.34.64 0.0.0.31` | Source + wildcard | Tout hôte du réseau PC1 (`/27`) |
| `host 172.22.34.62` | Destination | Uniquement le Server (IP unique) |
| `eq ftp` | Port destination | Port 21 (FTP) uniquement |

**Deuxième ACE :**
- `icmp` : protocole ICMP (ping) — pas de notion de port pour ICMP
- Même source (PC1 LAN) → même destination (Server uniquement)

> **Deny implicite final :** Tout trafic non matché (ping vers PC2, HTTP, etc.) est bloqué par le `deny any any` implicite. Il n'est pas nécessaire de l'écrire, mais le faire explicitement est une bonne pratique.

#### Vérification

```
R1# show access-lists
Extended IP access list 100
    10 permit tcp 172.22.34.64 0.0.0.31 host 172.22.34.62 eq ftp
    20 permit icmp 172.22.34.64 0.0.0.31 host 172.22.34.62
```

### Étape 2 : Appliquer l'ACL 100

L'ACL filtre le trafic **venant du réseau PC1** → on l'applique **inbound sur G0/0** (interface de R1 côté PC1).

```
R1(config)# interface gigabitEthernet 0/0
R1(config-if)# ip access-group 100 in
```

> **Pourquoi inbound ?** Le trafic de PC1 entre dans R1 par G0/0. En filtrant inbound, on bloque le trafic dès son arrivée sur le routeur — avant tout traitement de routage. C'est le placement recommandé pour les ACLs étendues côté source.

### Étape 3 : Vérifier

| Test | Résultat attendu | Raison |
|------|-----------------|--------|
| `ping 172.22.34.62` (PC1 → Server) | ✅ | `permit icmp` matche |
| `ftp 172.22.34.62` (PC1 → Server) | ✅ | `permit tcp eq ftp` matche |
| `ping 172.22.34.98` (PC1 → PC2) | ❌ | Destination = PC2 ≠ Server → `deny any any` implicite |

```
PC1> ftp 172.22.34.62
Username: cisco
Password: cisco
ftp> quit
```

## Partie 2 : ACL étendue nommée — HTTP_ONLY (PC2 LAN)

### Étape 1 : Créer l'ACL HTTP_ONLY

```
R1(config)# ip access-list extended HTTP_ONLY
R1(config-ext-nacl)# permit tcp 172.22.34.96 0.0.0.15 host 172.22.34.62 eq www
R1(config-ext-nacl)# permit icmp 172.22.34.96 0.0.0.15 host 172.22.34.62
```

> **`eq www`** = port 80 (HTTP). Le mot-clé `www` est un alias pour le port 80, comme `ftp` = 21, `telnet` = 23, `smtp` = 25.

> **Wildcard PC2 LAN `/28` :** `255.255.255.255 - 255.255.255.240 = 0.0.0.15`

> **`ip access-list extended`** ouvre le sous-mode `config-ext-nacl` — les ACEs sont saisies directement sans répéter `access-list <num>` à chaque ligne, comme pour les ACLs standard nommées.

#### Vérification des deux ACLs

```
R1# show access-lists
Extended IP access list 100
    10 permit tcp 172.22.34.64 0.0.0.31 host 172.22.34.62 eq ftp
    20 permit icmp 172.22.34.64 0.0.0.31 host 172.22.34.62
Extended IP access list HTTP_ONLY
    10 permit tcp 172.22.34.96 0.0.0.15 host 172.22.34.62 eq www
    20 permit icmp 172.22.34.96 0.0.0.15 host 172.22.34.62
```

### Étape 2 : Appliquer HTTP_ONLY

```
R1(config)# interface gigabitEthernet 0/1
R1(config-if)# ip access-group HTTP_ONLY in
```

### Étape 3 : Vérifier

| Test | Résultat attendu | Raison |
|------|-----------------|--------|
| `ping 172.22.34.62` (PC2 → Server) | ✅ | `permit icmp` matche |
| Navigateur → `172.22.34.62` (PC2 → Server HTTP) | ✅ | `permit tcp eq www` matche |
| `ftp 172.22.34.62` (PC2 → Server FTP) | ❌ | FTP non autorisé pour PC2 → `deny any any` |

## Tableau récapitulatif des commandes clés

| Commande | Contexte | Description |
|----------|----------|-------------|
| `access-list <100-199> permit/deny <proto> <src> <wc> <dst> <wc> [eq <port>]` | Global config | ACL étendue numérotée |
| `ip access-list extended <nom>` | Global config | Crée une ACL étendue nommée |
| `permit/deny <proto> <src> <wc> <dst> <wc> [eq <port>]` | ACL ext config | ACE dans une ACL nommée |
| `ip access-group <num/nom> {in\|out}` | Interface config | Applique l'ACL |
| `show access-lists` | Privileged EXEC | Affiche toutes les ACLs et compteurs |

**Ports courants :**

| Mot-clé | Port | Protocole |
|---------|------|-----------|
| `ftp` | 21 | FTP (TCP) |
| `telnet` | 23 | Telnet (TCP) |
| `smtp` | 25 | Email sortant (TCP) |
| `www` | 80 | HTTP (TCP) |
| `pop3` | 110 | Email entrant (TCP) |

---

## Mémo — Syntaxe ACL étendue

```
Syntaxe générale :
  access-list <100-199> {permit|deny} <protocole> <src> <wc-src> <dst> <wc-dst> [eq <port>]

Protocoles courants :
  tcp, udp, icmp, ip (= tout protocole)

Filtrage par port (TCP/UDP uniquement) :
  eq <port>    → égal au port
  lt <port>    → inférieur au port
  gt <port>    → supérieur au port
  range <p1> <p2> → plage de ports

Mot-clé "host" :
  host 172.22.34.62  =  172.22.34.62 0.0.0.0

Placement recommandé :
  ACL étendue → le plus proche de la SOURCE (filtre précis)
  ACL standard → le plus proche de la DESTINATION (filtre large)

Direction :
  in  → filtre le trafic entrant (de la source vers le routeur)
  out → filtre le trafic sortant (du routeur vers la destination)
```

## Script complet

```
! ============================================================
! PARTIE 1 - ACL étendue numérotée (PC1 LAN : FTP + ICMP)
! ============================================================

! --- Sur R1 ---
      access-list 100 permit tcp 172.22.34.64 0.0.0.31 host 172.22.34.62 eq ftp
      access-list 100 permit icmp 172.22.34.64 0.0.0.31 host 172.22.34.62

  show access-lists

      interface gigabitEthernet 0/0
        ip access-group 100 in

! --- Tests depuis PC1 ---
ping 172.22.34.62
ftp 172.22.34.62
ping 172.22.34.98

! ============================================================
! PARTIE 2 - ACL étendue nommée (PC2 LAN : HTTP + ICMP)
! ============================================================

! --- Sur R1 ---
      ip access-list extended HTTP_ONLY
        permit tcp 172.22.34.96 0.0.0.15 host 172.22.34.62 eq www
        permit icmp 172.22.34.96 0.0.0.15 host 172.22.34.62

  show access-lists

      interface gigabitEthernet 0/1
        ip access-group HTTP_ONLY in

! --- Tests depuis PC2 ---
ping 172.22.34.62
! Navigateur → 172.22.34.62 (HTTP → succès)
ftp 172.22.34.62
! (FTP → échec attendu)
```
