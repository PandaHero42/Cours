## Analyse des exigences avant configuration

### Logique de sécurité CDP/LLDP dans ce lab

```
Réseau HQ (LLDP uniquement) :
  HQ router ←── LLDP ─── HQ-SW-1/SW-2
  → HQ reçoit les infos des switches (no transmit sur HQ)
  → Les switches envoient mais ne reçoivent pas (no receive sur SW uplink)
  → Les ports d'accès des switches = LLDP totalement désactivé

Réseau Branch (CDP uniquement) :
  Branch router → CDP activé
  → Les switches Branch : CDP désactivé sur les ports d'accès uniquement
    (pas de CDP vers les PCs/hôtes)

NTP :
  HQ → synchronisé sur 192.168.1.254
```

### Vue d'ensemble des configurations requises

| Équipement | CDP | LLDP | NTP |
|------------|-----|------|-----|
| HQ | Désactiver globalement | Activer global ; no transmit sur G0/0/0, G0/0/1 | `ntp server 192.168.1.254` |
| HQ-SW-1 | Désactiver globalement | Activer global ; no receive sur uplink HQ ; no tx + no rx sur ports d'accès | — |
| HQ-SW-2 | Désactiver globalement | Activer global ; no receive sur uplink HQ ; no tx + no rx sur ports d'accès | — |
| Branch | Activer CDP | — | — |
| BR-SW-1/2/3 | no cdp enable sur ports d'accès | — | — |

## Configuration LLDP — Réseau HQ

### Sur HQ

```
HQ(config)# no cdp run

HQ(config)# lldp run

! Interfaces vers les switches : recevoir seulement (pas d'envoi)
HQ(config)# interface G0/0/0
HQ(config-if)# no lldp transmit

HQ(config)# interface G0/0/1
HQ(config-if)# no lldp transmit
```

> HQ **reçoit** les annonces LLDP des switches (pour découvrir la topologie) mais **n'envoie pas** vers eux — les switches ne doivent pas pouvoir identifier le routeur HQ via LLDP.

### Sur HQ-SW-1

IP non configurée → accès direct via CLI Packet Tracer (clic sur le switch).

```
HQ-SW-1(config)# no cdp run

HQ-SW-1(config)# lldp run

! Uplink vers HQ : envoyer seulement (pas de réception)
HQ-SW-1(config)# interface <uplink_vers_HQ>
HQ-SW-1(config-if)# no lldp receive

! Ports d'accès en service : LLDP totalement désactivé
HQ-SW-1(config)# interface <access_port_1>
HQ-SW-1(config-if)# no lldp transmit
HQ-SW-1(config-if)# no lldp receive

HQ-SW-1(config)# interface <access_port_2>
HQ-SW-1(config-if)# no lldp transmit
HQ-SW-1(config-if)# no lldp receive
```

> **Uplink vers HQ :** `no lldp receive` uniquement — le switch envoie ses infos à HQ (`transmit` reste actif) mais n'accepte pas les annonces de HQ (`receive` désactivé). Cohérent avec la configuration de HQ (`no transmit`).
>
> **Ports d'accès :** `no lldp transmit` + `no lldp receive` = LLDP totalement muet sur ces ports. Les PCs connectés ne doivent pas recevoir ni envoyer d'informations LLDP — ils ne sont pas des équipements réseau et n'ont pas à participer à la découverte de topologie.

### Sur HQ-SW-2 (même configuration)

```
HQ-SW-2(config)# no cdp run
HQ-SW-2(config)# lldp run
HQ-SW-2(config)# interface <uplink_vers_HQ>
HQ-SW-2(config-if)# no lldp receive
HQ-SW-2(config)# interface <access_port_en_service>
HQ-SW-2(config-if)# no lldp transmit
HQ-SW-2(config-if)# no lldp receive
```

## Configuration CDP — Réseau Branch

### Sur Branch (routeur)

```
Branch(config)# cdp run
```

### Sur BR-SW-1, BR-SW-2, BR-SW-3 (accès SSH obligatoire)

Les switches Branch ne peuvent pas être cliqués directement dans PT → SSH depuis Branch :

```
! Depuis Branch, SSH vers chaque BR-SW (IP à découvrir via CDP)
Branch# ssh -l admin <IP_BR-SW1>
Password: SW1admin#
BR-SW1> enable
Password: SW1EnaAccess#
BR-SW1#
```

Une fois connecté, désactiver CDP uniquement sur les **ports d'accès en service** (pas globalement — CDP reste actif sur les liens inter-switches et vers le routeur) :

```
BR-SW1(config)# interface <access_port_en_service>
BR-SW1(config-if)# no cdp enable

! Répéter pour chaque port d'accès actif
```

> **Pourquoi `no cdp enable` sur les ports d'accès seulement (pas `no cdp run`) ?** Le CDP global doit rester actif sur les switches Branch pour que le routeur Branch puisse découvrir les switches. Seuls les ports vers les PCs/hôtes finals doivent être silencieux — les hôtes n'ont pas à recevoir des informations de topologie Cisco.

Répéter la procédure SSH + `no cdp enable` sur les ports d'accès pour BR-SW-2 et BR-SW-3.

## Tableau récapitulatif des commandes clés

| Commande | Contexte | Description |
|----------|----------|-------------|
| `no cdp run` | Global config | Désactive CDP globalement |
| `cdp run` | Global config | Active CDP globalement |
| `no cdp enable` | Interface config | Désactive CDP sur une interface spécifique |
| `lldp run` | Global config | Active LLDP globalement |
| `no lldp transmit` | Interface config | Désactive l'envoi LLDP sur l'interface |
| `no lldp receive` | Interface config | Désactive la réception LLDP sur l'interface |
| `ntp server <IP>` | Global config | Configure le serveur NTP |
| `show lldp neighbors [detail]` | Privileged EXEC | Voisins LLDP découverts |
| `show cdp neighbors [detail]` | Privileged EXEC | Voisins CDP découverts |
| `show ntp status` | Privileged EXEC | État de synchronisation NTP |

## Mémo — Schéma des flux CDP/LLDP dans ce lab

```
RÉSEAU HQ — LLDP ASYMÉTRIQUE :

  HQ (no transmit G0/0/0, G0/0/1)
      ↑ LLDP reçu (SW → HQ)
      ✗ LLDP non envoyé (HQ → SW)
      │
  HQ-SW-1/SW-2
      → uplink vers HQ : no receive (SW envoie, ne reçoit pas)
      → access ports : no transmit + no receive (silence total)

RÉSEAU BRANCH — CDP SÉLECTIF :

  Branch router (cdp run)
      ↔ CDP avec BR-SW-1/2/3 (liens trunk/uplink)
      │
  BR-SW-1/2/3
      → uplinks entre switches : CDP actif
      → access ports : no cdp enable (silence vers les PCs)

NTP :
  HQ ─── ntp server 192.168.1.254 ──→ NTP Server
  HQ devient Stratum 2
```

```
! ============================================================

      no cdp run
      lldp run
      interface G0/0/0
        no lldp transmit
      interface G0/0/1
        no lldp transmit

! ============================================================
! LLDP — HQ-SW-1
! ============================================================

      no cdp run
      lldp run
      interface <uplink_HQ>
        no lldp receive
      interface <access_port_1>
        no lldp transmit
        no lldp receive
      interface <access_port_2>
        no lldp transmit
        no lldp receive

! ============================================================
! LLDP — HQ-SW-2 (même structure)
! ============================================================

      no cdp run
      lldp run
      interface <uplink_HQ>
        no lldp receive
      interface <access_port_en_service>
        no lldp transmit
        no lldp receive

! ============================================================
! CDP — Branch router
! ============================================================

      cdp run

! ============================================================
! CDP — BR-SW-1 (via SSH depuis Branch)
! ============================================================

! Branch# ssh -l admin <IP_BR-SW1>
! Password: SW1admin#  →  enable  →  SW1EnaAccess#

      interface <access_port_en_service>
        no cdp enable

! Répéter pour BR-SW-2 (SW2admin# / SW2EnaAccess#)
! et BR-SW-3 (SW3admin# / SW3EnaAccess#)

! ============================================================
! NTP — HQ
! ============================================================

      ntp server 192.168.1.254

! ============================================================
! Vérification
! ============================================================

  show lldp neighbors
  show cdp neighbors
  show ntp status
  show clock detail
```
