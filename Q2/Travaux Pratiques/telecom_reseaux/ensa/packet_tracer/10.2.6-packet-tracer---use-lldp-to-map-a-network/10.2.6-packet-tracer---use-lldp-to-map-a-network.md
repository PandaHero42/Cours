## Objectifs

Cartographier le réseau Remote Branch Office (RBO) en combinant **SSH** et **LLDP**, en notant la configuration granulaire transmit/receive de LLDP.

---

## Contexte — LLDP vs CDP

| Caractéristique | CDP | LLDP |
|-----------------|-----|------|
| Standard | Propriétaire Cisco | Ouvert — IEEE 802.1AB |
| Compatibilité | Cisco uniquement | Multi-vendeur (Cisco, FortiGate, HP, etc.) |
| Couche | 2 (Data Link) | 2 (Data Link) |
| Contrôle TX/RX | Global ou par interface (on/off) | **Par interface, séparément** : `no lldp transmit` / `no lldp receive` |
| Commandes | `cdp run` / `show cdp neighbors` | `lldp run` / `show lldp neighbors` |
| Désactivé par défaut sur IOS | Non | **Oui** |

> **Avantage clé de LLDP :** Le contrôle **séparé** de la transmission et de la réception par interface permet des configurations de sécurité fines — ex. recevoir des informations d'un voisin sans lui en envoyer, ce qui est impossible avec CDP.

## Partie 1 : Accès SSH et configuration LLDP sur Edge

### a–b. SSH depuis Admin-PC vers Edge

```
PC> ssh -l admin01 192.168.1.1
Password: S3cre7P@55
Edge#
```

### c. Désactiver CDP, activer LLDP

Edge était configuré avec CDP — on migre vers LLDP :

```
Edge(config)# no cdp run
Edge(config)# lldp run
```

### d. Configuration LLDP granulaire sur G0/0 (vers S1)

```
Edge(config)# interface g0/0
Edge(config-if)# no lldp transmit
```

> Edge reçoit des messages LLDP de S1 (`lldp receive` reste actif par défaut) mais **n'en envoie pas** vers S1. Raison de sécurité : ne pas exposer les informations d'Edge (version IOS, plateforme) au switch S1 du réseau local, qui pourrait être accessible par des utilisateurs non-autorisés.

### e. Vérifier la réception LLDP depuis S1

```
Edge# show lldp neighbors
```

S1 apparaît dans la liste — Edge reçoit bien ses annonces LLDP.

### f. SSH vers S1 et vérification unidirectionnelle

```
Edge# ssh -l admin01 192.168.1.2
S1> show lldp neighbors
S1> exit
```

**Observation :** S1 ne voit **pas** Edge dans ses voisins LLDP — confirme que `no lldp transmit` sur Edge G0/0 empêche bien l'envoi vers S1. La relation est **unidirectionnelle** (Edge reçoit de S1, mais S1 ne reçoit pas d'Edge).

### g. Documenter les interfaces d'Edge

```
Edge# show ip interface brief
Edge# show interfaces
```

### h. SSH vers RBO-Edge

```
Edge# ssh -l RBOadmin 209.165.200.10
Password: S3cre7P@55
RBO-Edge#
```

**Réponse — information manquante complétée :** La connexion confirme que `209.165.200.10` est l'adresse de l'interface G0/0 de RBO-Edge. On peut maintenant compléter l'entrée correspondante de Edge (S0/0/0 ou G0/0 côté WAN) dans le tableau.

## Partie 2 : Découverte LLDP sur RBO-Edge

### a. Documenter les interfaces de RBO-Edge

```
RBO-Edge# show ip interface brief
RBO-Edge# show interfaces
```

### b–c. Activer LLDP et désactiver sur l'interface Internet

```
RBO-Edge# show lldp
% LLDP is not enabled
```

```
RBO-Edge(config)# lldp run
RBO-Edge(config)# interface g0/0
RBO-Edge(config-if)# no lldp transmit
RBO-Edge(config-if)# no lldp receive
```

> Ici, **les deux directions sont désactivées** sur G0/0 (interface WAN vers ISP). Comparé au lab CDP où `no cdp enable` coupait tout d'un coup, LLDP permet de les couper séparément :
> - `no lldp transmit` → ne pas envoyer d'infos vers l'ISP
> - `no lldp receive` → ne pas accepter d'annonces LLDP de l'ISP
> Les deux ensemble = isolation complète de l'interface externe.

### d. Découvrir les voisins

```
RBO-Edge# show lldp neighbors
```

**Réponse :** Un switch voisin est détecté (ex. `RBO-S1`), connecté sur une interface GigabitEthernet de RBO-Edge. **L'adresse IP n'est pas affichée** dans la sortie résumée.

### e. Déterminer l'IP du voisin via la table de routage

```
RBO-Edge# show ip route
```

En identifiant le réseau connecté sur l'interface où le voisin LLDP est visible, on peut déduire la plage d'adresses et donc l'IP probable du voisin (ex. premier hôte du réseau).

> **Note PT :** La version actuelle de Packet Tracer ne fournit pas l'adresse de management du voisin dans `show lldp neighbors detail` — d'où l'astuce de la table de routage pour déduire l'IP.

### f. Détails LLDP du voisin

```
RBO-Edge# show lldp neighbors detail
```

**Réponse — informations sensibles exposées :** En plus du nom et des interfaces, la sortie `detail` révèle :
- La **description système** (version IOS, modèle)
- Les **capacités** (switch, routeur, etc.)
- L'adresse de management (si disponible dans PT)

### g–j. Cartographie progressive — SSH vers chaque voisin

Répéter pour chaque nouvel équipement découvert :

```
RBO-Edge# ssh -l RBOadmin <IP_voisin>
<device># show lldp neighbors
<device># show lldp neighbors detail
```

**Étape j — switch sans LLDP activé :**

En atteignant l'adresse `192.168.4.133` via SSH, LLDP n'est pas actif :
```
% LLDP is not enabled
```

On l'active sans configuration supplémentaire (TX et RX on par défaut) :
```
<device>(config)# lldp run
```

Puis `show lldp neighbors` révèle ses voisins. Une fois LLDP actif sur ce dernier équipement, il peut être utile de **revenir sur les équipements précédemment visités** pour relancer `show lldp neighbors` — ils voient maintenant ce switch dans leurs voisins, ce qui complète le tableau bilatéralement.

## Tableau récapitulatif des commandes clés

| Commande | Contexte | Description |
|----------|----------|-------------|
| `lldp run` | Global config | Active LLDP globalement |
| `no lldp run` | Global config | Désactive LLDP globalement |
| `no lldp transmit` | Interface config | Désactive l'**envoi** LLDP sur cette interface |
| `no lldp receive` | Interface config | Désactive la **réception** LLDP sur cette interface |
| `show lldp` | Privileged EXEC | Vérifie si LLDP est activé |
| `show lldp neighbors` | Privileged EXEC | Liste les voisins LLDP (résumé — sans IP) |
| `show lldp neighbors detail` | Privileged EXEC | Détails complets (description, capacités, management IP) |
| `show ip route` | Privileged EXEC | Astuce : déduire l'IP du voisin depuis le réseau connecté |

---

## Mémo — LLDP vs CDP (comparatif complet)

```
CDP (Cisco Discovery Protocol) :
  cdp run / no cdp run          ← activation globale
  no cdp enable                 ← désactivation sur interface (tout ou rien)
  show cdp neighbors [detail]
  → Cisco uniquement

LLDP (Link Layer Discovery Protocol — IEEE 802.1AB) :
  lldp run / no lldp run        ← activation globale
  no lldp transmit              ← couper envoi sur interface
  no lldp receive               ← couper réception sur interface
  show lldp neighbors [detail]
  → Multi-vendeur (Cisco, FortiGate, HP Aruba, Juniper...)
  → Désactivé par défaut sur IOS (contrairement à CDP)

Sécurité — bonne pratique :
  Interface interne (LAN) : lldp run sur l'interface (TX+RX)
  Interface externe (WAN/ISP) : no lldp transmit + no lldp receive
  Pour recevoir sans envoyer (one-way) : no lldp transmit uniquement

Pertinence pour Agence 1 :
  → FortiGate supporte LLDP (pas CDP)
  → Pour cartographier les voisins entre RT-01 (Cisco) et FortiGate : utiliser LLDP
```

```
ssh -l admin01 192.168.1.1

      no cdp run

      lldp run
      interface g0/0
        no lldp transmit

  show lldp neighbors

! SSH vers S1 pour vérifier unidirectionnel
  ssh -l admin01 192.168.1.2
    show lldp neighbors
! (Edge n'apparaît pas chez S1 → confirmé)

  show ip interface brief
  show interfaces

  ssh -l RBOadmin 209.165.200.10

! ============================================================
! PARTIE 2 - Découverte LLDP sur RBO-Edge
! ============================================================

! --- Sur RBO-Edge ---
  show lldp

      lldp run
      interface g0/0
        no lldp transmit
        no lldp receive

  show lldp neighbors
  show lldp neighbors detail
  show ip route

! SSH vers chaque voisin découvert, puis répéter :
  show lldp neighbors
  show lldp neighbors detail

! Sur le switch sans LLDP (192.168.4.133) :
      lldp run

  show lldp neighbors
  show lldp neighbors detail

! Revenir sur les équipements précédents pour compléter le tableau
```
