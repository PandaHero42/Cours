## Objectifs

- **Partie 1 :** Planifier l'implémentation des ACLs

## Contexte

Les routeurs sont déjà configurés (adresses IP + EIGRP). Ce lab porte sur la **planification et l'implémentation d'ACLs standard** pour appliquer deux politiques de sécurité réseau distinctes, une sur R2, une sur R3.

---

## Partie 1 : Planifier l'implémentation des ACLs

### Étape 1 : Vérifier la connectivité initiale

Avant toute ACL, vérifier que tous les hôtes se pingent mutuellement :

```
ping 192.168.10.10
ping 192.168.11.10
ping 192.168.20.254
ping 192.168.30.10
```

Tous les pings doivent réussir — c'est la baseline.

### Étape 2 : Analyser les politiques et planifier le placement

#### Politique 1 — sur R2

> **"Le réseau 192.168.11.0/24 ne peut pas accéder au WebServer (192.168.20.0/24)."**

| Élément | Décision |
|---------|----------|
| Source à bloquer | `192.168.11.0/24` (PC2) |
| Destination protégée | `192.168.20.254` (WebServer) sur `192.168.20.0/24` |
| Routeur | R2 (gateway du WebServer) |
| Interface | G0/0 (lien vers le WebServer) |
| Direction | **outbound** — le trafic sort de R2 vers le WebServer |

> **Pourquoi outbound sur G0/0 de R2 ?** ACL standard = filtre sur source uniquement → doit être placée **le plus proche de la destination**. En outbound sur G0/0 de R2, on intercepte le trafic juste avant qu'il n'atteigne le WebServer, sans affecter les autres flux qui traversent R2.

#### Politique 2 — sur R3

> **"Le réseau 192.168.10.0/24 ne peut pas communiquer avec le réseau 192.168.30.0/24."**

| Élément | Décision |
|---------|----------|
| Source à bloquer | `192.168.10.0/24` (PC1) |
| Destination protégée | `192.168.30.0/24` (PC3) |
| Routeur | R3 (gateway de PC3) |
| Interface | G0/0 (lien vers PC3) |
| Direction | **outbound** — trafic sort de R3 vers PC3 |

## Partie 2 : Configurer, appliquer et vérifier les ACLs

### Étape 1 : ACL 1 sur R2

#### a–b. Créer l'ACL

```
R2(config)# access-list 1 deny 192.168.11.0 0.0.0.255
R2(config)# access-list 1 permit any
```

> **Séquence** : la ligne `deny` est évaluée en premier (séquence 10). Si la source est dans `192.168.11.0/24` → droppé. Le `permit any` (séquence 20) laisse passer tout le reste. Sans ce `permit any`, le `deny any` implicite bloquerait **tout** le trafic vers le WebServer.

#### c. Vérifier avant d'appliquer

```
R2# show access-lists
```
```
Standard IP access list 1
    10 deny   192.168.11.0 0.0.0.255
    20 permit any
```

> **Bonne pratique :** toujours vérifier le contenu d'une ACL **avant** de l'appliquer sur une interface active — une erreur dans l'ACL peut couper du trafic légitime.

#### d. Appliquer sur l'interface

```
R2(config)# interface GigabitEthernet0/0
R2(config-if)# ip access-group 1 out
```

### Étape 3 : Vérifier le placement et les résultats

#### Vérifier le placement de l'ACL

```
R2# show ip interface gigabitethernet 0/0
R3# show ip interface gigabitethernet 0/0
```

La ligne `Outgoing access list is 1` confirme l'application correcte.

#### Tableau de tests de vérification

| Source | Destination | Résultat attendu | Raison |
|--------|-------------|-----------------|--------|
| PC1 (`192.168.10.10`) | PC2 (`192.168.11.10`) | ✅ Succès | Trafic local R1, aucune ACL sur ce chemin |
| PC1 (`192.168.10.10`) | WebServer (`192.168.20.254`) | ✅ Succès | PC1 = `192.168.10.x` → non bloqué par l'ACL de R2 (qui bloque `192.168.11.x`) |
| PC2 (`192.168.11.10`) | WebServer (`192.168.20.254`) | ❌ Échec | PC2 = `192.168.11.x` → bloqué par ACL 1 de R2 (G0/0 out) |
| PC1 (`192.168.10.10`) | PC3 (`192.168.30.10`) | ❌ Échec | PC1 = `192.168.10.x` → bloqué par ACL 1 de R3 (G0/0 out) |
| PC2 (`192.168.11.10`) | PC3 (`192.168.30.10`) | ✅ Succès | PC2 = `192.168.11.x` → non bloqué par l'ACL de R3 (qui bloque `192.168.10.x`) |
| PC3 (`192.168.30.10`) | WebServer (`192.168.20.254`) | ✅ Succès | PC3 = `192.168.30.x` → non bloqué par aucune des deux ACLs |

#### Compteurs de hits après les tests

```
R2# show access-lists
Standard IP access list 1
    10 deny   192.168.11.0 0.0.0.255 (4 match(es))
    20 permit any                     (8 match(es))

R3# show access-lists
Standard IP access list 1
    10 deny   192.168.10.0 0.0.0.255 (4 match(es))
    20 permit any                     (8 match(es))
```

> **Les compteurs de hits** (`match(es)`) sont très utiles en diagnostic : ils confirment que l'ACL est bien évaluée et indiquent combien de paquets ont matché chaque ACE. Un compteur à 0 après du trafic suspect peut indiquer que l'ACL n'est pas appliquée au bon endroit ou dans la bonne direction.

## Tableau récapitulatif des commandes clés

| Commande | Contexte | Description |
|----------|----------|-------------|
| `access-list <1-99> {deny\|permit} <source> <wildcard>` | Global config | Crée une ACE dans une ACL standard numérotée |
| `access-list <num> permit any` | Global config | Autorise tout le reste (évite le deny implicite total) |
| `ip access-group <num> {in\|out}` | Interface config | Applique l'ACL sur l'interface |
| `show access-lists` | Privileged EXEC | Affiche les ACLs et leurs compteurs de hits |
| `show ip interface <if>` | Privileged EXEC | Vérifie quelle ACL est appliquée (in/out) |
| `show run \| include interface\|access` | Privileged EXEC | Vue rapide ACLs + interfaces |

## Mémo — Planification d'une ACL standard

```
Règle de placement : ACL standard → le plus PROCHE de la DESTINATION
  └─ Car filtre sur SOURCE uniquement → trop tôt = bloque trop large

Checklist de planification :
  1. Identifier la politique : qui est bloqué vers quoi ?
  2. Identifier la source → wildcard mask
  3. Identifier la destination → quel routeur la sert ? quelle interface ?
  4. Choisir la direction : in ou out
     └─ out : paquet déjà routé, sur le point de sortir vers la destination
     └─ in  : paquet entrant dans le routeur depuis le réseau source
  5. Toujours terminer par permit any (ou le deny implicite bloque tout)
  6. show access-lists AVANT d'appliquer
  7. Vérifier avec show ip interface après application
  8. Tester avec des pings depuis les hôtes concernés
  9. Contrôler les compteurs de hits avec show access-lists
```

```
! ============================================================

ping 192.168.11.10

      interface GigabitEthernet0/0

      access-list 1 deny 192.168.10.0 0.0.0.255
      access-list 1 permit any

  show access-lists

      interface GigabitEthernet0/0
        ip access-group 1 out

! ============================================================
! Vérification (sur R2 et R3)
! ============================================================

  show ip interface gigabitethernet 0/0
  show access-lists

! Tests de connectivité (depuis les PCs) :
! PC1 → PC2       : succès
! PC1 → WebServer : succès
! PC2 → WebServer : ÉCHEC  (bloqué ACL R2)
! PC1 → PC3       : ÉCHEC  (bloqué ACL R3)
! PC2 → PC3       : succès
! PC3 → WebServer : succès
```
