# Packet Tracer – Point-to-Point Single-Area OSPFv2 Configuration

> **Objectif** : Configurer OSPF single-area sur trois routeurs en utilisant trois méthodes différentes — network statements avec wildcard masks, quad-zero masks, et configuration directe sur les interfaces. Configurer les interfaces passives et vérifier OSPF.

---

## Topologie

| Device | Interface | Adresse IP    | Masque |
|--------|-----------|---------------|--------|
| R1     | G0/0/0    | 192.168.10.1  | /24    |
| R1     | S0/1/0    | 10.1.1.1      | /30    |
| R1     | S0/1/1    | 10.1.1.5      | /30    |
| R2     | G0/0/0    | 192.168.20.1  | /24    |
| R2     | S0/1/0    | 10.1.1.2      | /30    |

| R3     | G0/0/0    | 192.168.30.1  | /24    |
| R3     | S0/1/0    | 10.1.1.10     | /30    |
| R3     | S0/1/1    | 10.1.1.6      | /30    |
| PC1    | NIC       | 192.168.10.10 | /24    |
| PC2    | NIC       | 192.168.20.10 | /24    |
| PC3    | NIC       | 192.168.30.10 | /24    |

### Liens série (réseaux /30)

| Lien   | Réseau        | R1 côté  | R2/R3 côté |
|--------|---------------|----------|------------|
| R1–R2  | 10.1.1.0/30   | 10.1.1.1 | 10.1.1.2   |
| R1–R3  | 10.1.1.4/30   | 10.1.1.5 | 10.1.1.6   |
| R2–R3  | 10.1.1.8/30   | 10.1.1.9 | 10.1.1.10  |

### Concepts OSPF — wildcards masks

> 💡 **Wildcard mask** = inverse du masque de sous-réseau = `255.255.255.255 - masque`
> - `/24` → masque `255.255.255.0` → wildcard `0.0.0.255`
> - `/30` → masque `255.255.255.252` → wildcard `0.0.0.3`
> - **Quad-zero** `0.0.0.0` = correspond uniquement à l'adresse exacte

## Partie 1 : Configurer les Router IDs

Le Router ID identifie chaque routeur de façon unique dans OSPF.  
Sans `router-id` explicite, IOS choisit automatiquement la plus haute adresse loopback ou interface.  
Le process ID (`10` ici) est local au routeur — deux routeurs peuvent avoir des process IDs différents et toujours établir une adjacence.

**Sur R1 :**

```
R1# configure terminal

R1(config)# router ospf 10
R1(config-router)# router-id 1.1.1.1
R1(config-router)# exit
```

**Sur R2 :**

```
R2# configure terminal

R2(config)# router ospf 10
R2(config-router)# router-id 2.2.2.2
R2(config-router)# exit
```

**Sur R3 :**

```
R3# configure terminal

R3(config)# router ospf 10
R3(config-router)# router-id 3.3.3.3
R3(config-router)# exit
```

## Partie 2 : Configurer les réseaux OSPF

### Méthode 1 — R1 : network statements + wildcard masks

**Réponses aux questions :**
- **Combien de statements pour R1 ?** → **3** (G0/0/0, S0/1/0, S0/1/1)
- **Wildcard /24** → `255.255.255.255 - 255.255.255.0 = 0.0.0.255`
- **Wildcard /30** → `255.255.255.255 - 255.255.255.252 = 0.0.0.3`

La commande `network` indique à OSPF quelles interfaces activer. Le wildcard `0.0.0.255` match tout le réseau /24, `0.0.0.3` match le réseau /30.

```
R1(config)# router ospf 10

R1(config-router)# network 192.168.10.0 0.0.0.255 area 0
! → active OSPF sur G0/0/0 (réseau LAN /24)

R1(config-router)# network 10.1.1.0 0.0.0.3 area 0
! → active OSPF sur S0/1/0 (lien R1-R2 /30)

R1(config-router)# network 10.1.1.4 0.0.0.3 area 0
! → active OSPF sur S0/1/1 (lien R1-R3 /30)

R1(config-router)# exit
```

Vérifier :

```
R1# show running-config | section ospf
```

### Méthode 2 — R2 : quad-zero masks (adresses IP exactes)

Le wildcard `0.0.0.0` correspond **exactement** à l'adresse spécifiée — OSPF active l'interface dont l'adresse correspond exactement. C'est équivalent à spécifier l'adresse de l'interface.

```
R2(config)# router ospf 10

R2(config-router)# network 192.168.20.1 0.0.0.0 area 0
! → active OSPF sur G0/0/0 (adresse exacte)

R2(config-router)# network 10.1.1.2 0.0.0.0 area 0
! → active OSPF sur S0/1/0

R2(config-router)# network 10.1.1.9 0.0.0.0 area 0
! → active OSPF sur S0/1/1

R2(config-router)# exit
```

### Méthode 3 — R3 : configuration directe sur les interfaces

**Réponse — quelles interfaces de R3 configurer avec OSPF ?**  
**Toutes les 3** : G0/0/0 (LAN), S0/1/0 (lien R2-R3), S0/1/1 (lien R1-R3).

La commande `ip ospf` s'applique directement sur l'interface — pas besoin de `network` dans le processus OSPF. C'est la méthode la plus directe et la plus lisible.

```
R3(config)# interface g0/0/0
R3(config-if)# ip ospf 10 area 0
R3(config-if)# exit

R3(config)# interface s0/1/0
R3(config-if)# ip ospf 10 area 0
R3(config-if)# exit

R3(config)# interface s0/1/1
R3(config-if)# ip ospf 10 area 0
R3(config-if)# exit
```

---

## Partie 3 : Configurer les interfaces passives

**Réponse — quelles sont les interfaces LAN de R1, R2 et R3 ?**  
- R1 : **G0/0/0**
- R2 : **G0/0/0**
- R3 : **G0/0/0**

`passive-interface` empêche l'envoi de Hello OSPF sur une interface — les PC n'ont pas besoin de recevoir ces paquets. OSPF continue de **annoncer** le réseau LAN, mais n'envoie pas de Hellos dessus.

**Sur R1, R2, R3 :**

```
R1(config)# router ospf 10
R1(config-router)# passive-interface g0/0/0
R1(config-router)# exit
```

```
R2(config)# router ospf 10
R2(config-router)# passive-interface g0/0/0
R2(config-router)# exit
```

```
R3(config)# router ospf 10
R3(config-router)# passive-interface g0/0/0
R3(config-router)# exit
```

---

## Partie 4 : Vérifier la configuration OSPF

```
R1# show ip ospf neighbor
! → vérifier adjacences avec R2 et R3 (State = FULL)

R1# show ip ospf interface
! → vérifier interfaces actives, état passive sur G0/0/0

R1# show ip route ospf
! → vérifier routes O (OSPF) vers les LANs distants

R1# show ip protocols
! → résumé OSPF : process ID, router ID, réseaux, interfaces passives
```

## Résumé des commandes clés

| Commande | Rôle |
|----------|------|
| `router ospf <process-id>` | Démarre le processus OSPF |
| `router-id <x.x.x.x>` | Définit le Router ID explicitement |
| `network <réseau> <wildcard> area <n>` | Active OSPF sur les interfaces correspondantes |
| `ip ospf <process-id> area <n>` | Active OSPF directement sur une interface |
| `passive-interface <interface>` | Bloque les Hellos OSPF sur une interface (LAN) |
| `show ip ospf neighbor` | Affiche les voisins OSPF et leur état |
| `show ip ospf interface` | Détail des interfaces OSPF |
| `show ip route ospf` | Affiche uniquement les routes apprises via OSPF |
| `show ip protocols` | Résumé des protocoles de routage actifs |

---

## Comparaison des 3 méthodes de configuration OSPF

| Méthode | Commande | Utilisation sur |
|---------|----------|----------------|
| Network + wildcard | `network 192.168.10.0 0.0.0.255 area 0` | R1 |
| Network + quad-zero | `network 192.168.20.1 0.0.0.0 area 0` | R2 |
| Interface directe | `ip ospf 10 area 0` (sur l'interface) | R3 |

> 💡 Les trois méthodes produisent le même résultat — OSPF devient actif sur les interfaces concernées et les réseaux sont annoncés aux voisins.

## Script complet (toutes les commandes dans l'ordre)

```
! ══════════════════════════════════════════════
! ─── PARTIE 1 : Router IDs ────────────────────
! ══════════════════════════════════════════════

! ─── Sur R1 ───────────────────────────────────

    enable

        configure terminal

            ! ─── Global Config ───────────────
            router ospf 10
                ! ─── OSPF Config ─────────────
                router-id 1.1.1.1
                exit

            end


! ─── Sur R2 ───────────────────────────────────

    enable

        configure terminal

            ! ─── Global Config ───────────────
            router ospf 10
                ! ─── OSPF Config ─────────────
                router-id 2.2.2.2
                exit

            end


! ─── Sur R3 ───────────────────────────────────

    enable

        configure terminal

            ! ─── Global Config ───────────────
            router ospf 10
                ! ─── OSPF Config ─────────────
                router-id 3.3.3.3
                exit

            end


! ══════════════════════════════════════════════
! ─── PARTIE 2 : Réseaux OSPF ──────────────────
! ══════════════════════════════════════════════

! ─── R1 : méthode network + wildcard ──────────

    enable

        configure terminal

            ! ─── Global Config ───────────────
            router ospf 10
                ! ─── OSPF Config ─────────────
                network 192.168.10.0 0.0.0.255 area 0
                network 10.1.1.0 0.0.0.3 area 0
                network 10.1.1.4 0.0.0.3 area 0
                exit

            end

        show running-config | section ospf


! ─── R2 : méthode quad-zero ───────────────────

    enable

        configure terminal

            ! ─── Global Config ───────────────
            router ospf 10
                ! ─── OSPF Config ─────────────
                network 192.168.20.1 0.0.0.0 area 0
                network 10.1.1.2 0.0.0.0 area 0
                network 10.1.1.9 0.0.0.0 area 0
                exit

            end


! ─── R3 : méthode interface directe ───────────

    enable

        configure terminal

            ! ─── Global Config ───────────────
            interface g0/0/0
                ! ─── Interface Config ────────
                ip ospf 10 area 0
                exit

            interface s0/1/0
                ! ─── Interface Config ────────
                ip ospf 10 area 0
                exit

            interface s0/1/1
                ! ─── Interface Config ────────
                ip ospf 10 area 0
                exit

            end


! ══════════════════════════════════════════════
! ─── PARTIE 3 : Interfaces passives ───────────
! (Sur R1, R2 et R3 — répéter)
! ══════════════════════════════════════════════

    enable

        configure terminal

            ! ─── Global Config ───────────────
            router ospf 10
                ! ─── OSPF Config ─────────────
                passive-interface g0/0/0
                exit

            end


! ══════════════════════════════════════════════
! ─── PARTIE 4 : Vérification ──────────────────
! ══════════════════════════════════════════════

    enable

        show ip ospf neighbor
        ! → R1 doit voir R2 et R3 en FULL

        show ip ospf interface
        ! → G0/0/0 = passive, S0/1/x = actif

        show ip route ospf
        ! → routes O vers les 3 LANs

        show ip protocols
        ! → process ID, router ID, réseaux, passives
```
