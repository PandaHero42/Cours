## Objectifs

Lab de **dépannage** — identifier et corriger les erreurs de configuration sur un réseau d'entreprise utilisant : port security, VLANs, EtherChannel, DHCP, OSPF (IPv4 + IPv6), NAT, et coûts OSPF.

## Inventaire des problèmes et corrections

### PROBLÈME 1 — Port security non configuré sur S1 F0/3

**Symptôme :** `show port-security` montre que F0/3 n'a pas de port security configuré.

**Correction :**
```
S1(config)# interface f0/3
S1(config-if)# switchport port-security
S1(config-if)# switchport port-security mac-address sticky
```

> `switchport port-security mac-address sticky` : le switch apprend dynamiquement la MAC de PC1 et la "colle" (sticky) dans la configuration — elle devient une entrée sécurisée permanente. Toute autre MAC sur ce port déclenchera une violation qui désactive l'interface (shutdown = mode par défaut).

---

### PROBLÈME 2 — Port G0/1 de S1 pas dans VLAN 10

**Symptôme :** PC1 ne reçoit pas d'adresse DHCP car le port de S1 connecté à R1 n'est pas dans VLAN 10 → R1 ne voit pas les requêtes DHCP de PC1.

**Vérification :**
```
S1# show vlan brief
```

**Correction :**
```
S1(config)# interface G0/1
S1(config-if)# switchport access vlan 10
S1(config-if)# spanning-tree portfast
```

**Test :**
```
PC1> ipconfig /renew
PC1> ping 192.168.20.254
```

> `spanning-tree portfast` sur G0/1 accélère la mise en service du port (bypass des états STP listening/learning) — recommandé sur les ports d'accès vers des équipements non-switches.

---

### PROBLÈME 3 — EtherChannel S3 mal configuré

**Symptôme :** `show etherchannel summary` sur S2 montre Po1 et Po2 actifs, mais S3 ne contribue pas correctement à Po1.

**Vérification :**
```
S2# show etherchannel summary
S3# show etherchannel summary
```

**Correction sur S3 :**
```
S3(config)# interface range f0/1-2
S3(config-if-range)# channel-group 1 mode on
```

> `mode on` = EtherChannel statique sans protocole de négociation (ni PAgP ni LACP). Les deux extrémités doivent être en `mode on` pour que le channel se forme sans négociation.

**Vérification :**
```
S3# show etherchannel summary
```
→ Po1 doit être `SU` (SU = Switch, Up) avec Fa0/1 et Fa0/2 en état `P` (in Port-channel).

---

### PROBLÈME 4 — Native VLAN incorrecte sur S2

**Symptôme :** `show interfaces trunk` sur S2 montre un native VLAN différent de 99 sur G0/1 → mismatch de native VLAN avec les autres switches → paquets untagged abandonnés ou mauvaise VLAN.

**Correction :**
```
S2(config)# interface g0/1
S2(config-if)# switchport trunk native vlan 99
```

---

### PROBLÈME 5 — S2 n'est pas root bridge pour tous les VLANs

**Symptôme :** `show spanning-tree summary totals` sur S2 → "Root bridge for:" est vide — S2 n'est root pour aucun VLAN.

**Correction :**
```
S2(config)# spanning-tree vlan 1-1005 root primary
```

**Vérification :**
```
S2# show spanning-tree summary totals
Switch is in pvst mode
Root bridge for: default V30 V40 V50 Native
```

---

### PROBLÈME 6 — DHCP : default-router incorrect dans les pools LAN40 et LAN50

**Symptôme :** PC2 (VLAN 40) et PC3 (VLAN 50) reçoivent une adresse DHCP mais avec la mauvaise gateway (`192.168.30.1` au lieu de `.40.1` et `.50.1`).

**Vérification :**
```
R3# show run | begin dhcp
```

Sortie révèle :
```
ip dhcp pool LAN40
 network 192.168.40.0 255.255.255.0
 default-router 192.168.30.1   ← ERREUR (devrait être 192.168.40.1)

ip dhcp pool LAN50
 network 192.168.50.0 255.255.255.0
 default-router 192.168.30.1   ← ERREUR (devrait être 192.168.50.1)
```

**Correction :**
```
R3(config)# ip dhcp pool LAN40
R3(dhcp-config)# default-router 192.168.40.1

R3(config)# ip dhcp pool LAN50
R3(dhcp-config)# default-router 192.168.50.1
```

**Renouveler les adresses DHCP sur PC2, PC3, PC4 :**
```
ipconfig /renew
```

### PROBLÈME 7 — OSPF : route par défaut non propagée (IPv4 et IPv6)

**Symptôme IPv4 :** R1 et R3 n'ont pas de route par défaut `O*E2 0.0.0.0/0` dans leur table de routage → pas d'accès à Internet.

**Correction sur R2 :**
```
R2(config)# router ospf 1
R2(config-router)# default-information originate
```

**Symptôme IPv6 :** R3 ne peut pas pinger Outside Host en IPv6.

**Correction sur R2 :**
```
R2(config)# ipv6 router ospf 1
R2(config-rtr)# default-information originate
```

**Vérification :**
```
R1# show ip route ospf
R3# show ip route ospf
→ O*E2 0.0.0.0/0 présent sur R1 et R3
```

---

### PROBLÈME 8 — OSPF : coût mal configuré sur R1 G0/0/0 et R3 G0/1/0

**Symptôme :** Le trafic de R1 vers TFTP Server emprunte le lien **série** (S0/1/0 → R2) au lieu du lien **fibre** (G0/0/0 → R3 → R2). Le coût de la fibre a été importé de l'ancienne configuration série et est identique au coût de la liaison série.

**Diagnostic :**
```
R1# traceroute 192.168.20.254
→ 1 hop: 10.1.1.2 (interface série R2) ← trafic sur le lien série
```

Les deux interfaces ont un coût OSPF identique de **648** (coût d'une liaison série T1) configuré manuellement, alors que la fibre GigabitEthernet devrait avoir un coût naturellement plus bas.

**Correction :**
```
R1(config)# interface g0/0/0
R1(config-if)# no ip ospf cost 648

R3(config)# interface g0/1/0
R3(config-if)# no ip ospf cost 648
```

> En retirant le coût manuel, IOS recalcule le coût naturel du lien GigabitEthernet (~1) vs Serial (~647) → OSPF préfère maintenant le chemin fibre.

**Vérification :**
```
R1# traceroute 192.168.20.254
→ 1 hop: 10.3.3.2 (interface fibre R3) ← correct
```

**Test de bascule sur le lien de secours :**
```
R3(config)# interface g0/2/0
R3(config-if)# shutdown
```
→ Pings vers TFTP Server et Outside Host doivent toujours réussir via le lien série de secours.

```
R3(config-if)# no shutdown
```

---

### PROBLÈME 9 — NAT : S0/0/0 de R2 non configuré en inside

**Symptôme :** Les pings depuis R1 vers Outside Host échouent malgré la route par défaut. `show ip nat translations` vide après ping de R1.

**Diagnostic :**
```
R2# show ip nat statistics
Outside Interfaces: GigabitEthernet0/0
Inside Interfaces: GigabitEthernet0/1, GigabitEthernet0/1/0
→ S0/0/0 manquant dans les inside interfaces !
```

Le trafic de R1 arrive sur R2 via S0/0/0, mais cette interface n'est pas marquée `ip nat inside` → R2 ne traduit pas le trafic provenant de R1.

**Correction :**
```
R2(config)# interface s0/0/0
R2(config-if)# ip nat inside
```

**Test :**
```
R1# ping <Outside Host IP>
→ Succès
```

        spanning-tree portfast

      interface range f0/1-2

      interface g0/1
        switchport trunk native vlan 99

! BUG 5 - STP S2
      spanning-tree vlan 1-1005 root primary

! ============================================================
! PARTIE 2 - DHCP
! ============================================================

! BUG 6 - Default-router incorrect sur R3
      ip dhcp pool LAN40
        default-router 192.168.40.1
      ip dhcp pool LAN50
        default-router 192.168.50.1

! ============================================================
! PARTIE 3 - Routing
! ============================================================

! BUG 7 - Route par défaut OSPF non propagée sur R2
      router ospf 1
        default-information originate
      ipv6 router ospf 1
        default-information originate

! ============================================================
! PARTIE 4 - WAN
! ============================================================

! BUG 8 - Coût OSPF erroné sur liens fibre

      interface g0/0/0
        no ip ospf cost 648

      interface g0/1/0
        no ip ospf cost 648

      interface s0/0/0
        ip nat inside
