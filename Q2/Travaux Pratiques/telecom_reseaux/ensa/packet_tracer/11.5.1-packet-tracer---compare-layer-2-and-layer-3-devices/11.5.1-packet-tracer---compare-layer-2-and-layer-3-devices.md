# Packet Tracer – Compare Layer 2 and Layer 3 Devices

## Objectifs

- **Partie 1 :** Comparer un switch L2 (Cisco 2960) et un switch L3 (Cisco 3650)
- **Partie 2 :** Comparer un switch L3 (3650) et un routeur (ISR 4321)

> ℹ️ Lab d'**observation et de compréhension conceptuelle** — peu de configuration, beaucoup de questions. L'objectif est de maîtriser les différences fondamentales entre les équipements réseau couches 2 et 3.

## Partie 1 : Switch L2 (2960 / ASw-1) vs Switch L3 (3650 / D1)

### a. Aspects physiques

**Réponses aux questions :**

**Nombre de switchports :**
→ Le **WS-C3650-24PS-L** (D1) dispose de **24 ports GigabitEthernet** + 4 ports SFP uplink. Le **WS-C2960** (ASw-1) dispose de **24 ports FastEthernet** + 2 ports GigabitEthernet uplink (modèle typique 2960-24).

**FastEthernet vs GigabitEthernet :**
→ Le 2960 dispose principalement de ports **FastEthernet (100 Mbps)** avec des uplinks GigabitEthernet. Le 3650 dispose entièrement de ports **GigabitEthernet (1000 Mbps)** — meilleure bande passante pour un switch de distribution/core.

**Vitesses de transmission :**
→ FastEthernet : 10/100 Mbps. GigabitEthernet : 10/100/1000 Mbps (auto-négociation).

**Design modulaire :**
→ **Non** pour le 2960 (fixe). Le 3650 dispose de slots SFP pour les uplinks, mais son châssis reste fixe (non modulaire comme un Catalyst 6500 par exemple).

### b. Différences fondamentales L2 vs L3

**Différence entre switch L2 et switch L3 :**

| Caractéristique | Switch L2 (2960) | Switch L3 (3650) |
|-----------------|------------------|------------------|
| Décisions de transfert | Basées sur les **adresses MAC** (couche 2) | Basées sur MAC **ET** adresses IP (couches 2 et 3) |
| Routage inter-VLAN | Impossible (nécessite un routeur externe) | Possible nativement (`ip routing`) |
| Table | Table CAM (MAC addresses) | Table CAM + Table de routage |
| Interfaces L3 | SVI (interface VLAN) uniquement | SVI + ports physiques routed (`no switchport`) |
| Protocoles de routage | Non supportés | OSPF, EIGRP, etc. supportés |
| Commande IP | `ip address` sur SVI uniquement | `ip address` sur SVI ou interface physique routed |

**Différence entre interface physique et interface VLAN (SVI) :**
→ Une **interface physique** est un port matériel (ex. G0/1) — elle transmet les trames physiquement. Une **interface VLAN (SVI — Switch Virtual Interface)** est une interface logicielle associée à un VLAN (ex. `interface vlan 10`). Elle n'a pas d'existence physique propre mais représente le VLAN entier au niveau L3. C'est via la SVI qu'on assigne une IP à un switch L2 pour la gestion, ou qu'on fait du routage inter-VLAN sur un switch L3.

**Couches d'opération :**
→ Le **2960** opère à la **couche 2** uniquement. Le **3650** opère aux **couches 2 et 3**.

**Différences observées dans `show run` :**
→ Sur D1 (3650) : présence de `ip routing` (active le routage), possibilité de `no switchport` sur les ports physiques, configuration de protocoles de routage (OSPF, EIGRP). Sur ASw-1 (2960) : absence de `ip routing`, pas de `no switchport`, uniquement des SVIs pour la gestion.

**`show ip route` — pourquoi fonctionne sur D1 mais pas ASw-1 :**
→ `show ip route` affiche la **table de routage**. Un switch L2 (ASw-1) **n'a pas de table de routage** — il ne prend pas de décisions L3. La commande est donc non reconnue ou retourne une erreur. D1 (switch L3 avec `ip routing` activé) maintient une table de routage et peut afficher ses routes.

## Partie 2 : Switch L3 (D1/D2) vs Routeur (R1/R2/R3)

### a. Comparaison physique et fonctionnelle

**Similitudes et différences physiques (D1 vs R1) :**

| Caractéristique | Switch L3 (3650 / D1) | Routeur (ISR 4321 / R1) |
|-----------------|----------------------|------------------------|
| Ports LAN | Nombreux (24 GE) — conçu pour connecter des hôtes | Peu de ports LAN (2–4 GE) |
| Ports WAN | Aucun (pas de ports série/WAN) | Ports WAN série/DSL/VDSL, modules SFP |
| PoE | Disponible (3650-PS = Power over Ethernet) | Non |
| Design | Optimisé pour la commutation haute densité | Optimisé pour le routage et les connexions WAN |
| Coût | Moins cher pour grand nb de ports | Plus cher, mais fonctionnalités WAN avancées |

**Différences dans `show run` :**
→ Le routeur R1 n'a pas de configuration de VLANs ni de commutation. Le switch D1 n'a pas de configuration d'interfaces série ou WAN. R1 peut avoir des sous-interfaces (802.1Q), des tunnels VPN, des interfaces WAN. D1 a des configurations de switchports, VLANs, et spanning-tree.

**Commande pour assigner une IP sur une interface physique de D1 :**
→ `no switchport` dans le mode de configuration d'interface — transforme le port de switchport (couche 2) en interface routed (couche 3), permettant d'y assigner une adresse IP comme sur un routeur.

**`show ip route` sur D1 vs R1 :**
→ Les deux affichent une table de routage. Si seuls des réseaux directement connectés sont présents, les tables sont similaires. La différence : R1 peut avoir des routes apprises via des interfaces WAN série, alors que D1 a des routes associées à des SVIs de VLANs.

**Analyse D2 vs R2 (avec protocole de routage) :**
→ La configuration de D2 et R2 inclut un **protocole de routage** (ex. OSPF ou EIGRP). D2 a des routes apprises dynamiquement depuis R2 et vice-versa. Ce que D2 a en plus de D1 : la configuration du protocole de routage (`router ospf 1` ou `router eigrp`). Ce que R2 a en plus de R1 : idem.

**Quel réseau D2 a appris depuis R2 ?**
→ D2 apprend les réseaux connectés à R2 (et au-delà) via le protocole de routage. Visible dans `show ip route` par le code `O` (OSPF) ou `D` (EIGRP) suivi de l'adresse réseau de R2.

### b. Tests de connectivité

**Pings entre PCs sur réseaux différents :**

- PC1 → PC2 : succès
- PC3 → PC4 : succès
- PC5 → PC6 et PC7 : succès

**Quel équipement permet la communication inter-réseaux ?**
→ Le **switch L3** (3650 avec `ip routing` activé). Dans les topologies utilisant D1/D2, le routage inter-VLAN est assuré par le switch lui-même sans routeur externe.

**Pourquoi peut-on pinger entre réseaux sans routeur ?**
→ Parce que le switch L3 (3650) avec `ip routing` activé **fait du routage** — il prend des décisions de transfert basées sur les adresses IP en plus des adresses MAC. Il joue le rôle d'un routeur pour les réseaux directement connectés à ses interfaces/SVIs, éliminant le besoin d'un routeur externe pour le routage inter-VLAN.

**Bonus — Comment un switch L2 peut-il avoir une adresse IP s'il opère à la couche 2 ?**

→ Un switch L2 est un équipement de couche 2 pour le **transfert des trames** — il ne route pas. Cependant, le switch lui-même a un processeur et un système d'exploitation (IOS) qui doivent être accessibles pour la gestion à distance (SSH, Telnet, SNMP). La **SVI (Switch Virtual Interface)** `interface vlan X` est une interface logicielle L3 **du processeur du switch**, pas du plan de transfert. Elle permet au CPU du switch d'envoyer et recevoir des paquets IP pour la gestion, sans que le switch route du trafic entre réseaux. En d'autres termes : le **plan de transfert** reste L2, mais le **plan de gestion** opère à L3 via la SVI.

## Synthèse — Tableau comparatif complet

| Critère | Switch L2 (2960) | Switch L3 (3650) | Routeur (ISR 4321) |
|---------|------------------|------------------|---------------------|
| Couches | 2 | 2 et 3 | 3 (et 4+) |
| Décisions de transfert | MAC (table CAM) | MAC + IP | IP (table de routage) |
| Ports LAN | Nombreux (24+ FE/GE) | Nombreux (24+ GE) | Peu (2–4 GE) |
| Ports WAN | Non | Non | Oui (série, DSL, etc.) |
| Routage | Non (SVI gestion uniquement) | Oui (`ip routing`) | Oui (natif) |
| Routage inter-VLAN | Non (nécessite routeur) | Oui (nativement) | Oui (sous-interfaces) |
| Protocoles routage | Non | Oui (OSPF, EIGRP...) | Oui (OSPF, EIGRP...) |
| `ip routing` | Non disponible | Requis | Toujours actif |
| `no switchport` | Non disponible | Disponible | N/A (pas de switchport) |
| SVI | Oui (gestion uniquement) | Oui (routage + gestion) | N/A |

## Mémo — Commandes clés L3 switch

```
Activer le routage sur switch L3 :
  ip routing

Convertir un port switchport en port routé (L3) :
  interface <GigabitEthernet>
    no switchport
    ip address <ip> <masque>

Créer une interface VLAN (SVI) pour routage inter-VLAN :
  interface vlan <id>
    ip address <ip> <masque>
    no shutdown

Vérification :
  show ip route          → table de routage (requiert ip routing)
  show interfaces        → état des interfaces (dont SVIs)
  show vlan brief        → VLANs configurés et ports associés
```
