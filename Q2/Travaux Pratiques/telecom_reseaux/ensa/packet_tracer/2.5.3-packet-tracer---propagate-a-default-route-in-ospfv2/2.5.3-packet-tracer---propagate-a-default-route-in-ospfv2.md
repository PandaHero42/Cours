## Objectifs

- **Partie 1 :** Configurer et propager une route par défaut via OSPF
- **Partie 2 :** Vérifier la connectivité vers Internet

---

## Contexte

OSPF est déjà configuré entre R1, R2 et R3 pour les réseaux internes. Cependant, aucun routeur ne sait comment atteindre Internet (`64.100.1.2`) : il manque une **route par défaut**. R2 est le seul routeur connecté à Internet (via S0/1/0). Ce lab consiste à configurer cette route par défaut sur R2 et à la **propager automatiquement** via OSPF vers R1 et R3, évitant de devoir la configurer manuellement sur chaque routeur.

---

## Partie 1 : Propager une route par défaut

### Étape 1 : Tester la connectivité initiale vers le Web Server

Depuis PC1, PC2 et PC3 :

```
ping 64.100.1.2
```

**Réponses aux questions :**

- **Les pings ont-ils réussi ?** → Non, tous échouent.
- **Quel message et quel équipement ?** → Le message `Destination host unreachable` est émis par la **passerelle de chaque PC** (R1 pour PC1, R2 pour PC2, R3 pour PC3). Le routeur répond lui-même à la place de la destination car il n'a aucune route vers `64.100.1.2`.

**Vérification dans les tables de routage :**

```
R1# show ip route
R2# show ip route
R3# show ip route
```

**Réponse à la question :**

L'entrée absente est une route vers `0.0.0.0/0` (route par défaut). Sur R1 et R3, il n'y a aucune ligne `Gateway of last resort` — ce qui signifie que tout paquet vers une destination inconnue (comme Internet) est **droppé**. Sur R2, même si l'interface S0/1/0 est connectée à Internet, aucune route par défaut n'a encore été configurée.

### Étape 2 : Configurer la route par défaut sur R2

R2 est le **routeur ASBR (Autonomous System Boundary Router)** — le point de sortie du domaine OSPF vers Internet. On lui configure une route statique par défaut pointant vers son interface série côté Internet :

```
R2(config)# ip route 0.0.0.0 0.0.0.0 Serial0/1/0
```

> **Pourquoi `0.0.0.0 0.0.0.0` ?** C'est la route par défaut — elle correspond à **toute destination** qui n'est pas plus spécifiquement connue dans la table de routage. C'est le "dernier recours" : si aucune autre route ne matche, le paquet est envoyé par cette interface.

> **Note :** IOS émet un avertissement car l'utilisation d'une interface de sortie (sans next-hop IP) sur un lien non point-à-point peut poser des problèmes de résolution ARP. On peut l'ignorer ici car S0/1/0 est bien un lien point-à-point.

À ce stade, R2 peut atteindre Internet, mais R1 et R3 ne connaissent toujours pas cette route.

### Étape 3 : Propager la route par défaut via OSPF

La commande `default-information originate` ordonne à OSPF de **redistribuer la route par défaut** dans ses mises à jour LSA, pour que tous les routeurs OSPF du domaine la reçoivent automatiquement :

```
R2(config)# router ospf 1
R2(config-router)# default-information originate
```

> **Pourquoi cette commande est-elle nécessaire ?** Par défaut, OSPF ne propage **jamais** la route `0.0.0.0/0` automatiquement, même si elle existe localement. `default-information originate` force R2 à générer un LSA de type externe (Type 5) contenant cette route, que tous les autres routeurs OSPF vont installer dans leur table.

### Étape 4 : Vérifier la propagation sur R1 et R3

```
R1# show ip route
```
```
Gateway of last resort is 172.16.3.2 to network 0.0.0.0
...
O*E2  0.0.0.0/0 [110/1] via 172.16.3.2, 00:00:08, Serial0/0/0
```

```
R3# show ip route
```
```
Gateway of last resort is 192.168.10.9 to network 0.0.0.0
...
O*E2  0.0.0.0/0 [110/1] via 192.168.10.9, 00:08:15, Serial0/0/1
```

**Lecture de l'entrée `O*E2 0.0.0.0/0` :**

| Champ | Valeur | Signification |
|-------|--------|---------------|
| `O` | OSPF | Route apprise via OSPF |
| `*` | Candidat route par défaut | Cette route est la "gateway of last resort" |
| `E2` | External Type 2 | Route externe redistribuée, coût fixe (non incrémenté par les routeurs internes) |
| `[110/1]` | AD/Coût | Distance administrative OSPF = 110, coût = 1 |
| `via 172.16.3.2` | Next-hop | Paquet envoyé vers R2 |

> **E2 vs E1 :** En External Type 2 (défaut), le coût de la route externe reste **constant** quel que soit le nombre de sauts internes parcourus. En E1, le coût interne est **additionné** au coût externe. Pour une route par défaut unique, E2 est parfaitement adapté.

## Partie 2 : Vérifier la connectivité

Depuis chaque PC :

```
ping 64.100.1.2
```

Les pings doivent maintenant aboutir. R1 et R3 savent désormais envoyer le trafic inconnu vers R2, qui le route vers Internet.

## Tableau récapitulatif des commandes clés

| Commande | Contexte | Description |
|----------|----------|-------------|
| `ip route 0.0.0.0 0.0.0.0 <interface/next-hop>` | Global config | Configure la route par défaut statique |
| `default-information originate` | Router OSPF config | Propage la route par défaut dans les mises à jour OSPF |
| `show ip route` | Privileged EXEC | Affiche la table de routage (chercher `O*E2 0.0.0.0/0`) |

## Mémo — Route par défaut OSPF

```
Problème : R1 et R3 ne savent pas atteindre Internet
Solution  : Configurer la route par défaut sur l'ASBR (R2) et la propager

Étapes :
  1. ip route 0.0.0.0 0.0.0.0 <interface/next-hop>   → route par défaut locale sur l'ASBR
  2. router ospf 1
     default-information originate                    → redistribution dans OSPF

Résultat sur les autres routeurs :
  O*E2 0.0.0.0/0 [110/1] via <next-hop>
  └─ O = OSPF, * = route par défaut, E2 = externe type 2 (coût fixe)
  └─ "Gateway of last resort is <next-hop> to network 0.0.0.0"
```

## Script complet

```
! ============================================================
! PARTIE 1 - Configuration et propagation de la route par défaut
! ============================================================

! --- Sur R2 : route par défaut statique vers Internet ---
      ip route 0.0.0.0 0.0.0.0 Serial0/1/0

! --- Sur R2 : propagation via OSPF ---
      router ospf 1
        default-information originate

! ============================================================
! PARTIE 2 - Vérification
! ============================================================

! --- Vérification sur R1 et R3 ---
  show ip route

! --- Depuis les PCs ---
ping 64.100.1.2
```
