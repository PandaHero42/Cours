## Objectifs

- **Partie 1 :** Configurer une ACL étendue nommée unique (`LimitedAccess`) avec plusieurs politiques de blocage
- **Partie 2 :** Appliquer et vérifier l'ACL

---

## Contexte et politique de sécurité

Une seule ACL (`LimitedAccess`) implémente **trois restrictions distinctes** selon l'hôte source :

| Hôte | Bloqué vers Server1 et Server2 | Autorisé |
|------|-------------------------------|----------|
| PC1 (`172.31.1.101`) | HTTP (80) + HTTPS (443) | FTP, ICMP, tout autre trafic |
| PC2 (`172.31.1.102`) | FTP (21) | HTTP, HTTPS, ICMP, tout autre trafic |
| PC3 (`172.31.1.103`) | ICMP (ping) | HTTP, HTTPS, FTP, tout autre trafic |

> **Approche liste noire** : on bloque explicitement ce qui est interdit, puis `permit ip any any` autorise tout le reste. Contrairement au scénario 1 qui utilisait une liste blanche, ici on part du principe que l'accès est globalement permis, sauf exceptions.

---

## Partie 1 : Configurer l'ACL LimitedAccess

### Réponse — commande pour créer l'ACL étendue nommée

```
RT1(config)# ip access-list extended LimitedAccess
```

### Étape 1 : Bloquer PC1 → HTTP et HTTPS vers Server1 et Server2 (4 ACEs)

```
RT1(config-ext-nacl)# deny tcp host 172.31.1.101 host 64.101.255.254 eq 80
RT1(config-ext-nacl)# deny tcp host 172.31.1.101 host 64.101.255.254 eq 443
RT1(config-ext-nacl)# deny tcp host 172.31.1.101 host 64.103.255.254 eq 80
RT1(config-ext-nacl)# deny tcp host 172.31.1.101 host 64.103.255.254 eq 443
```

> **Pourquoi 4 ACEs et non 2 ?** Il faut bloquer HTTP **et** HTTPS sur **chaque** serveur séparément. `eq 80` et `eq 443` ne peuvent pas être combinés en une seule ACE — chaque port nécessite sa propre entrée. Idem pour chaque serveur (IP de destination différente).

> **`eq 443`** : HTTPS n'a pas de mot-clé IOS (contrairement à `www` pour 80 ou `ftp` pour 21). On utilise directement le numéro de port.

### Étape 2 : Bloquer PC2 → FTP vers Server1 et Server2 (2 ACEs)

```
RT1(config-ext-nacl)# deny tcp host 172.31.1.102 host 64.101.255.254 eq 21
RT1(config-ext-nacl)# deny tcp host 172.31.1.102 host 64.103.255.254 eq 21
```

> On peut aussi écrire `eq ftp` à la place de `eq 21` — les deux sont équivalents.

### Étape 3 : Bloquer PC3 → ICMP vers Server1 et Server2 (2 ACEs)

```
RT1(config-ext-nacl)# deny icmp host 172.31.1.103 host 64.101.255.254
RT1(config-ext-nacl)# deny icmp host 172.31.1.103 host 64.103.255.254
```

> **Pas de `eq` pour ICMP** : ICMP n'utilise pas de ports TCP/UDP. Le filtrage par type ICMP est possible (`echo`, `echo-reply`, etc.) mais non requis ici — on bloque tout ICMP de PC3 vers les serveurs.

### Étape 4 : Autoriser tout le reste

```
RT1(config-ext-nacl)# permit ip any any
```

> **`permit ip any any`** : `ip` = tout protocole (TCP, UDP, ICMP, etc.). Cette ACE finale est la soupape de sécurité — sans elle, le `deny any any` implicite bloquerait **tout le trafic restant**, y compris le trafic légitime (ex. PC1 FTP vers les serveurs, PC2 HTTP vers les serveurs, etc.).

### Étape 5 : Vérifier avant d'appliquer

```
RT1# show access-lists
```
```
Extended IP access list LimitedAccess
    10 deny tcp host 172.31.1.101 host 64.101.255.254 eq www
    20 deny tcp host 172.31.1.101 host 64.101.255.254 eq 443
    30 deny tcp host 172.31.1.101 host 64.103.255.254 eq www
    40 deny tcp host 172.31.1.101 host 64.103.255.254 eq 443
    50 deny tcp host 172.31.1.102 host 64.101.255.254 eq ftp
    60 deny tcp host 172.31.1.102 host 64.103.255.254 eq ftp
    70 deny icmp host 172.31.1.103 host 64.101.255.254
    80 deny icmp host 172.31.1.103 host 64.103.255.254
    90 permit ip any any
```

> **`show access-lists` vs `show running-config | begin access-list` :** `show access-lists` affiche les **numéros de séquence** (10, 20, 30…) indispensables pour modifier des ACEs individuelles. `show run` n'affiche pas ces numéros mais montre la configuration telle qu'elle sera sauvegardée.

## Partie 2 : Appliquer et vérifier l'ACL

### Étape 1 : Placement de l'ACL

**Réponse — interface et direction :**

Le trafic à filtrer provient du réseau `172.31.1.96/27` (PC1/PC2/PC3) et est destiné aux serveurs Internet. Ce trafic **entre** dans RT1 par **G0/0** (interface LAN). Conformément à la règle de placement des ACLs étendues (proche de la source) :

→ **G0/0, direction inbound**

```
RT1(config)# interface g0/0
RT1(config-if)# ip access-group LimitedAccess in
```

## Tableau récapitulatif des commandes clés

| Commande | Contexte | Description |
|----------|----------|-------------|
| `ip access-list extended <nom>` | Global config | Crée l'ACL étendue nommée |
| `deny tcp host <src> host <dst> eq <port>` | ACL ext config | Bloque TCP vers un port précis entre deux hôtes |
| `deny icmp host <src> host <dst>` | ACL ext config | Bloque tout ICMP entre deux hôtes |
| `permit ip any any` | ACL ext config | Autorise tout le reste (indispensable si liste noire) |
| `ip access-group <nom> in` | Interface config | Applique l'ACL inbound |
| `show access-lists` | Privileged EXEC | Affiche les ACLs avec numéros de séquence et compteurs |
| `show ip access-lists` | Privileged EXEC | Identique — affiche uniquement les ACLs IP |
| `clear access-list counters` | Privileged EXEC | Remet les compteurs de hits à zéro |
| `show run \| begin access-list` | Privileged EXEC | Affiche la config ACL sans numéros de séquence |

## Mémo — Liste blanche vs liste noire en ACL étendue

```
LISTE BLANCHE (Scénario 1) :
  → Tout est interdit par défaut, sauf ce qui est explicitement permis
  → Dernière ACE : deny any any (implicite ou explicite)
  → Usage : environnements restrictifs, serveurs exposés

  access-list 100 permit tcp <src> <dst> eq ftp
  access-list 100 permit icmp <src> <dst>
  (deny any any implicite)

LISTE NOIRE (Scénario 2) :
  → Tout est permis par défaut, sauf ce qui est explicitement interdit
  → Dernière ACE : permit ip any any (OBLIGATOIRE — sinon deny implicite bloque tout)
  → Usage : politiques d'exception ciblées, LAN avec accès général à Internet

  deny tcp host <PC1> host <Server1> eq 80
  deny tcp host <PC1> host <Server1> eq 443
  ...
  permit ip any any   ← INDISPENSABLE

Piège classique : oublier "permit ip any any" dans une liste noire
  → Le deny implicite final bloque TOUT le trafic non matché
  → Tous les PCs perdent l'accès à Internet
```

## Script complet

```
! ============================================================
! PARTIE 1 - Configuration de l'ACL LimitedAccess
! ============================================================

! --- Sur RT1 ---
      ip access-list extended LimitedAccess

! Bloquer PC1 → HTTP et HTTPS (Server1 et Server2)
        deny tcp host 172.31.1.101 host 64.101.255.254 eq 80
        deny tcp host 172.31.1.101 host 64.101.255.254 eq 443
        deny tcp host 172.31.1.101 host 64.103.255.254 eq 80
        deny tcp host 172.31.1.101 host 64.103.255.254 eq 443

! Bloquer PC2 → FTP (Server1 et Server2)
        deny tcp host 172.31.1.102 host 64.101.255.254 eq 21
        deny tcp host 172.31.1.102 host 64.103.255.254 eq 21

! Bloquer PC3 → ICMP (Server1 et Server2)
        deny icmp host 172.31.1.103 host 64.101.255.254
        deny icmp host 172.31.1.103 host 64.103.255.254

! Autoriser tout le reste
        permit ip any any

! --- Vérification avant application ---
  show access-lists

! ============================================================
! PARTIE 2 - Application et vérification
! ============================================================

! --- Application sur G0/0 inbound ---
      interface g0/0
        ip access-group LimitedAccess in

! --- Vérification avec compteurs ---
  show ip access-lists

! --- Remise à zéro des compteurs si nécessaire ---
  clear access-list counters
```
