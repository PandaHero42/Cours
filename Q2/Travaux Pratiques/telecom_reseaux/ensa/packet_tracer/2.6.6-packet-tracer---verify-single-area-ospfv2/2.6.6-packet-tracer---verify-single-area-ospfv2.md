## Partie 1 : Vérifier le fonctionnement OSPFv2 existant

### Étape 1 : Vérification sur R1

#### a. Table de routage — `show ip route`

```
R1# show ip route
```

Sortie obtenue (annotée) :

```
Gateway of last resort is 172.16.3.2 to network 0.0.0.0

     172.16.0.0/16 is variably subnetted, 5 subnets, 3 masks
C       172.16.1.0/24 is directly connected, GigabitEthernet0/0
L       172.16.1.1/32 is directly connected, GigabitEthernet0/0
O       172.16.2.0/24 [110/65] via 172.16.3.2, 00:02:18, Serial0/0/0
C       172.16.3.0/30 is directly connected, Serial0/0/0
L       172.16.3.1/32 is directly connected, Serial0/0/0
O       192.168.1.0/24 [110/65] via 192.168.10.6, 00:02:18, Serial0/0/1
     192.168.10.0/24 is variably subnetted, 3 subnets, 2 masks
C       192.168.10.4/30 is directly connected, Serial0/0/1
L       192.168.10.5/32 is directly connected, Serial0/0/1
O       192.168.10.8/30 [110/128] via 172.16.3.2, 00:02:18, Serial0/0/0
                        [110/128] via 192.168.10.6, 00:02:18, Serial0/0/1
O*E2    0.0.0.0/0 [110/1] via 172.16.3.2, 00:02:18, Serial0/0/0
```

**Réponses aux questions :**

- **Comment R1 a-t-il reçu la route par défaut ?** → Via OSPF, redistribuée par un ASBR (`O*E2` = OSPF External Type 2, candidat route par défaut). La ligne `Gateway of last resort is 172.16.3.2` confirme la réception.
- **De quel routeur R1 a-t-il reçu la route par défaut ?** → De **R2**, accessible via `172.16.3.2` (interface S0/0/0 de R2). C'est R2 qui est configuré avec `default-information originate`.
- **Comment filtrer `show ip route` pour n'afficher que les routes OSPF ?** → `show ip route ospf` (affiche uniquement les entrées de type `O` et `O*E2`).

> **Lecture de la route ECMP :** La route `192.168.10.8/30` dispose de **deux next-hops avec le même coût** (128). OSPF réalise du load-balancing Equal-Cost Multi-Path (ECMP) en installant les deux chemins simultanément dans la table de routage.

#### b. Voisins OSPF — `show ip ospf neighbor`

```
R1# show ip ospf neighbor
```

**Réponses aux questions :**

- **Quels routeurs ont formé des adjacences avec R1 ?** → **R2** (via S0/0/0) et **R3** (via S0/0/1).
- **Router IDs et états :** R2 et R3 apparaissent en état `FULL` (adjacence complète établie). Leurs Router IDs correspondent à leurs plus hautes adresses de loopback ou d'interface configurées.
- **Tous les routeurs adjacents sont-ils affichés ?** → Oui. R1 n'a de liens directs qu'avec R2 et R3 — R4 n'est pas encore connecté au réseau à cette étape.

#### c. Ping de PC1 vers l'ISP Router (`64.100.54.5`)

```
ping 64.100.54.5
```

Doit être **réussi** — R1 dispose de la route par défaut OSPF (`O*E2`) pour atteindre l'ISP. Si le ping échoue, exécuter `clear ip ospf process` sur les routeurs pour forcer la reconvergence, puis réessayer.

### Étape 2 : Vérification sur R2

#### a. Table de routage

```
R2# show ip route
```

**Réponse à la question — Comment R2 a-t-il appris la route par défaut vers l'ISP ?**

R2 **n'apprend pas** la route par défaut via OSPF — il est lui-même l'**ASBR** qui génère et redistribue cette route. Il dispose d'une route statique locale (`ip route 0.0.0.0 0.0.0.0 ...`) affichée avec le code `S*` dans sa propre table de routage.

#### b. Détails OSPF sur G0/0 — `show ip ospf interface g0/0`

```
R2# show ip ospf interface g0/0
```

**Réponses aux questions :**

- **Quel type de réseau OSPF est attaché à cette interface ?** → **Broadcast** (réseau Ethernet multi-accès — déclenche une élection DR/BDR).
- **Des paquets Hello OSPF sont-ils envoyés sur cette interface ?** → Techniquement oui, mais puisque G0/0 de R2 est un LAN sans autre routeur OSPF connecté dessus, les Hellos sont envoyés dans le vide. L'interface participe à OSPF (annonce le réseau) mais n'a pas de voisin à former sur ce segment. Il serait plus efficace de la configurer en **passive-interface** pour éviter ce trafic inutile.

#### c. Ping de PC2 vers S0/0/1 de R3 (`192.168.10.10`)

```
ping 192.168.10.10
```

Doit être **réussi** — R2 connaît le réseau `192.168.10.8/30` via OSPF.

### Étape 3 : Vérification sur R3

#### a. Réseaux routés par R3 — `show ip protocols`

```
R3# show ip protocols
```

**Réponse à la question — R3 route pour quels réseaux ?**

La sortie affiche la section `Routing for Networks` du processus OSPF de R3, listant tous les réseaux inclus dans les instructions `network` de sa configuration OSPF : typiquement `192.168.1.0/24` (G0/0), `192.168.11.0/24` (G0/1), `192.168.10.4/30` (S0/0/0), `192.168.10.8/30` (S0/0/1).

#### b. Détails voisins — `show ip ospf neighbor detail`

```
R3# show ip ospf neighbor detail
```

**Réponse à la question — Quelle est la priorité des voisins OSPF ?**

La priorité affichée est **1** — c'est la **valeur par défaut** sur toutes les interfaces OSPF Cisco. Elle intervient dans l'élection DR/BDR sur les segments multi-accès.

#### c. Ping de PC3 vers l'ISP Router (`64.100.54.5`)

```
ping 64.100.54.5
```

Doit être **réussi** — R3 dispose de la route par défaut propagée par R2 via OSPF (`O*E2`).

## Partie 2 : Ajouter le nouveau LAN succursale au réseau OSPF

### Étape 1 : Vérifier la configuration OSPF sur R4

```
R4# show run | begin router ospf
```

Cette commande affiche la configuration OSPF de R4 à partir de la ligne `router ospf`. On vérifie que les instructions `network` sont présentes pour les réseaux configurés sur R4.

**Réponse à la question — Quelle interface est configurée pour ne pas envoyer de mises à jour OSPF ?**

L'interface **G0/0/1** (côté LAN Laptop) est configurée en **passive-interface**. Cela signifie qu'OSPF annonce ce réseau dans ses LSA mais ne transmet pas de paquets Hello sur cette interface — comportement correct pour une interface LAN sans routeur voisin.

### Étape 2 : Connecter R4 au réseau OSPF

#### a. Connexion physique et vérification d'adjacence

Connecter l'interface **G0/0/0 de R4** au port **G0/1 du switch S3** avec le câble Ethernet approprié (câble droit).

```
R4# show ip ospf neighbor
```

**Réponse à la question — Quel état est affiché pour R3 ?**

R3 apparaît en état **FULL** — l'adjacence OSPF est complètement établie entre R4 et R3.

#### b. État de R4 vu depuis R3

```
R3# show ip ospf neighbor
```

**Réponse à la question — Pourquoi l'état de R4 est-il différent de celui de R1 et R2 ?**

R4 est connecté à R3 via un **réseau Ethernet (multi-accès broadcast)**. Sur ce type de réseau, OSPF élit un DR et un BDR. R3 est déjà présent sur ce segment (il est probablement DR ou BDR) et R4 vient d'arriver. L'état affiché pour R4 depuis R3 peut être **FULL/DR**, **FULL/BDR** ou **FULL/DROTHER** selon le résultat de l'élection — ce qui diffère de R1 et R2 qui sont connectés à R3 via des **liens point-à-point série** (pas d'élection DR/BDR → état simplement `FULL/-`).

#### c. Ping depuis le Laptop vers PC2 (`172.16.2.2`)

```
ping 172.16.2.2
```

Doit être **réussi** — R4 a propagé son réseau `192.168.11.0/24` via OSPF vers R3, qui le redistribue au reste du domaine. Le Laptop obtient son adresse par DHCP et peut désormais atteindre tous les hôtes du réseau.

## Tableau récapitulatif des commandes clés

| Commande | Contexte | Description |
|----------|----------|-------------|
| `show ip route` | Privileged EXEC | Table de routage complète (C, L, O, O*E2...) |
| `show ip route ospf` | Privileged EXEC | Filtre uniquement les routes apprises via OSPF |
| `show ip ospf neighbor` | Privileged EXEC | État des adjacences OSPF (FULL, 2WAY, DROTHER...) |
| `show ip ospf neighbor detail` | Privileged EXEC | Détails complets des voisins (priorité, Router ID, timers) |
| `show ip ospf interface <if>` | Privileged EXEC | Détails OSPF d'une interface (type réseau, DR/BDR, Hello...) |
| `show ip protocols` | Privileged EXEC | Protocoles de routage actifs et réseaux annoncés |
| `show ip ospf` | Privileged EXEC | Informations sur le processus OSPF (Process ID, Router ID, area) |
| `show run \| begin router ospf` | Privileged EXEC | Affiche la configuration OSPF depuis la running-config |
| `clear ip ospf process` | Privileged EXEC | Réinitialise le processus OSPF (force reconvergence) |

## Mémo — Lecture de la table de routage OSPF

```
Codes OSPF dans show ip route :
  O      → route intra-area apprise via OSPF
  O IA   → route inter-area (autre zone OSPF)
  O*E2   → route externe Type 2 redistribuée (coût fixe) — typiquement la route par défaut
  O E1   → route externe Type 1 (coût cumulé)

Format d'une entrée :
  O  172.16.2.0/24 [110/65] via 172.16.3.2, Serial0/0/0
                    │   │         │
                    AD  Coût      Next-hop

ECMP (Equal-Cost Multi-Path) :
  Plusieurs lignes "via" pour la même destination → OSPF load-balance sur les deux chemins

show ip ospf neighbor — états clés :
  FULL       → adjacence complète, synchronisation LSDB terminée
  FULL/DR    → voisin est le DR du segment
  FULL/BDR   → voisin est le BDR du segment
  FULL/-     → lien point-à-point (pas de DR/BDR)
  FULL/DROTHER → voisin n'est ni DR ni BDR
  2WAY       → Hellos échangés mais pas d'adjacence complète (entre DROTHERs)
```
