# Packet Tracer – Determine the DR and BDR

## Topologie

| Device | Interface | Adresse IP     | Masque de sous-réseau |
|--------|-----------|----------------|----------------------|
| RA     | G0/0      | 192.168.1.1    | 255.255.255.0        |
| RA     | Lo0       | 192.168.31.11  | 255.255.255.255      |
| RB     | G0/0      | 192.168.1.2    | 255.255.255.0        |
| RB     | Lo0       | 192.168.31.22  | 255.255.255.255      |
| RC     | G0/0      | 192.168.1.3    | 255.255.255.0        |
| RC     | Lo0       | 192.168.31.33  | 255.255.255.255      |

---

## Objectifs

- **Partie 1 :** Observer les changements de rôles DR et BDR
- **Partie 2 :** Modifier la priorité OSPF et forcer une élection

---

## Contexte

Sur un réseau **multi-accès** (comme Ethernet), OSPF élit un **DR (Designated Router)** et un **BDR (Backup Designated Router)** pour réduire le trafic de synchronisation LSA. Sans DR/BDR, chaque routeur devrait former une adjacence complète avec tous les autres (complexité O(n²)). Avec DR/BDR, tous les routeurs se synchronisent uniquement avec le DR et le BDR, réduisant drastiquement le nombre d'échanges.

- **DR** : collecte et redistribue toutes les mises à jour LSA vers les autres routeurs du segment.
- **BDR** : surveille le DR et prend le relais immédiatement s'il tombe.
- **DROTHER** : tout routeur qui n'est ni DR ni BDR. Il ne forme une adjacence `FULL` qu'avec le DR et le BDR (état `2WAY` avec les autres DROTHERs).

L'élection repose sur deux critères, dans l'ordre :
1. **Priorité OSPF** la plus élevée (0–255, défaut = 1 ; priorité 0 = jamais élu)
2. **Router ID** le plus élevé (en cas d'égalité de priorité)

> ⚠️ L'élection OSPF est **non-préemptive** : un routeur qui rejoint le réseau après l'élection ne délogera pas le DR/BDR en place, même s'il a une priorité plus élevée — sauf si on force une nouvelle élection (`clear ip ospf process`).

## Partie 1 : Observer les changements de rôles DR et BDR

### Étape 1 : Attendre que les liens passent au vert

À l'ouverture du fichier dans Packet Tracer, les liens du switch sont en **orange** pendant environ 50 secondes : STP vérifie que les routeurs connectés ne sont pas des switches. On peut accélérer avec **Fast Forward Time**.

### Étape 2 : Vérifier l'état des voisins OSPF

On utilise `show ip ospf neighbor` sur chaque routeur pour identifier les rôles actuels :

```
RA# show ip ospf neighbor
```
```
Neighbor ID    Pri   State        Dead Time   Address       Interface
192.168.31.33    2   FULL/DR      00:00:35    192.168.1.3   GigabitEthernet0/0
192.168.31.22    1   FULL/BDR     00:00:35    192.168.1.2   GigabitEthernet0/0
```

```
RB# show ip ospf neighbor
```
```
Neighbor ID    Pri   State           Dead Time   Address       Interface
192.168.31.11    1   FULL/DROTHER    00:00:36    192.168.1.1   GigabitEthernet0/0
192.168.31.33    2   FULL/DR         00:00:36    192.168.1.3   GigabitEthernet0/0
```

```
RC# show ip ospf neighbor
```
```
Neighbor ID    Pri   State           Dead Time   Address       Interface
192.168.31.11    1   FULL/DROTHER    00:00:39    192.168.1.1   GigabitEthernet0/0
192.168.31.22    1   FULL/BDR        00:00:38    192.168.1.2   GigabitEthernet0/0
```

**Réponses aux questions :**

- **Quel routeur est le DR ?** → **RC** (Router ID `192.168.31.33`, priorité 2 — la plus élevée du segment)
- **Quel routeur est le BDR ?** → **RB** (Router ID `192.168.31.22`, priorité 1 — départage par Router ID le plus élevé entre RA et RB)
- **Quel est l'état OSPF de RA ?** → **DROTHER** — RA n'est ni DR ni BDR. Il maintient une adjacence `FULL` avec DR et BDR, mais resterait à `2WAY` avec un autre DROTHER.

> **Pourquoi RC est DR avec priorité 2 ?** À la configuration initiale, RC avait une priorité OSPF de 2 sur son interface G0/0, contre 1 (défaut) pour RA et RB. La priorité la plus haute l'emporte immédiatement.

### Étape 3 : Activer le debug des adjacences OSPF

Le debug permet d'observer en temps réel le processus d'élection DR/BDR :

```
RA# debug ip ospf adj
RB# debug ip ospf adj
```

> Les messages debug s'affichent directement dans la console chaque fois qu'un événement d'adjacence se produit (hello reçu, dead timer expiré, changement de rôle, etc.).

### Étape 4 : Désactiver G0/0 sur RC (simulation de panne)

```
RC(config)# interface g0/0
RC(config-if)# shutdown
```

On attend environ 30 secondes que les **dead timers** expirent sur RA et RB (le dead timer vaut 4× le hello interval, soit 40 s par défaut sur Ethernet). Passé ce délai, RA et RB détectent la disparition de RC et déclenchent une nouvelle élection.

**Réponse à la question :**

D'après la sortie debug :
- **Nouveau DR → RB** (Router ID `192.168.31.22`, le plus élevé restant)
- **Nouveau BDR → RA** (Router ID `192.168.31.11`, seul autre routeur restant)

### Étape 5 : Réactiver G0/0 sur RC

```
RC(config)# interface g0/0
RC(config-if)# no shutdown
```

On attend la reconvergence OSPF.

**Réponse à la question — Les rôles ont-ils changé ?**

Non, les rôles **ne changent pas**. RC revient sur le réseau mais l'élection OSPF est **non-préemptive** : RB reste DR, RA reste BDR. RC reprend simplement le rôle de DROTHER, même si sa priorité (2) est supérieure à celle de RB (1).

```
RC# show ip ospf neighbor
```
```
Neighbor ID    Pri   State     Dead Time   Address       Interface
192.168.31.22    1   FULL/DR   00:00:34    192.168.1.2   GigabitEthernet0/0
192.168.31.11    1   FULL/BDR  00:00:34    192.168.1.1   GigabitEthernet0/0
```

> Pour qu'un nouveau routeur (ou un routeur avec une priorité plus élevée) devienne DR, il faut **forcer une nouvelle élection** via `clear ip ospf process`.

### Étape 6 : Désactiver G0/0 sur RB

```
RB(config)# interface g0/0
RB(config-if)# shutdown
```

On attend ~30 secondes pour que les hold-down timers expirent sur RA et RC.

**Réponse à la question :**

D'après le debug sur RA :
- **Nouveau DR → RA** (BDR promu automatiquement au rang de DR — c'est précisément le rôle du BDR)
- **Nouveau BDR → RC** (seul autre routeur restant, élu BDR)

> C'est le mécanisme clé du BDR : en cas de perte du DR, le **BDR prend la relève immédiatement** sans nouvelle élection complète, minimisant l'interruption de service. Une élection a lieu uniquement pour désigner un nouveau BDR.

### Étape 7 : Réactiver G0/0 sur RB

```
RB(config)# interface g0/0
RB(config-if)# no shutdown
```

**Réponse à la question — Les rôles ont-ils changé ?**

Non. Même principe de non-préemption : RB rejoint le réseau en tant que DROTHER. RA reste DR, RC reste BDR.

```
RC# show ip ospf interface g0/0
```

**Réponse à la question — Quel est le statut de RC ?**

RC est désormais **BDR** sur ce segment (`Backup Designated Router` affiché dans la sortie de `show ip ospf interface`).

### Étape 8 : Désactiver le debug

```
RA# undebug all
RB# undebug all
```

> `undebug all` (ou son alias `no debug all`) désactive tous les processus de debug actifs sur le routeur. Il est impératif de les couper après utilisation : un debug actif en production peut saturer le CPU du routeur.

## Partie 2 : Modifier la priorité OSPF et forcer une élection

### Étape 1 : Configurer les priorités OSPF sur chaque routeur

On modifie la priorité OSPF directement sur l'interface G0/0 de chaque routeur :

| Routeur | Priorité souhaitée | Résultat attendu |
|---------|--------------------|------------------|
| RA      | 200                | DR               |
| RB      | 100                | BDR              |
| RC      | 1 (défaut)         | DROTHER          |

```
RA(config)# interface g0/0
RA(config-if)# ip ospf priority 200

RB(config)# interface g0/0
RB(config-if)# ip ospf priority 100

RC(config)# interface g0/0
RC(config-if)# ip ospf priority 1
```

> La modification de priorité n'a **aucun effet immédiat** tant qu'une nouvelle élection n'est pas déclenchée (non-préemption).

### Étape 2 : Forcer une nouvelle élection

On réinitialise le processus OSPF sur chaque routeur, en commençant par RA :

```
RA# clear ip ospf process
RB# clear ip ospf process
RC# clear ip ospf process
```

> `clear ip ospf process` force le routeur à abandonner toutes ses adjacences et à redémarrer le processus OSPF depuis zéro. Cela déclenche de nouvelles élections DR/BDR sur tous les segments multi-accès. On peut utiliser **Fast Forward Time** pour accélérer la convergence.

### Étape 3 : Vérifier les nouvelles élections

```
RA# show ip ospf neighbor
RB# show ip ospf neighbor
RC# show ip ospf neighbor
```

**Réponse à la question :**

- **Nouveau DR → RA** (priorité 200, la plus haute)
- **Nouveau BDR → RB** (priorité 100, la deuxième plus haute)
- **RC** → DROTHER (priorité 1)

Les routeurs occupent désormais les rôles souhaités, confirmant que la **priorité OSPF** est le levier principal pour contrôler l'élection DR/BDR.

## Tableau récapitulatif des commandes clés

| Commande | Contexte | Description |
|----------|----------|-------------|
| `show ip ospf neighbor` | Privileged EXEC | Affiche les voisins OSPF et leurs rôles (DR, BDR, DROTHER) |
| `debug ip ospf adj` | Privileged EXEC | Active le debug des événements d'adjacence OSPF |
| `undebug all` | Privileged EXEC | Désactive tous les debugs actifs |
| `shutdown` | Interface config | Désactive une interface |
| `no shutdown` | Interface config | Réactive une interface |
| `ip ospf priority <0-255>` | Interface config | Définit la priorité OSPF de l'interface (0 = jamais élu) |
| `clear ip ospf process` | Privileged EXEC | Réinitialise le processus OSPF et force une nouvelle élection |
| `show ip ospf interface` | Privileged EXEC | Détails OSPF d'une interface (rôle DR/BDR, priorité, timers) |

## Mémo — Règles d'élection DR/BDR

```
Priorité la plus haute → DR
  └─ En cas d'égalité : Router ID le plus élevé → DR

Deuxième priorité la plus haute → BDR
  └─ En cas d'égalité : deuxième Router ID le plus élevé → BDR

Priorité 0 → jamais éligible (ni DR ni BDR)

Élection NON-PRÉEMPTIVE :
  └─ Un nouveau routeur (même avec une priorité plus élevée) ne délogera pas le DR/BDR en place
  └─ Pour forcer une nouvelle élection : clear ip ospf process

En cas de perte du DR :
  └─ Le BDR est promu DR automatiquement
  └─ Une nouvelle élection désigne uniquement un nouveau BDR
```

## Script complet

```
! ============================================================
! PARTIE 1 - Observation des rôles DR/BDR
! ============================================================

! --- Vérification initiale (sur chaque routeur) ---
  show ip ospf neighbor

! --- Activation du debug adjacence OSPF ---
  debug ip ospf adj

! --- Simulation de panne RC ---
! Sur RC :
      interface g0/0
        shutdown

! Attendre ~30 s (dead timer)

! --- Restauration RC ---
! Sur RC :
      interface g0/0
        no shutdown

! --- Simulation de panne RB ---
! Sur RB :
      interface g0/0
        shutdown

! Attendre ~30 s

! --- Restauration RB ---
! Sur RB :
      interface g0/0
        no shutdown

! --- Vérification sur RC après restauration ---
  show ip ospf interface g0/0

! --- Désactivation du debug ---
  undebug all

! ============================================================
! PARTIE 2 - Modification des priorités et forçage d'élection
! ============================================================

! --- Configuration des priorités OSPF ---
! Sur RA :
      interface g0/0
        ip ospf priority 200

! Sur RB :
      interface g0/0
        ip ospf priority 100

! Sur RC :
      interface g0/0
        ip ospf priority 1

! --- Forçage de la nouvelle élection (sur chaque routeur) ---
  clear ip ospf process

! Attendre la convergence (ou Fast Forward Time)

! --- Vérification finale ---
  show ip ospf neighbor
```
