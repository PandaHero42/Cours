# Packet Tracer – Troubleshooting Challenge – Document the Network

## Objectifs

- Tester la connectivité réseau
- Collecter les informations d'adressage des hôtes
- Accéder à distance aux équipements (passerelles)
- Documenter les configurations des équipements
- Découvrir la topologie via des protocoles de découverte
- Dessiner la topologie réseau

---

## Contexte

**Scénario :** L'administrateur réseau précédent a quitté l'entreprise sans laisser de documentation. Il faut reconstituer entièrement la topologie et l'adressage à partir de zéro. Accès VTY : mot de passe `cisco` ; enable : `class`. Telnet est utilisé (pas SSH — noter comme problème de sécurité).

> Ce lab est la **Partie 1** d'une série de deux. La documentation produite ici sera utilisée dans la Partie 2 pour le dépannage.

---

## Méthodologie de découverte — Approche par couches (Bottom-Up)

La reconstitution d'une topologie inconnue suit une approche structurée :

```
1. Hôtes (PCs)        → ipconfig / ifconfig → IP, masque, gateway
2. Passerelles        → Telnet → show ip interface brief, show run
3. Tables de routage  → show ip route → réseaux connus, next-hops
4. Voisins CDP/LLDP   → show cdp/lldp neighbors detail → switches, routeurs
5. Switches           → SSH/Telnet → show vlan, show interfaces, show cdp neighbors
6. Synthèse           → Tableau d'adressage + schéma de topologie
```

---

## Partie 1 : Tester la connectivité

Depuis chaque PC, pinger les autres PCs et le serveur Internet :

```
PC1> ping PC2_IP
PC1> ping PC3_IP
...
PC1> ping <Internet Server IP>
```

> Les pings qui échouent **avant** toute modification indiquent des problèmes existants à noter pour la Partie 2. Ne pas corriger à ce stade — documenter uniquement.

---

## Partie 2 : Découvrir la configuration des PCs

Sur chaque PC (PC1 à PC7) → Command Prompt :

```
ipconfig /all
```

**Informations à relever pour chaque PC :**

| Champ | Source |
|-------|--------|
| Adresse IP | `IPv4 Address` |
| Masque de sous-réseau | `Subnet Mask` |
| Default Gateway | `Default Gateway` |
| Adresse MAC | `Physical Address` |
| DHCP ou statique | `DHCP Enabled: Yes/No` |

Reporter dans le tableau d'adressage.

---

## Partie 3 : Accéder aux équipements passerelles (Telnet)

Chaque PC a une default gateway — c'est l'adresse d'un routeur ou switch L3. Connexion Telnet :

```
PC1> telnet <IP_default_gateway>
Password: cisco
Router> enable
Password: class
Router#
```

**Commandes à exécuter sur chaque passerelle :**

```
show ip interface brief       → état et IP de toutes les interfaces
show interfaces               → détails (speed, duplex, description)
show run                      → configuration complète
show version                  → modèle, IOS, hostname
```

> **Sécurité à noter :** Telnet transmet les identifiants en clair. Un réseau bien géré devrait utiliser SSH exclusivement. C'est une des recommandations à formuler dans la section Réflexion.

---

## Partie 4 : Reconstituer la topologie réseau

### Étape 1 : Analyser les tables de routage

Sur chaque routeur/switch L3 :

```
show ip route
```

**Ce qu'on peut déduire :**
- Les réseaux `C` (Connected) → interfaces directement configurées sur cet équipement
- Les réseaux `O` / `R` / `D` (OSPF/RIP/EIGRP) → réseaux appris depuis d'autres routeurs (indique un protocole de routage actif et des voisins)
- Les routes statiques → configuration manuelle, souvent vers l'Internet ou entre sites

```
show ip protocols             → protocole de routage actif, réseaux annoncés, voisins
```

### Étape 2 : Découvrir les équipements non-passerelles (CDP/LLDP)

Sur chaque routeur et switch découvert :

```
show cdp neighbors
show cdp neighbors detail     → IP, version IOS, plateforme de chaque voisin
```

ou

```
show lldp neighbors
show lldp neighbors detail
```

**Informations extraites :**
- Nom des équipements voisins (`Device ID`)
- Interface locale et interface distante (`Local Intrfce` / `Port ID`)
- Type d'équipement (`Capability` : R=Router, S=Switch, H=Host)
- IP de management (`Management Address` dans `detail`)

→ Chaque voisin découvert = nouvelle ligne dans le tableau d'adressage + nouveau lien dans le schéma.

---

## Partie 5 : Explorer en profondeur et compléter

### SSH/Telnet vers les switches découverts

Pour chaque switch identifié via CDP :

```
Router# ssh -l <user> <IP_switch>
```
ou
```
Router# telnet <IP_switch>
```

**Commandes sur les switches :**

```
show vlan brief               → VLANs configurés et ports associés
show interfaces trunk         → liens trunk, VLANs autorisés
show spanning-tree summary    → mode STP, root bridge
show cdp neighbors            → voisins supplémentaires (autres switches, routeurs)
show port-security            → sécurité des ports configurée
show etherchannel summary     → canaux agrégés
```

### Itération jusqu'à la complétion

Répéter : découvrir un voisin → y accéder → lancer `show cdp neighbors` → découvrir ses propres voisins → etc. jusqu'à n'avoir plus de nouveaux équipements.

## Réflexion — Recommandations de sécurité et bonnes pratiques

En parcourant les configurations, les problèmes courants à identifier et signaler sont :

| Problème constaté | Recommandation CCNA |
|-------------------|---------------------|
| **Telnet utilisé** pour l'accès distant | Remplacer par **SSH** (`transport input ssh` sur les lignes VTY) |
| **Mots de passe en clair** dans la config (`password cisco`) | Utiliser `enable secret` (MD5) + `service password-encryption` |
| **CDP activé sur toutes les interfaces** (y compris vers l'extérieur) | `no cdp enable` sur les interfaces WAN/DMZ/exposées |
| **Pas de banner MOTD** | Configurer un banner d'avertissement légal |
| **Pas de timeout VTY** | `exec-timeout 10 0` sur les lignes VTY |
| **Pas de `login local`** sur les VTY | Utiliser des comptes locaux avec `username / secret` |
| **Interfaces non utilisées actives** | `shutdown` sur toutes les interfaces inutilisées |
| **VLAN 1 utilisé comme VLAN natif** | Changer le native VLAN vers un VLAN dédié (ex. VLAN 99) |
| **Protocole de routage RIPv2** (si présent) | Migrer vers OSPF ou EIGRP (RIP obsolète, convergence lente) |

| `show spanning-tree summary` | Switch | STP mode, root bridge |
| `show port-security` | Switch | Sécurité des ports |

## Mémo — Processus de documentation réseau

```
Étape 1 : Hôtes (sans accès réseau actif requis)
  ipconfig → IP, masque, gateway, MAC

Étape 2 : Passerelles (accès réseau requis)
  Telnet/SSH → show ip int brief, show run, show version

Étape 3 : Table de routage (réseaux et protocoles)
  show ip route → réseaux connus
  show ip protocols → protocole, voisins

Étape 4 : Découverte voisins (couche 2)
  show cdp neighbors detail → switches et routeurs adjacents
  show lldp neighbors detail → équipements multi-vendeur

Étape 5 : Switches (connexion via IP SVI)
  show vlan, show trunk, show etherchannel, show stp

Étape 6 : Synthèse
  Tableau d'adressage complet + schéma topologique
  Liste des non-conformités et recommandations
```
