# Packet Tracer – Troubleshoot WLAN Issues

> **Objectif** : Identifier et corriger les problèmes de connectivité sans fil dans un réseau domestique (Home Wireless Router) et un réseau entreprise (WLC + RADIUS), pour que tous les hôtes puissent accéder au Web Server par IP et par URL.

---

## Topologie

| Device               | Interface  | Adresse IP          |
|----------------------|------------|---------------------|
| Home Wireless Router | Internet   | DHCP                |
| Home Wireless Router | LAN        | 192.168.0.1         |
| R1                   | G0/0/0.10  | 192.168.10.1/24     |
| R1                   | G0/0/0.20  | 192.168.20.1/24     |
| R1                   | G0/0/0.200 | 192.168.200.1/24    |
| R1                   | G0/0/1     | 172.31.1.1/24       |
| WLC-1                | Management | 192.168.200.254/24  |
| RADIUS Server        | NIC        | 172.31.1.254/24     |
| Web Server           | NIC        | 203.0.113.78/24     |
| DNS Server           | NIC        | 10.100.100.254      |

### WLANs de référence

| WLAN          | SSID     | Auth              | Username | Password  |
|---------------|----------|-------------------|----------|-----------|
| Home Network  | HomeSSID | WPA2-Personal     | N/A      | Cisco123  |
| WLAN VLAN 10  | SSID-10  | WPA2-PSK/Personal | N/A      | Cisco123  |
| WLAN VLAN 20  | SSID-20  | WPA2-Enterprise   | user2    | User2Pass |

**Objectif** : tous les hôtes doivent pouvoir accéder à `www.netacad.pt` et `203.0.113.78`.

---

## Partie 1 : Tester et identifier les problèmes

### Étape 1 – Tests initiaux

Pour chaque hôte sans fil, tester depuis **Desktop → Web Browser** :
- `http://203.0.113.78` (accès par IP)
- `http://www.netacad.pt` (accès par URL)

Et depuis **Desktop → Command Prompt** :
```
ping 203.0.113.78
```

### Étape 2 – Méthodologie de dépannage WLAN

```
1. L'hôte est-il connecté au bon SSID ?
   → PC Wireless > Connect tab

2. A-t-il reçu une IP valide (pas APIPA 169.254.x.x) ?
   → IP Configuration ou ipconfig

3. Les paramètres de sécurité sont-ils corrects ?
   → Bonne passphrase / bon profil WPA2-Enterprise

4. Le WLC / routeur est-il bien configuré ?
   → https://192.168.200.254 (admin/Cisco123)
   → 192.168.0.1 (admin/admin) pour le Home Router

5. Le DNS fonctionne-t-il ?
   → ping www.netacad.pt vs ping 203.0.113.78
```

## Problèmes classiques et corrections

> ⚠️ Les erreurs exactes dépendent du fichier Packet Tracer. Voici tous les problèmes possibles avec leurs corrections.

### Tableau de documentation

| Device | Réseau | Problème possible | Correction |
|--------|--------|-------------------|------------|
| Laptop1 / Laptop2 | Entreprise | Mauvais SSID ou passphrase | Reconnecter avec SSID-10 + Cisco123 |
| Tablet PC / Smartphone | Maison | SSID incorrect ou passphrase erronée | Reconnecter avec HomeSSID + Cisco123 |
| Home Admin / Laptop | Maison | IP statique incorrecte | Passer en DHCP |

| WLC | Entreprise | Interface VLAN incorrecte sur le WLAN | WLC → WLANs → Interface correcte |
| Home Wireless Router | Maison | SSID différent de HomeSSID | Wireless → Basic → SSID = HomeSSID |
| Home Wireless Router | Maison | Sécurité incorrecte ou passphrase | Wireless Security → WPA2 Personal → Cisco123 |
| Hôte entreprise | Entreprise | Pas de connexion au bon profil SSID-20 | Créer profil WPA2-Enterprise : user2/User2Pass |

## Partie 2 : Corrections

### Correction — Hôte domestique mal connecté (Home Network)

**Hôte → Desktop → PC Wireless → Connect → Refresh**  
Sélectionner `HomeSSID` → entrer `Cisco123` → **Connect**

Si le SSID n'apparaît pas → vérifier le Home Wireless Router :

**Browser → `192.168.0.1` → admin/admin**  
- **Wireless → Basic Wireless Settings** : SSID = `HomeSSID`, canal 6
- **Wireless → Wireless Security** : WPA2 Personal, AES, passphrase = `Cisco123`
- **Save Settings**

### Correction — WLAN VLAN10 désactivé sur le WLC

**Browser → `https://192.168.200.254` → admin/Cisco123**  
**WLANs** → cliquer sur l'ID du WLAN SSID-10 → cocher **Enabled** → **Apply**

### Correction — Hôte entreprise sur SSID-20 (WPA2-Enterprise)

**Hôte → Desktop → PC Wireless → Profiles → New**

| Paramètre | Valeur |
|-----------|--------|
| Profile Name | `Enterprise` |
| SSID | `SSID-20` → Advanced Setup |
| Network | DHCP |
| Security | `WPA2-Enterprise` |
| Login | `user2` |
| Password | `User2Pass` |

**Save** → sélectionner le profil → **Connect to Network**

### Correction — Mauvaise interface VLAN sur le WLC

**WLC GUI → WLANs → WLAN ID** → vérifier que l'interface correspond au bon VLAN :
- SSID-10 → interface `WLAN-10`
- SSID-20 → interface `WLAN-20`

### Correction — Problème DNS (URL ne fonctionne pas mais IP oui)

Si `ping 203.0.113.78` réussit mais `www.netacad.pt` échoue → problème DNS.

Vérifier la configuration DHCP du pool concerné — le DNS server doit être `10.100.100.254`.

Sur le routeur ou le WLC, vérifier que le DNS server communiqué aux clients est correct.

## Résumé des commandes de vérification

| Action | Où |
|--------|----|
| Tester connexion IP | `ping 203.0.113.78` depuis Command Prompt |
| Tester DNS | `ping www.netacad.pt` depuis Command Prompt |
| Vérifier IP obtenue | `ipconfig` depuis Command Prompt |
| Vérifier SSID connecté | PC Wireless → Link Information |
| Vérifier WLANs actifs | WLC GUI → WLANs |
| Vérifier interfaces WLC | WLC GUI → Controller → Interfaces |
| Vérifier RADIUS | WLC GUI → Security → RADIUS |
| Vérifier Home Router | Browser → 192.168.0.1 |

---

> ⚠️ **Rappel** :
> - Si l'IP est en `169.254.x.x` → problème DHCP ou non connecté au WLAN.
> - Si ping par IP réussit mais pas par URL → problème DNS.
> - Sur le WLC, ne jamais oublier **Apply** après chaque modification.
> - Les credentials WLC : `admin` / `Cisco123`. Home Router : `admin` / `admin`.
