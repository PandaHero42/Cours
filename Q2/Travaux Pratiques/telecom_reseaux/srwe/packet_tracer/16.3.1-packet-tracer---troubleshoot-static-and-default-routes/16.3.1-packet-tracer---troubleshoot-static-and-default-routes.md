# Packet Tracer – Troubleshoot Static and Default Routes

> **Objectif** : Identifier et corriger les erreurs de configuration dans des routes statiques et par défaut IPv4/IPv6 entre trois LANs.

---

## Partie 1 : Diagnostic

### Commandes de vérification

Sur chaque routeur :

```
R1# show ip route
R1# show ipv6 route
R1# show running-config | include ip route
R1# show running-config | include ipv6 route
```

### Routes correctes attendues

**R1 doit avoir :**
- Route vers LAN2 (`172.31.0.0/24`) → next hop `172.31.1.193` (R2 S0/0/0)
- Route vers LAN3 (`172.31.1.128/26`) → next hop `172.31.1.193`

**R2 doit avoir :**
- Route vers LAN1 (`172.31.1.0/25`) → next hop `172.31.1.194` (R1 S0/0/0)
- Route vers LAN3 (`172.31.1.128/26`) → next hop `172.31.1.198` (R3 S0/0/1)

**R3 doit avoir :**
- Route vers LAN1 (`172.31.1.0/25`) → next hop `172.31.1.197` (R2 S0/0/1)
- Route vers LAN2 (`172.31.0.0/24`) → next hop `172.31.1.197`
- (ou route par défaut `0.0.0.0/0` → next hop `172.31.1.197`)

---

## Problèmes classiques et corrections

| Localisation | Problème possible | Correction |
|---|---|---|
| R1 | Next hop erroné (ex: `172.31.1.194` au lieu de `172.31.1.193`) | Supprimer et recréer la route avec le bon next hop |
| R1 | Réseau de destination incorrect (ex: `172.31.0.0/25` au lieu de `/24`) | Corriger le masque |
| R2 | Route vers LAN1 ou LAN3 absente | Ajouter la route manquante |
| R2 | Mauvais next hop vers R3 (ex: `172.31.1.197` au lieu de `172.31.1.198`) | Corriger le next hop |
| R3 | Route par défaut ou statiques manquantes/incorrectes | Ajouter/corriger |
| Tout routeur | Route IPv6 manquante ou mauvais préfixe | Vérifier et corriger |

## Partie 2 : Corrections

### Corrections IPv4 sur R1

```
R1# show running-config | include ip route
! → identifier les routes incorrectes

R1# configure terminal

! Supprimer les routes incorrectes (adapter selon ce qu'on trouve) :
R1(config)# no ip route <réseau> <masque> <mauvais_next_hop>

! Reconfigurer correctement :
R1(config)# ip route 172.31.0.0 255.255.255.0 172.31.1.193
! → LAN2 via R2 (next hop = R2 S0/0/0)

R1(config)# ip route 172.31.1.128 255.255.255.192 172.31.1.193
! → LAN3 via R2 (next hop = R2 S0/0/0)

R1(config)# end
```

### Corrections IPv4 sur R2

```
R2# configure terminal

R2(config)# ip route 172.31.1.0 255.255.255.128 172.31.1.194
! → LAN1 via R1 (next hop = R1 S0/0/0)

R2(config)# ip route 172.31.1.128 255.255.255.192 172.31.1.198

R2(config)# end
```

## Résumé des commandes clés

| Commande | Rôle |
|----------|------|
| `show ip route` | Table de routage IPv4 |
| `show ipv6 route` | Table de routage IPv6 |
| `show run \| include ip route` | Affiche toutes les routes statiques IPv4 |
| `show run \| include ipv6 route` | Affiche toutes les routes statiques IPv6 |
| `no ip route <réseau> <masque> <next-hop>` | Supprime une route statique IPv4 |
| `no ipv6 route <préfixe> <next-hop>` | Supprime une route statique IPv6 |

---

> ⚠️ **Erreurs classiques dans ce type de PT** :
> - Next hop qui pointe vers la propre IP du routeur au lieu de celle du voisin.
> - Masque incorrect (ex: /24 au lieu de /25).
> - Routes qui existent dans un sens mais pas dans l'autre (trafic aller ≠ retour).
> - Routes IPv6 avec mauvais préfixe ou next hop.
> - `no ip route` sans le next hop exact ne supprimera pas la route — il faut correspondre exactement à la route existante.

## Script complet (toutes les commandes dans l'ordre)

```
! ══════════════════════════════════════════════
! ─── DIAGNOSTIC initial ───────────────────────
! ══════════════════════════════════════════════

! Sur R1, R2, R3 :
    enable
        show ip route
        show ipv6 route
        show run | include ip route
        show run | include ipv6 route


! ══════════════════════════════════════════════
! ─── CORRECTIONS (adapter selon les erreurs) ──
! ══════════════════════════════════════════════

! ─── Sur R1 ───────────────────────────────────

    enable

        configure terminal

            ! ─── Global Config ───────────────
            ! Supprimer routes incorrectes :
            no ip route <réseau_erroné> <masque> <next_hop_erroné>

            ! Routes correctes IPv4 :
            ip route 172.31.0.0 255.255.255.0 172.31.1.193
            ip route 172.31.1.128 255.255.255.192 172.31.1.193

            ! Routes correctes IPv6 :
            ipv6 route 2001:DB8:3::/64 2001:DB8:2::193
            ipv6 route 2001:DB8:5::/64 2001:DB8:2::193

            end


! ─── Sur R2 ───────────────────────────────────

    enable

        configure terminal

            ! ─── Global Config ───────────────
            ip route 172.31.1.0 255.255.255.128 172.31.1.194
            ip route 172.31.1.128 255.255.255.192 172.31.1.198

            ipv6 route 2001:DB8:1::/64 2001:DB8:2::194
            ipv6 route 2001:DB8:5::/64 2001:DB8:4::198

            end


! ─── Sur R3 ───────────────────────────────────

    enable

        configure terminal

            ! ─── Global Config ───────────────
            ip route 172.31.1.0 255.255.255.128 172.31.1.197
            ip route 172.31.0.0 255.255.255.0 172.31.1.197
            ! ou : ip route 0.0.0.0 0.0.0.0 172.31.1.197

            ipv6 route 2001:DB8:1::/64 2001:DB8:4::197
            ipv6 route 2001:DB8:3::/64 2001:DB8:4::197
            ! ou : ipv6 route ::/0 2001:DB8:4::197

            end


! ─── Vérification finale ──────────────────────
! PC1 > ping 172.31.0.254   → ✅ (PC2)
! PC1 > ping 172.31.1.190   → ✅ (Server)
! PC2 > ping 172.31.1.126   → ✅ (PC1)
! PC2 > ping 172.31.1.190   → ✅ (Server)
```
