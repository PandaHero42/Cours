### Étape 3 – Vérifier la connectivité

```
! Depuis PC3
ping 10.0.5.10
! → ✅ (PC4, IPv4)

ping 2001:db8:acad:5::10
! → ✅ (PC4, IPv6)
```

**Réponse — pings PC3→PC4 réussis ?** Oui — les deux LANs sont directement connectés à R2.

```
! Depuis R2
ping 10.0.3.1
! → ✅ (R1 S0/1/1, IPv4)

ping 2001:db8:acad:3::1
! → ✅ (R1 S0/1/1, IPv6)
```

**Réponse — pings R2→R1 réussis ?** Oui — lien série S0/1/0 configuré des deux côtés.

```
! Depuis PC3
ping 209.165.200.226
! → ✅ (ISP, directement accessible via S0/1/1)

ping 64.100.1.1
! → ✗ (adresse ISP distante — pas de route par défaut configurée sur R2)
```

**Réponse — ping vers 209.165.200.226 ?** Oui — réseau directement connecté à R2.  
**Réponse — ping vers 64.100.1.1 ?** Non — R2 n'a pas de route par défaut vers l'ISP.

```
! Depuis PC3 — session SSH vers R2

! Password : 55Hadm!n  → ✅
```

**Réponse — accès SSH réussi ?** Oui — SSH configuré avec `transport input ssh` et `login local`.

## Partie 2 : Afficher les informations du routeur (via SSH)

Ouvrir une session SSH depuis PC3 :

```
ssh -l SSHadmin 2001:db8:acad:4::1
! Password : 55Hadm!n
```

### Étape 1 – Informations hardware/software

```
R2# show version
```

**Réponses — informations `show version` :**
- **Nom de l'image IOS** : `C1900-UNIVERSALK9-M` (ou similaire selon la version PT)
- **NVRAM** : `255 KB` (typique sur les routeurs 1941 dans PT)
- **Flash** : `255 MB` (typique)

```
R2# show version | include register
```

**Réponse — boot process au prochain reload ?**  
La valeur du registre de configuration (ex: `0x2102`) détermine la source de démarrage. `0x2102` = démarrage normal depuis la flash avec la startup-config.

### Étape 2 – Running configuration

```
R2# show running-config | include password
```

**Réponse — comment les mots de passe apparaissent-ils ?**  
Tous chiffrés — `service password-encryption` a chiffré les mots de passe en type 7, et `enable secret` utilise MD5 (type 5). Aucun mot de passe n'est visible en clair.

```
R2# show running-config | begin vty
```

**Réponse — résultat de cette commande ?**  
Affiche la configuration à partir de la première ligne contenant "vty" — montre la config des lignes VTY (transport input ssh, login local, exec-timeout) et tout ce qui suit dans la running-config.

### Étape 3 – Table de routage

```
R2# show ip route
```

**Réponse — code pour les réseaux directement connectés ?**  
`C` = Connected (directement connecté). `L` = Local (adresse de l'interface elle-même).

**Réponse — combien d'entrées `C` dans la table ?**  
4 entrées `C` — une par interface configurée (G0/0/0, G0/0/1, S0/1/0, S0/1/1).

### Étape 4 – Résumé des interfaces

```
R2# show ip interface brief
```

**Réponse — quelle commande a activé les interfaces GigabitEthernet ?**  
`no shutdown` — les interfaces sont administrativement down par défaut sur un routeur Cisco.

**Réponse — commande pour afficher uniquement les interfaces avec des adresses ?**  
```
R2# show ip interface brief | exclude unassigned
```

```
R2# show ipv6 interface brief
```

**Réponse — signification de `[up/up]` ?**  
Premier `up` = interface physique active (Layer 1). Deuxième `up` = protocole de ligne actif (Layer 2/3). Les deux doivent être `up` pour que l'interface soit opérationnelle.

---

## Résumé des commandes clés

| Commande | Rôle |
|----------|------|
| `show version` | Hardware, IOS, mémoire, registre de config |
| `show version \| include register` | Affiche le registre de configuration (boot) |
| `show running-config \| include password` | Affiche toutes les lignes contenant "password" |
| `show running-config \| begin vty` | Affiche la config depuis les lignes VTY |
| `show ip route` | Table de routage IPv4 |
| `show ip interface brief` | Résumé interfaces IPv4 (état + IP) |
| `show ip interface brief \| exclude unassigned` | Interfaces avec IP uniquement |
| `show ipv6 interface brief` | Résumé interfaces IPv6 |
| `exec-timeout 6 0` | Déconnexion après 6 minutes d'inactivité |
| `logging synchronous` | Évite que les logs interrompent la saisie |
